# 11 · 前端架构

前端的核心思想是：**界面本身也是被注册出来的**。
没有硬编码的页面拼装，一切 UI 都由模块在注册阶段「挂」上去。

---

## 1. 启动链

```
layout.tsx（Server Component）
  └─ NextIntlClientProvider
       └─ Client（'use client'）
            ├─ !initialized → <Loading />
            └─ ThemeProvider → TooltipProvider → {children} + <Toaster />
```

`src/app/client.tsx` 是关键 bootstrap：

```tsx
let bootstrap: Promise<void> | null = null;   // ⭐ 模块级 promise，防重复注册

export function Client({ children }) {
  const [initialized, setInitialized] = useState(false);
  const { handler } = useHandler();
  useEffect(() => {
    handler(async () => {
      await (bootstrap ??= registerClientPlugin());   // 只跑一次
      setInitialized(true);
    })();
  }, []);

  if (!initialized) return <Loading />;
  return (
    <ThemeProvider attribute="class" defaultTheme="system" enableSystem
                   disableTransitionOnChange storageKey="theme">
      <TooltipProvider>{children}<Toaster /></TooltipProvider>
    </ThemeProvider>
  );
}
```

**在注册完成前不渲染子组件** —— 保证所有注册表已填充。
`bootstrap` 用模块级变量避免 React 严格模式下的重复执行。

### 路由

| 路径 | 文件 | 内容 |
| --- | --- | --- |
| `/` | `src/app/page.tsx` | `useIsClient()` 未挂载返回 `null`，挂载后渲染 `<GlobalMenu />` |
| `/{id}` | `src/app/[id]/page.tsx` | 直接把 `params` 透传给 `@/stories/client/realms/page` |
| `/api/**` | 生成 | 无手写文件 |

## 2. 注册驱动的 UI

### 全局菜单

```ts
// src/global/client/menu.tsx
export interface GlobalMenuItem extends Registerable {
  label: () => React.ReactNode;
  content: React.ComponentType;
}
export const menus = getRegistry<GlobalMenuItem>('global-menu');
```

渲染时按拓扑序铺开：

```tsx
{menus.sorted().map((item) => (
  <SidebarMenuItem key={item.id}>{item.label()}</SidebarMenuItem>
))}
...
{element(menus.record(menu)?.content)}
```

`element()` 是注册表驱动的延迟渲染辅助函数：

```ts
element<T>(component?: React.ComponentType<T>, props?: T)
```

### 各模块注册什么

| 模块 | 注册内容 |
| --- | --- |
| `global` | 设置菜单（sequence 99999，排最后） |
| `files` | 文件管理菜单（sequence 999） |
| `presets` | 预设菜单 + 各条目 Tab + renderers + processers + macro feature |
| `stories` | 故事菜单 + tabs + features（image/comfyui/tools/macros/编辑类） |
| `models` | 设置 Tab |
| `comfyui` | 模型管理 + 工作流管理菜单 |
| `memories` | 设置 Tab（rag） |
| `signal` | 客户端 SSE 单例 |
| `@plugins/secyud-tavern-importer` | 导入菜单 |

**要找一个 UI 元素从哪来，就去对应注册表找 `register` 的调用点。**

## 3. Zustand 状态管理

三种持久化策略并存：

| 方式 | 用途 | 例 |
| --- | --- | --- |
| `dbStorage` | 存后端 `setting` 表（跨设备） | 默认模型、RAG 配置、ComfyUI 设置 |
| `localStorage` | 仅本地 UI 偏好 | 全局菜单状态、realm pinned |
| 不持久化 | 会话态 | realm 分页、输入框内容 |

`dbStorage` 的实现（`src/database/client/storage.ts`）把 zustand 的
`StateStorage` 接口重定向到 `settings.proxy`，即后端 setting 表。

### 主要 store

| store | 作用域 |
| --- | --- |
| `useGlobalState` | 当前菜单、侧边栏开合（localStorage，`partialize` 只存 menu/open） |
| `useStoryState` | 故事列表分页 + 当前项 + 当前 tab |
| `useRealmState` | 游玩态：输入、生成中、分页索引、输出索引、信号（只持久化 pinned） |
| `useModelSettingState` / `useModelState` | 模型 |
| `useRagState` | 记忆检索配置 |
| `useComfyUI*State` | ComfyUI 各页 |
| `usePresetState` + 各条目 store | 预设编辑 |

### `useRealmState` 的细节

```ts
setOutput(cur)   // ⭐ 切换输出时会写回历史（history.output = cur）并落库
                 //    所以"输出翻页会改变上下文"是真的
setRealmInfo()   // 有 get().generating && 守卫，避免子 agent 误刷 UI
initPager()      // 初始化 index.{cur,max} 与 output.{cur,max}
```

## 4. 分页骨架：createFetch + PagedItemList

全站列表页复用同一套模式。

### 状态工厂

```ts
// src/database/client/factory.ts
states.createFetch<TEntity, TSearch>(...)   // 返回 { items, length, cur, size, skip, max, loading, ... }
```

它负责 `cur` / `size` / `skip` 的换算与**越界回退**（删到最后一条时自动回退页码）。

### UI 骨架

```tsx
// src/components/pager.tsx
<PagedItemList<TItem> ... />
```

`PagedItemList` 用 `useEffect(..., [id])` 触发 `refresh`，
空态走 `EmptyEntries`。

两者**严格配对**：每个列表页都是「一个 createFetch store + 一个 PagedItemList」。

### 模块级工厂

- 预设：`createPresetEntryState<TData>(name, defaultData)` —— `size: 5`，
  `fetch` 每次从 `usePresetState` 取当前预设 id，并强制注入 `search.entryType = name`。
- 故事：`createStoryEntryState(name, defaultData, size = 5)` —— 同理，
  从 `useStoryState` 取 masterId。

## 5. Proxy 层

每个模块的 `client/proxy.ts` 是对 `src/client.ts` 的薄封装：

```ts
// 形如
export const proxy = {
  get: (id) => get('presets/{id}', { params: { id } }),
  entry: {
    set: (id, entryType, entryId, data) =>
      put('presets/{id}/entries/{entryType}/{entryId}', data, { params: { id, entryType, entryId } }),
    ...
  },
};
```

好处：

- 路径字符串集中在一处，改路由只改 proxy；
- `{key}` 占位符由 `buildUrl` 自动替换（见 [03-接口层与横切](./03-接口层与横切.md)）；
- 路径有编译期类型校验（来自 `src/generated/api-path.ts`）。

> ⚠️ `buildUrl` **会原地修改**传入的 `params` 对象（`delete params[key]`），
> **同一个 params 对象不要在多次调用间复用**。

## 6. 统一异常处理

所有 UI 层的异步副作用都经过 `useHandler().handler` 包裹：

```tsx
const { handler, success } = useHandler();

const submit = handler(async () => {
  await proxy.save(...);
  success(t('message.save.success'));
});

// 或包表单 action
<form action={handler(async (data: FormData) => { ... })} />
```

错误分支策略：

- `BusinessError` / `ApiError` → 按 `code` 翻译后 toast，**不再抛出**；
- 网络 / HTTP 错误 → toast，**不再抛出**；
- 未知错误 → toast 后 **`throw`**（交给错误边界）。

## 7. UI 组件库

### 双层结构

| 层 | 目录 | 说明 |
| --- | --- | --- |
| 原语层 | `src/components/ui/`（35 个文件） | shadcn CLI 管理 |
| 业务封装层 | `src/components/*.tsx`（14 个） | 带业务语义，如 `PagedItemList`、`AutoMedia` |

### ⚠️ 底层不是 Radix

`components.json` 声明 `style: "base-lyra"`、`baseColor: neutral`，
但**实际底层是 `@base-ui/react`**：

```tsx
// ui/button.tsx
import { Button as ButtonPrimitive } from '@base-ui/react/button';
```

这带来一个显著的写法差异 —— 组合用 `render` 插槽而非 `asChild`：

```tsx
<DialogTrigger render={<Button />}>{t('...')}</DialogTrigger>
```

### 常用封装组件

| 组件 | 用途 |
| --- | --- |
| `PagedItemList` | 列表页骨架（配 `createFetch`） |
| `AutoMedia` | 按 mime 前缀渲染图片/视频；UUID 自动探测类型；外部 URL 经 `/api/proxy` 读 content-type |
| `EmptyEntries` / `EmptySelectContent` | 空态 |
| `MonacoEditor` | 脚本、变量 JSON 编辑 |
| `element()` | 注册表驱动的延迟渲染 |
| `useRefresh` / `useTabs` / `useFormRef` / `useIsClient` | 通用 hook |

`useTabs(tabs, item)` 会按 `properties.types` 把 `hidable` 的 tab 拆成
「显示组」与「更多下拉组」。

## 8. 国际化

```ts
// src/localization/config.ts
export const locales = ['zh', 'en'];
export const defaultLocale = 'zh';
```

- **locale 来自 cookie**（不是路由前缀），由 `src/localization/request.ts` 读取；
- `resources[lang]()` 动态 import 各模块的 `localization/<lang>.json`
  （由 `src/generated/resources.ts` 聚合），`jsonUtils.merge` 深度合并；
- 使用约定：
  - 菜单标签用 `t(\`${name}.id\`)`；
  - **错误用 `code` 作 key**：`t(err.code, record)`；
  - 空态用 `t('message.empty.title', { target: t(module) })`。

新增文案时 `zh.json` 与 `en.json` 必须**成对更新**。

- Tailwind CSS 4 + `tw-animate-css` + `shadcn/tailwind.css`；

## 10. `'use client'` 的来源

`src/**/client/**` 下的文件**全部**带 `'use client'`，这不是手工维护的 ——
`scripts/generated/add-use-client.ts` 会递归查找所有名为 `client` 的目录并补上首行指令。

这说明了项目的一条约定：**`client/` 目录 == 客户端边界**。

## 11. 游玩页（realm）UI 结构

```tsx
<iframe key={1} ref={...} />        {/* ⚠️ key 不能删 */}
<RealmTips />                        {/* 生成中指示器 */}
<div className="fixed inset-0 top-auto min-h-20 sc-dc">
  <fieldset disabled={...}>
    <PageControl />                  {/* 历史翻页 + 输出翻页 */}
    {stories.features.registry.sorted().map(u => element(u.component))}
    <IconTooltip onClick={() => route.replace('/')}>回主页</IconTooltip>
    <IconTooltip onClick={() => setPinned(!pinned)}>固定聊天框</IconTooltip>
  </fieldset>
  <fieldset disabled={...}>
    <UserInput />
  </fieldset>
</div>
```

`UserInput` 会把自己的接口挂到 iframe 的 window 上：

```ts
window.userInput = {
  text: { element: () => inputRef.current, get: () => content, set: (v) => setContent(v) },
  summary: { get: () => summary, set: (v) => setSummary(v) },
  inputBuilders: [],
};
```

这是预设脚本能反向控制输入框的接口。

## 12. 已知问题

1. **`realms` 是全局单例**（`realms.realm` / `realms.iframe`）——
   同页面只能有一个活跃 realm，多标签页并存会互相覆盖。
2. **`useSse(type, callback)` 的 `useEffect` 依赖数组为空**，
   回调变化不会重新订阅（已知限制）。
3. **`buildUrl` 原地修改 params**，复用对象会丢字段。
4. **`realms.iframe` 用非空断言**（`null! as HTMLIFrameElement`），
   在 iframe 挂载前访问会出错。
5. **iframe 未设置 `sandbox` 属性**，是同源 iframe
   —— 预设脚本拥有完整同源权限（与项目定位一致，但审计时需知晓）。

## 13. 本章速查

- 界面从哪来？注册表。找 `register` 调用点。
- 新增一个页面？写 `GlobalMenuItem` 并 `globals.menus.register`。
- 新增一个列表页？`createFetch` store + `PagedItemList`。
- 请求怎么写？在模块 proxy 里加方法，用 `{key}` 模板字符串。
- 异步报错怎么办？一律用 `useHandler().handler` 包。
- 想让 UI 持久化？选 `dbStorage`（跨设备）或 localStorage（本地偏好）。
