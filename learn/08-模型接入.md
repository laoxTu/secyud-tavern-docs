# 08 · 模型接入

项目支持三种模型供应商：**OpenAI、DeepSeek、Anthropic**。
接入方式是「双层引擎」抽象，前后端各有一个同名注册表 `model-engine`。

---

## 1. 数据模型

```ts
// src/models/index.ts
export interface Model extends Entity, Properties, DisableDto {
  name: string;
  engine: string;        // 引擎 id：openai / deepseek / anthropic
  builder: string;       // 提示词构造器：default / layered
  stream: boolean;       // 是否流式
  key?: string;          // 加密后的 API Key
  iv?: Buffer;           // AES 初始向量
  iterations?: number;   // 单轮最大工具循环次数
}

export interface ModelProperty {
  retry: { interval: number; max: number };
}
export interface ModelSetting { model: NameValue | null; }
```

数据库表 `model`（`src/models/server/schema.ts`）：

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | text PK | UUID |
| `name` | text | 有 `model_name_idx` 索引 |
| `engine` | text | 引擎 id |
| `builder` | text NOT NULL default `'default'` | `default` / `layered` |
| `stream` | boolean default `true` | |
| `key` | text | 加密的 API Key |
| `iterations` | integer default `20` | 工具循环上限 |
| `iv` | blob | AES 向量 |
| `properties` | json default `{}` | 动态属性容器 |

供应商专属配置全部塞进 `properties` 的两个键：

```ts
models.names.config  = 'config';   // 连接配置（url、format 等）
models.names.options = 'option';   // 采样参数（temperature 等）
```

## 2. 双层引擎抽象

这是理解模型接入的关键：**同名注册表，前后端各一个，职责不同**。

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 前端引擎 | `src/models/client/engine.ts` | **格式**：把回调组装成供应商格式；解析流式事件 |
| 后端引擎 | `src/models/server/engine.ts` | **传输**：调用 SDK，返回流或完整响应 |

### 前端引擎

```ts
// src/models/client/engine.ts
export interface ModelEngine extends Registerable {
  configComponent: React.ComponentType;                                  // 配置 UI
  configureObject: (data: FormData, model: Partial<Model>) => Partial<Model>; // 表单 → 配置
  result: (ctx: ModelResultContext) => Promise<void>;                     // 解析输出
  prompt: (ctx: ModelPromptContext) => Promise<ModelInput>;               // 组装输入
}
```

`prompt` 收到的是「回调集合」（`ModelInjectContext`），
它负责把这些回调翻译成具体供应商的消息数组：

```ts
prompt: (content: string) => void;                              // user 消息
assist: (content, output) => void;                              // assistant 消息
system: (content) => void;                                      // system 消息
caller: (content, output, callings) => void;                    // 工具调用
```

`result` 把流式 delta 写进 `RealmOutput`（`content` / `thought` / `callings`），
并在结束时置 `ctx.stopped`。

### 后端引擎

```ts
// src/models/server/engine.ts
export interface ModelEngine extends Registerable {
  generate(context: ModelGenerateContext): Promise<AsyncIterable<any> | Record<string, any>>;
}

async function generate(model: Model, input: any, signal: AbortSignal) {
  const name = checker.notNullOrWhitespace('engine', model.engine, 'model');
  const engine = registry.records[name];
  checker.notNullEntity(name, engine, 'model.engine');

  const apiKey = model.key && model.iv ? hasher.decrypt(model.key, model.iv) : '';
  return await engine.generate({ model, apiKey, signal, input });
}
```

注意 **API Key 在此处解密**，仅在内存中明文存在。

## 3. 三个供应商实现

### OpenAI

```ts
// src/models/openai/server/engine.ts
const client = new OpenAI({ baseURL: config.url, apiKey });

if (config.format === 'responses') {
  return await client.responses.create({
    ...options, ...input, stream: model.stream,
    ...jsonUtils.parse(config.extras, {}),
  }, { signal });
} else {
  return await client.chat.completions.create({
    ...options, ...input, stream: model.stream,
  }, { signal });
}
```

**支持两种 API 格式**：

- `chat` —— 传统 `chat.completions`，消息数组 + `tools` / `tool_calls`。
- `responses` —— 新版 `responses` API，`instructions` + `function_call` / `function_call_output`。

前端引擎相应地有两套组装逻辑（`promptChatCompletion` / `promptResponses`）。

**流式事件解析**（前端 `result`）识别：

- `response.output_text.delta` → 正文
- `response.reasoning_summary_text.delta` → 思考内容
- `delta.tool_calls` → 按 `index` 归并并拼接 `arguments`
- `finish_reason === 'stop'` 或 `response.completed` → `ctx.stopped = true`

### DeepSeek

复用 `openai` 包，只换 `baseURL: 'https://api.deepseek.com'`。
前端引擎**直接复用** `openais.engine.prompt` / `result`。

后端做了一些字段清理（`src/models/deepseek/server/engine.ts`）：

```ts
// 未开 logprobs 则置 top_logprobs = undefined
// max_tokens 为假值则置 undefined
// thinking.type === 'disabled' 时置 reasoning_effort = undefined
```

DeepSeek 的 `reasoning_content` 被当作 `output.thought` 处理
（代码注释自称「偷懒」）。

### Anthropic

用 `@anthropic-ai/sdk` 的 `anthropic.messages.create`，
同样支持 `config.extras` 合并。

## 4. 密钥加密

```ts
// src/utils/server/hasher.ts（概要）
hasher.create(key)      // AES-128-CBC 加解密
hasher.generateKey(text, salt)  // pbkdf2Sync(text, salt, 100000, 16, 'sha256')
hasher.encrypt / decrypt        // 模块级单例，读 process.env.SECRET_KEYS / SECRET_SALT
```

Repository 中的处理（`src/models/server/repository.ts`）：

- `create()` **强制清空 `key` / `iv`** —— 创建时不能带 Key。
- `update()` 若存在 `model.key`，生成 **16 字节随机 iv** 并加密，同时**删除缓存**。
- `get()` 走进程内缓存 `model_{id}`，**TTL 5 分钟**。
- `list()` 只投影 `{ id, name }`，支持 `fuzzy` 的 `LIKE`。

> ⚠️ `.env` 里的 `SECRET_SALT` / `SECRET_KEYS` 由 `pnpm prepare` 生成，
> **一旦丢失就无法解密已存的 API Key**。
> 另外它们由 `strUtils.random`（基于 `Math.random()`）生成，非密码学安全随机源。

## 5. API 端点

| 方法 | 路径 |
| --- | --- |
| GET / POST | `/api/models` |
| GET / PUT / DELETE | `/api/models/{id}` |
| POST | `/api/models/{id}/clone` |
| POST | `/api/models/{id}/engine/generate` |

`generate` 是核心端点：`model.stream` 为真时用 `sseUtils.pack(result)`
包装成 `ReadableStream` 并以 `text/event-stream` 返回，否则返回 JSON。

前端 `handleResponse` 因 `Content-Type` 非 JSON 而原样放行 `Response`，
供 `sseUtils.read` 消费 —— 这是流式链路能成立的前提。

## 6. 客户端

### proxy

```ts
// src/models/client/proxy.ts
get / list / create / clone / update / delete
engine.generate(id, input, signal)   // 返回原始 Response，供上层读流
```

### state

- `useModelSettingState` —— zustand + persist 到 `dbStorage`，key `'model_setting'`，
  只持久化 `model`（默认模型选择）。
- `useModelState` —— 当前编辑项。

### 选择默认模型

用户可在设置页把某个模型设为默认（星标）。
故事上存 `NameValue`（`story.model` 的 json 列）。

解析顺序（`getRealm`）：

```ts
// story.model 为空 → 取全局设置里的默认模型
// 仍为空 → 抛 BusinessError('no model or default configured', 'error.story.model_not_configured')
```

运行时覆盖（`realms.model()`）：

```ts
async function model(realm: Realm, model?: NameValue | null) {
  return model ? await models.proxy.get(model.value) : realm.model;   // 工具可指定自己的模型
}
```

## 7. builder 的两种构造器

`model.builder` 有 `default` 与 `layered` 两个选项（UI 在
`src/models/client/setting.tsx` 的 `['default','layered']`）。

- **default**：世界书按 layer 阈值 100 简单划分注入位置。
- **layered**：世界书按「滑窗」分配层级，越靠后的历史承载 layer 越高的条目。

> 注意：`builder` 字段本身在 `src/models/**` 内**只是下发**，
> 真正的消费点在世界书注入器（`src/lorebooks/client/realm.ts` 的
> `create()` 里 `switch (builder)`）。这是模块间通过通用字段解耦的一个例子。

## 8. 某个模型的完整调用链

```
用户输入
  └─ models.processers.generate()
       ├─ prompt() → 各 Processer 填 converts/injects
       │    └─ engine.prompt(context)          ← 前端引擎，组装成 messages
       │         └─ 返回 { input, summaries }
       │
       ├─ models.proxy.engine.generate(model.id, input, signal)
       │    └─ POST /api/models/{id}/engine/generate   （SSE 或 JSON）
       │         └─ 服务端 engines.generate()
       │              ├─ 校验 engine 存在
       │              ├─ hasher.decrypt(key, iv)       ← 解密 API Key
       │              └─ engine.generate({ model, apiKey, signal, input })
       │                   └─ OpenAI / DeepSeek / Anthropic SDK
       │
       └─ for await chunk of sseUtils.read(response.body)
            └─ engine.result(context)         ← 前端引擎，解析 delta
                 └─ 写入 output.{content, thought, callings}
                      └─ ctx.stopped? → 终止工具循环
```

## 9. 已知问题

1. **非流式分支的 `stream` 实参**：`processer.ts` 里非流式路径调用
   `generate(true, response)`，传了 `true` 但实际是 `model.stream === false`，**疑似 bug**。
2. **重试语义混淆**：`retry` 同时用于「网络错误重试」与「流式卡死重试」。
3. **`ModelInput.summaries` 的消费者**在本模块内未找到，
   实际用于 UI 的上下文预览（`Viewer` 组件）。
4. **DeepSeek 复用 OpenAI 前端引擎**：若 DeepSeek 的 reasoning 字段语义变化，
   需要改 `deepseek/client/engine.tsx` 中的单独处理。

## 10. 本章速查

- 想加一个新供应商？写 `server/engine.ts`（传输）+ `client/engine.tsx`（格式），
  在两侧的 `index.ts` 里 `register`。
- API Key 存哪里？`model.key`（AES 加密）+ `model.iv`，`.env` 提供主密钥。
- 为什么生成会走到 `/api/models/{id}/engine/generate`？因为密钥只在服务端解密。
- 想换默认模型？设置页星标，或直接在故事上指定。
