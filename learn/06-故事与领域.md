# 06 · 故事与领域（Story / Realm）

**Story 是持久化的配置，Realm 是运行时的游玩视图。**
理解这一区分是读懂整个叙事系统的前提。

---

## 1. Story（故事）

```ts
// src/stories/index.ts
export interface Story extends Entity, Properties, Entries {
  name: string;                    // 显示名
  model?: NameValue | null;        // 使用的模型，为空则用全局默认
  presets: NameValue[];            // 预设组合，一般一项，可多项
}
```

数据库表 `story`：

```ts
export const storySchema = sqliteTable('story', {
  id: text('id').primaryKey(),
  name: text('name').notNull(),
  model: json<NameValue | null>('model').default(null),
  presets: json<NameValue[]>('presets').default([]),
  properties: json('properties').default({}),
}, (t) => [index(`story_name_idx`).on(t.name)]);
```

要点：

- `presets` 是**数组** —— 一个故事可叠加多个预设，条目跨预设合并处理。
- Story 自身**没有条目字段**，条目通过独立的 `story_entry` 表按 `entryType` 分组加载。

### 故事条目

```ts
export interface StoryEntry<T = any> extends Entry { data: T; }
export type StoryItem<T = any> = T & EntryItem & { entryId: number };
```

`story_entry` 表由 `schemas.entry()` 生成，带额外列 `data: json('data').notNull()`。
`src/stories/server/index.ts` 里只注册了 `images.storage`（`entryType = 'image'`），
其他条目类型通过各自模块注册。

## 2. Realm（领域）

源码注释：「realm 领域，王国，描述进入游玩的界限，由故事映射而来」。

```ts
// src/stories/realms.ts
export interface Realm extends Entity, Properties, Entries {
  name: string;
  histories: (RealmHistory | null)[];   // ⭐ 稀疏数组，null = 未加载
  model: Model;                          // 已解析的完整模型对象
  presets: Preset[];                     // 已解析的完整预设对象（含条目）
  context?: Record<string, any>;         // 运行期缓存（不持久化）
}
```

### ⚠️ Realm 不是数据库表

它由 `getRealm(story)`（`src/stories/server/repository.ts`）投影出来，做四件事：

1. `story.model` 为空时，从全局设置取默认模型；仍为空则抛
   `BusinessError('no model or default configured', 'error.story.model_not_configured')`。
2. 取完整 Model 对象。
3. `count()` 出 `realm_history` 行数，创建**长度为 count 的全 null 数组**作为 `histories`
   —— 这是**懒加载占位**，避免进入故事就拉全量历史。
4. `presets.repository.listWithRequires(...)` 解析预设依赖闭包。

注意 `getRealm` **不加载 story 条目**，所以 Realm 上不会有 image 等条目数据。

### 运行期缓存 `realm.context`

各 Processer / Renderer 的 `init` 结果都缓存在这里，通过一对函数管理：

```ts
// src/stories/client/realms/index.ts
function context<T>(realm: Realm, key: string): T {
  const value = realm.context?.[key];
  if (value === undefined) {
    throw new BusinessError(
      `realm context "${key}" is not initialized. (...)`,
      'error.story.realm_not_initialized',
    ).withValue('key', key);
  }
  return value as T;
}

function initContext(realm: Realm, key: string, value: any) {
  if (realm.context[key] !== undefined || value === undefined) {
    throw new BusinessError(
      `realm content "${key}" already initialized`,
      'realm.content_already_initialized',
    ).withValue('key', key);
  }
  realm.context[key] = value;
}
```

**同键重复初始化会抛错** —— 源码注释说明这是「防止两个引擎/插件意外共用同一 key 互相覆盖」。
键名由 `realms.key(id)` 生成，即 `realm.<processorId>`。

### 三条历史相关的接口

```ts
export interface RealmMessage extends Properties {
  content: string;
  variables: Operation[];        // ⭐ JSON Patch 操作数组
}
export interface RealmPrompt extends RealmMessage {}

export interface RealmOutput extends RealmMessage {
  thought: string;               // 思考内容（reasoning）
  callings?: ToolCall[];         // 工具调用
}

export interface RealmHistory {
  masterId: string;
  sequence: number;
  summary: boolean;              // ⭐ 上下文截断标记
  variables: Record<string, any>;
  prompts: RealmPrompt[];
  output: number;                // 当前选中的输出下标
  outputs: RealmOutput[][];      // ⭐ 二维：外层是"第几次尝试"，内层是"一轮的多段"
}
```

`outputs` 的二维结构是理解「输出翻页」的关键：

- 外层数组：重新生成会**追加**一组，所以可以来回翻看历史版本。
- 内层数组：一轮对话可能因为工具调用被拆成多次请求，每次一段。

## 3. 历史表

```ts
export const realmHistorySchema = sqliteTable('realm_history', {
  masterId: foreignKey('master_id', () => storySchema.id).notNull(),
  sequence: integer('sequence').notNull(),
  summary: boolean('summary').default(false).notNull(),
  variables: json<Record<string, any>>('variables').default({}).notNull(),
  prompts: json<RealmPrompt[]>('inputs').default([]).notNull(),   // ⚠️ 列名是 inputs
  output: integer('output').default(-1).notNull(),
  outputs: json<RealmOutput[][]>('outputs').default([]).notNull(),
}, (table) => [primaryKey({ columns: [table.masterId, table.sequence] })]);
```

> ⚠️ 两个陷阱：
> 1. 数据库列名是 `inputs`，但 TS 属性名是 `prompts`。
> 2. `history.get` 按 **offset 索引**取，不是按 sequence
>    （源码注释：「注意! 历史获取不用sequence，用索引」），
>    但 HTTP 路径参数名叫 `sequence` —— 两者语义不一致，读代码时务必留意。

## 4. 开场白（opening）

开场白被建模为一条**伪历史**，是整个变量系统的起点：

```ts
function opening(realm: Realm) {
  const key = 'opening';
  let opening = realm.context?.[key] as RealmHistory;
  if (!opening) {
    const variables = {};
    for (const preset of realm.presets) {
      jsonUtils.merge(variables, jsonUtils.parse(preset.variables));   // 多预设变量深度合并
    }
    opening = {
      masterId: realm.id,
      sequence: -1,
      prompts: [{ content: '', variables: [], properties: {} }],
      summary: true,          // ⭐ 被视为一个总结段落
      output: 0,
      outputs: [],
      variables,
    };
    opening.outputs.push(
      realm.presets.map(u => u.opening?.trim()).filter(u => u)
        .map(v => ({ content: v!, variables: [], properties: {}, thought: '' })),
    );
    initContext(realm, key, opening);   // 懒生成并缓存
  }
  return opening;
}
```

关键点：

- **所有预设的 `variables` 深度合并**，作为故事的初始变量。
- `sequence: -1`、`summary: true` —— 它被当作「第一个总结段落」，
  这正好配合下面 prompt 的倒序回溯逻辑。
- 多个预设的 `opening` 会各自成为一段输出。

## 5. 上下文（context）如何截断

这是叙事系统的核心机制之一 —— **不按 token 计数，按 `summary` 标记**：

```ts
// src/models/client/processer.ts（prompt 函数）
const histories: RealmHistory[] = [];
for (let i = realm.histories.length; i > 0; i--) {
  const history = await realms.history.get(i, realm);
  histories.push(history);
  if (history.summary) break;          // ⭐ 遇到总结段就停止回溯
  if (i === 1) {
    histories.push(realms.opening(realm));   // 走到头也没遇到，补开场白
  }
}
histories.reverse();                   // 恢复正序
```

即上下文永远是「**最后一个总结段 → 现在**」。
用户界面上那个「总结」复选框，写的就是 `history.summary`。

## 6. 变量系统：JSON Patch 回放

每条消息（prompt / output）都带一个 `variables: Operation[]`，
它是一个**补丁序列**，而不是完整快照：

```ts
function variables(history: RealmHistory, output: boolean = true) {
  const variables = structuredClone(history.variables);   // 从该回合的基线快照开始
  for (const input of history.prompts) {
    patch(variables, input.variables);                    // 依次回放
  }
  if (output && history.outputs.length > 0) {
    const list = outputs(history);
    if (list) for (const output of list) patch(variables, output.variables);
  }
  return variables;
}
```

好处：

- **节省存储**：只需存增量。
- **可回溯**：切换到任意输出（`output` 参数控制是否应用输出补丁）
  就能得到那一刻的变量状态 —— 这正是「输出翻页会改变上下文」的实现。

`@/utils/json-patch` 的 `patch()` 特意标注：

> 针对 AI 的 JSON patch，和一般 JSON Patch 理解不同

差异点：`add` 到数组是 push、到对象是展开合并；`replace` 目标不存在也赋值，
数组按数字下标 replace/append/unshift。

## 7. 一次对话的完整流程

### 进入页面

`/[id]` → `src/app/[id]/page.tsx` → `RealmPage`（`src/stories/client/realms/page.tsx`）：

```ts
const realm = await stories.proxy.realm.id(id);
await models.processers.initialize({ realm });   // 各模块 init，构建缓存
await stories.renderers.initialize({ realm });
realms.realm = realm;                            // ⭐ 存入全局单例
await initPager();
```

### 用户提交

`UserInput` 组件 → `realms.generate(true)`：

1. 设定 `generating = true`。
2. 读 iframe 内 `window.userInput.inputBuilders`，按 `sequence` 排序后依次改写输入。
3. **历史合并规则**（很关键）：
   - 上一条历史**已有输出** → 取它的变量作为新历史的初始变量 → **创建新历史**。
   - 上一条历史**还没有输出** → 直接追加 prompt 到该历史（合并）。
   - 还没有任何历史 → 用 `opening(realm)` 的变量。
4. push prompt 到 `history.prompts`，先 `setIndex()` 把用户输入渲染出来。
5. 新历史通过 `stories.proxy.history.add()` 落库。

### 生成循环

进入 `models.processers.generate({ realm, signal })`（详见 [07-生成管线](./07-生成管线.md)）：

- 工具循环最多 `iterations` 轮；
- 每轮重建 prompt 上下文 → 请求模型 → 逐块解析进 `RealmOutput`；
- 满足条件时调用 `stories.renderers.stream()` 流式渲染。

### 收尾

```ts
await setIndexCur();
await models.processers.output({ realm });   // 缓存世界书匹配结果等
// finally 中：
set({ generating: false });
await setIndex(histories.length);
await setHistory(histories.length, realm);   // 落库
```

## 8. 渲染管线

`src/stories/client/renderer.ts`：

```ts
export interface Renderer<T = any> extends Registerable {
  init: (ctx: RealmInitContext) => Promise<T>;
  stream?: (ctx: RealmRenderContext, cache: T) => Promise<void>;   // 流式渲染
  output?: (ctx: RealmRenderContext, cache: T) => Promise<void>;   // 总渲染
}
```

注册表名 `realm-processer`。已注册的 renderer：
`styles`、`scripts`、`regexes`、`macros`。

```ts
async content({ history, realm }) {
  const context: RealmRenderContext = { properties: {}, history, realm, converts: [] };
  await registry.use(async (p) => { await p.output?.(context, realms.cache(realm, p.id)); });
  await realms.message.content(history, async (text, ctx) =>
    models.convert(context.converts, text, ctx));     // 用收集到的 converts 链转换
  realms.message.variables(history);
}
```

流程：各 renderer 往 `context.converts` 里 push 转换器 →
最后统一用这条链把文本转换后 `postMessage` 进 iframe。

每个 renderer 的 `init` 结果缓存在 `realm.context['realm-processer.<id>']`。

## 9. iframe 渲染沙箱

游玩页渲染一个 iframe，**界面完全由预设脚本绘制**：

```tsx
{/* key不要删除。发布后，如果没有这个key，会导致引用有问题，原因不明，开发环境无此问题。 */}
<iframe key={1} ref={(iframe) => { realms.iframe = iframe!; }} width={'100%'} height={'100%'} />
```

数据通过 `postMessage` 单向推入：

```ts
function postMessage(type: string, data: any) {
  const window = realms.iframe?.contentWindow;
  const g = window as { __messageData?: Record<string, any> };
  g.__messageData ??= new Map<string, any>();
  g.__messageData[type] = data;        // 同时挂到 window 上供同步读取
  window.postMessage({ type }, '*');
}
```

推送三类数据：`variables`（变量快照）、`content`（`{inputs, output, thought}`）、
以及脚本自行监听的任意消息。

反向通道：主应用在 iframe window 上挂 `userInput`，
脚本可注册 `inputBuilders` 改写玩家输入（详见 [04-预设系统](./04-预设系统.md)）。

## 10. 游玩界面（slot）的功能清单

`docs/zh/guide/story/slot.md` 描述的就是这个界面。**"slot" 是命名约定而非独立抽象**
（输入框 DOM id 为 `slot-user-input`，报错文案里称 `context` 为「插槽缓存」）。

| 功能 | 实现 |
| --- | --- |
| 历史翻页 | `PageControl` → `setIndex` |
| 输出翻页（切换会改变上下文） | `setOutput` → 写回 `history.output` 并落库 |
| 生成图片 | `src/comfyui/client/feature.tsx` |
| 图片（故事图集弹窗） | `src/stories/images/client/index.tsx` |
| 宏选择器 / 工具选择器 | `src/presets/macros/client/feature.tsx`、`src/tools/client/feature.tsx`（sequence 100） |
| 删除回复 / 删除历史 / 重新生成 / 查看上下文 / 编辑当前历史 / 回到主页 | `src/stories/client/realms/feature.tsx`（sequence 1000） |
| 输入框 / 总结 | `UserInput` |

底部的功能按钮由 feature 注册表驱动：

```tsx
{stories.features.registry.sorted().map((u, i) => (
  <div key={u.id} className="bg-background">{element(u.component)}</div>
))}
```

### 功能实现细节

- **Viewer（查看上下文）**：构造一条**虚拟待发历史**（prompt 用输入框当前内容），
  clone 整个 histories 并把所有 `callings.result ??= ''`（防止虚拟预览真的调工具），
  然后跑一遍真实的 `models.processers.prompt()`，只为拿 `summaries` 做预览与字数统计。
- **Editor（编辑历史）**：Monaco 编辑 `history.variables` JSON，
  并允许改写每条 prompt / output 的 content。
- **Deleter（删除）**：删除当前输出时 `outputs.splice(history.output, 1)` 并修正下标；
  若删空且存在下一条历史，则把 `summary` 与 `prompts` **前移合并**到下一条再删本条。
- **clone / reopen**：`stories.proxy.clone(realm.id)` 复制整个 Story 为新 uuid。

## 11. 图片

`StoryImage` 是普通 story 条目（`entryType = 'image'`），不是独立表：

```ts
export interface StoryImage { image?: string | null; updateAt: string; }
```

上传流程（`POST /api/stories/{id}/image`）：
取 FormData 的 `image` File → `files.repository.create()` 得到 fileId →
以 `{ image: fileId, updateAt: Date() }` 新增条目。

与 ComfyUI 的关系是**生产者/消费者**：

- ComfyUI 工作流里注入 `target_url = ${baseUrl}/api/stories/${realm.id}/image`，
  生成完成后由 ComfyUI 的 `Form Post Request Node` 回传，自动落库为故事图片。
- 所以「故事图片」包含 ComfyUI 产物，但也可以是手工上传的图。

## 13. 已知陷阱

1. **全局单例 `realms`**：`realms.realm`、`realms.iframe` 是模块级单例，
   **同一页面只能有一个活跃 realm**，多标签页并存会互相覆盖。
2. **`history.get` 按 offset 而非 sequence**，但路径参数叫 `sequence`。
3. **`realm_history.inputs` 列名与 `prompts` 属性名不一致**。
4. **iframe 的 `key={1}` 不能删**（生产环境会出引用问题，开发环境复现不了）。
5. **切换 realm 若不刷新 iframe 会沿用旧脚本** —— renderer 用
   `window.__injectedScriptInitialized` 之类的全局标志保证只注入一次。
6. **`getRealm` 不加载 story 条目**，需要条目数据时要另行请求。
7. **无 schema 版本化机制**：`realm_history` 没有版本列，格式变更需自行兼容。

## 14. 本章速查

- 想理解「故事」和「游玩」的区别？Story 是配置表，Realm 是运行时投影。
- 上下文为什么截断在某处？找 `history.summary === true`。
- 变量为什么是这个值？从该回合 `variables` 基线开始回放所有 `Operation`。
- 界面为什么是空白的？因为预设里没有脚本 —— 这是设计而非 bug。
