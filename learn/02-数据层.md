# 02 · 数据层

所有持久化都落在**一个 SQLite 文件**上，通过 Drizzle ORM 访问。

---

## 1. 引擎与连接

```ts
// src/database/server/provider.ts
const url = `file:${config.dataDir}/secyud-tavern.db`;  // 默认 data/secyud-tavern.db
const migrationsFolder = 'scripts/migrations';

const client = createClient({ url });       // @libsql/client
const db = drizzle(client);

async function migrate() {
  await drizzleMigrate(db, { migrationsFolder });
}
```

- 驱动是 `@libsql/client`（SQLite 兼容），**不是** better-sqlite3。
- 迁移目录是 `scripts/migrations`（不是默认的 `drizzle/`）。
- `drizzle.config.ts`：`dialect: 'sqlite'`，`schema: 'src/**/schema.ts'`
  —— 这个 glob 正是「schema 分散在各模块」的体现。

**迁移执行时机有两处**：

1. `pnpm prepare` → `scripts/operations/migrate.ts`
2. `instrumentation.ts` → Next 启动时 `dbProvider.migrate()`

也就是说实际会跑两次（幂等，但值得知道）。

数据库文件位于 `data/`，已被 `.gitignore` 忽略。

## 2. 通用类型（`src/database/index.ts`）

这些是所有模块共享的 DTO 基础：

```ts
export interface Entity { id: string; }

export interface Properties { properties?: Record<string, any>; }

// 分页请求 / 响应
export interface DataRequest<TSearch = never> {
  skip?: number;   // 默认 0
  size?: number;   // 默认 20
  search?: TSearch;
}
export interface DataResponse<T> { items: T[]; length: number; }

export interface DisableDto { disabled: boolean; }
export interface VersionDto { version: string; }

// 主子结构的核心：一个实体挂多组条目
export interface Entries extends Entity {
  entries?: Record<string, any[]>;   // key 是 plural，如 'lorebooks'
}

// 条目（数据库行）
export interface Entry {
  masterId: string;
  entryType: string;
  entryId: number;
  name: string;
}

// 导入导出用（id 可选：导出不需要，内部唯一键需要）
export interface EntryItem { id?: string; name: string; }

export interface EntryRequestParam { filter?: string; entryType?: string; }
export interface NameValue { name: string; value: string; }
```

> `Entries.entries` 的键是**复数形式**（`plural`），
> 这解释了为什么每个模块的 `index.ts` 都要导出一对 `name` / `plural`。

### 工具函数

`src/database/index.ts` 还导出一个 `utils` 对象，全项目高频使用：

| 函数 | 作用 |
| --- | --- |
| `getProperty(item, key, init?)` / `setProperty` | 读写 `item.properties[key]`，`init` 懒初始化 |
| `getItems(model, plural)` | 取出 `model.entries[plural]` |
| `forEachItems(model, plural, action)` | 遍历单个实体的某一类条目 |
| `forEachItemsList(models, plural, action)` | 遍历多个实体（多预设合并场景常用） |
| `mapData(data, convert)` | 分页结果映射 |
| `get` / `set` | 更底层的懒初始化读写 |

`forEachItemsList` 是「预设可组合」这一设计的支撑点：
一个 Realm 可能挂多个 Preset，所有条目处理都是跨预设扁平遍历的。

## 3. entry 表模式：一套表结构支撑所有「条目」

这是数据层最巧妙的设计。所有子条目（宏、正则、脚本、世界书、工具、记忆……）
**共用同一种表结构**，由 `schemas.entry()` 生成：

```ts
// src/database/server/factory.ts
export const schemas = {
  entry(name: string, ref: () => SQLiteColumn, extraColumns: any = {}) {
    return sqliteTable(name, {
      masterId: foreignKey('master_id', ref).notNull(),
      entryType: text('entry_type').notNull(),
      entryId:   integer('entry_id').notNull(),
      name:      text('name').notNull().default(''),
      filter:    text('filter').notNull().default(''),   // 模糊搜索用
      sorter:    text('sorter').notNull().default(''),   // 排序用
      ...extraColumns,
    }, (table) => [
      primaryKey({ columns: [table.masterId, table.entryType, table.entryId] }),
      index(`${name}_filter_idx`).on(table.filter),
      index(`${name}_sorter_idx`).on(table.sorter),
    ]);
  },
};
```

关键点：

- **复合主键** `(masterId, entryType, entryId)`，天然支持「一个预设下多种条目」。
- `filter` / `sorter` 是**冗余的字符串列**，由各模块的 `criteria()` 回调计算出来，
  用于 SQL 层的 `LIKE` 搜索与 `ORDER BY`，避免把 JSON 里的字段提出来建索引。
- `extraColumns` 用于追加业务列，最典型的是 `data: json('data').notNull()`
  —— 条目的真实内容以 JSON 存在 `data` 列里。

### 三个列辅助函数

```ts
export const json      = <T>(name) => text(name, { mode: 'json' }).$type<T>();
export const boolean   = (name) => integer(name, { mode: 'boolean' }).$type<boolean>();
export const foreignKey = (name, ref) =>
  text(name).references(ref, { onDelete: 'cascade', onUpdate: 'cascade' });
```

注意 `boolean` 用 `integer(mode:'boolean')`，`json` 用 `text(mode:'json')`，
外键统一 `cascade`（删主记录自动清理条目）。

## 4. repository.entry：通用条目仓储

`repositories.entry(table, manager, map)` 返回一套完整的 CRUD，被所有条目表复用。

```ts
const repo = repositories.entry(storyEntrySchema, manager, (table) => ({
  data: table.data, ...
}));
// → { list, make, types, get, add, set, del }
```

| 方法 | 签名 | 说明 |
| --- | --- | --- |
| `list` | `(id, request?)` | 按 `masterId` 过滤，支持 `entryType` 精确与 `filter` 模糊，按 `sorter` 排序，支持分页 |
| `make` | `(masterId, entryType, entries[])` | **批量插入**，`entryId` 从当前最大值 +1 连续分配 |
| `types` | `(masterId)` | `SELECT DISTINCT entry_type` |
| `get` | `(masterId, entryType, entryId)` | 单条 |
| `add` | `(masterId, entryType, entry)` | 单条插入，返回新 `entryId` |
| `set` | `(masterId, entryType, entryId, entry)` | 更新（显式把主键三列置 `undefined`，防误改） |
| `del` | `(masterId, entryType, entryId)` | 删除 |

所有写操作都会调用 `manager.criteria(entryType, entry)` 计算 `filter` / `sorter`：

```ts
await db.insert(table).values({
  ...entry,
  ...manager.criteria(entryType, entry),   // ← 注入冗余检索列
  masterId, entryType, entryId,
});
```

## 5. storage / factory / provider 三层抽象

这是每个模块 `server/` 目录下那组文件的职责划分：

```
storage.ts   声明「怎么把条目序列化进出实体」——实现 Storage<T>
factory.ts   提供创建 Storage 的工厂（通用逻辑在这里）
repository.ts 具体表的 CRUD 与查询
provider.ts  外部资源连接（数据库、模型、HTTP）
schema.ts    Drizzle 表定义
```

### Storage 接口

```ts
// src/database/server/storage.ts
export interface Storage<TEntity extends Entries> extends Registerable {
  load: (model: TEntity) => Promise<void>;
  save: (model: TEntity) => Promise<void>;
  criteria: (entry: any) => Criteria;   // → { filter?, sorter? }
}

export interface StorageManager<TEntity extends Entries = any> {
  load: (model: TEntity) => Promise<void>;
  save: (model: TEntity) => Promise<void>;
  criteria: (type: string, entry: any) => Criteria;
}
```

`StorageManager` 由 `storages.createManager(registry)` 创建，
它把操作**扇出到该实体所有已注册的 Storage** 上：

```ts
// src/database/server/factory.ts
export const storages = {
  createManager<TEntity extends Entries>(registry: Registry<Storage<TEntity>>) {
    return {
      load: async (entity) => { await registry.use(p => p.load(entity)); },
      save: async (entity) => { await registry.use(p => p.save(entity)); },
      criteria: (type, entry) => registry.record(type)!.criteria(entry),
    };
  },
};
```

> 语义：`load(entity)` 会把该实体**所有类型**的条目一次性装配进 `entity.entries[plural]`。
> 这就是为什么 API 能返回一个「完整的」Preset 对象。

### 预设侧的专用工厂

`src/presets/server/factory.ts` 的 `storages.create(...)` 更具体，它额外处理归档：

```ts
storages.create<TData>(
  { name: type, plural },
  criteria,        // (entry) => Criteria
  loadArchive,     // 把条目写进 zip 节点
  saveArchive,     // 从 zip 节点读回条目
): PresetStorage
```

- `load(model)`：`repository.entry.list(model.id, { search: { entryType: type } })`
  → 映射进 `model.entries[plural]`，并回填 `disabled` 与 `name`。
- `save(model)`：把 `model.entries[plural]` 批量写库，把 `disabled` / `name`
  从 `data` 里剥离出去（它们是一等列，不重复存 JSON）。
- `loadArchive` / `saveArchive`：文件式导入导出的钩子。

## 6. 具体表清单

| 表 | 定义位置 | 说明 |
| --- | --- | --- |
| `preset` | `src/presets/server/schema.ts` | 预设主表 |
| `preset_entry` | 同上（`schemas.entry`） | 宏/正则/脚本/样式/工具/世界书条目 |
| `story` | `src/stories/server/schema.ts` | 故事主表 |
| `story_entry` | 同上（`schemas.entry`） | 故事条目（含 memories） |
| `realm_history` | 同上 | 游玩历史 |
| `model` | `src/models/server/schema.ts` | 模型配置 |
| `comfyui_model` | `src/comfyui/server/schema.ts` | ComfyUI 模型 |
| `comfyui_workflow` | 同上 | 工作流 |
| `comfyui_param` | 同上（复合主键 `masterId + sequence`） | 工作流参数 |
| `file` | `src/files/server/schema.ts` | 文件/附件 |
| `setting` | `src/global/server/schema.ts` | 全局设置（key-value） |

### story 的 schema（示例）

```ts
export const storySchema = sqliteTable('story', {
  id: text('id').primaryKey(),
  name: text('name').notNull(),
  model: json<NameValue | null>('model').default(null),
  presets: json<NameValue[]>('presets').default([]),   // 可挂多个预设
  properties: json('properties').default({}),
}, (t) => [index(`story_name_idx`).on(t.name)]);

export const realmHistorySchema = sqliteTable('realm_history', {
  masterId: foreignKey('master_id', () => storySchema.id).notNull(),
  sequence: integer('sequence').notNull(),
  summary: boolean('summary').default(false).notNull(),
  variables: json<Record<string, any>>('variables').default({}).notNull(),
  prompts: json<RealmPrompt[]>('inputs').default([]).notNull(),   // 注意列名是 inputs
  output: integer('output').default(-1).notNull(),
  outputs: json<RealmOutput[][]>('outputs').default([]).notNull(),
}, (table) => [primaryKey({ columns: [table.masterId, table.sequence] })]);
```

要点：

- `story.presets` 是**数组** —— 一个故事可以叠加多个预设，条目会跨预设合并。
- `realm_history.outputs` 是**二维数组** `RealmOutput[][]`：
  外层是「第几次输出尝试（用于重新生成后翻页）」，内层是「一轮里的多段
  （因为工具调用会把一轮拆成多次请求）」。
- `prompts` 字段在数据库里的列名是 `inputs`（历史遗留命名差异，读代码时注意）。

### ⚠️ Realm 不是表

`Realm` 是**内存中的 DTO**，由 `src/stories/server/repository.ts` 的 `getRealm()`
把一个 Story + 预设 + 模型投影出来，并把 `histories` 数组**填洞**成定长数组后再交给前端。
理解这点很重要：数据库里没有 `realm` 表，游玩状态是「故事 + 历史」的运行时视图。

## 7. 本章速查

- 加一个新条目类型？在模块里 `schemas.entry('<表名>', ref, { data: json('data').notNull() })`
  → 用 `storages.create(...)` 造 storage → 注册进 entity 的 storage registry。
- 搜索/排序为什么不走 JSON？因为 `filter` / `sorter` 是写库时算好的冗余列。
- 为什么删主记录不用手动清子表？外键统一 `cascade`。
- 想看某模块存了什么？先找 `server/schema.ts`，再找 `server/repository.ts`。
