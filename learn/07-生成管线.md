# 07 · 生成管线

这一章讲清楚「一次 AI 回复」从组装上下文到写回历史的完整过程。
核心实现是 `src/models/client/processer.ts` 与 `src/models/client/engine.ts`。

---

## 1. 两个核心扩展点

生成管线由两个注册表驱动，分别对应「发给模型前」与「渲染给用户前」：

| 注册表    | 名字              | 接口                         | 职责                     |
| --------- | ----------------- | ---------------------------- | ------------------------ |
| Processer | `model-processer` | `init` / `prompt` / `output` | 影响**发给模型的内容**   |
| Renderer  | `realm-processer` | `init` / `stream` / `output` | 影响**呈现给用户的内容** |

### Processer

```ts
// src/models/client/processer.ts
export interface Processer<T = any> extends Registerable {
  init: (ctx: ModelInitContext) => Promise<T>; // 建缓存
  /** 处理提示词，更新输入历史 */
  prompt?: (ctx: ModelPromptContext, cache: T) => Promise<void>;
  /** 处理输出信息，更新输出属性 */
  output?: (ctx: ModelOutputContext, cache: T) => Promise<void>;
}
```

已注册的 Processer 及其依赖（`requires` 决定执行顺序）：

| Processer   | requires  | 作用                               |
| ----------- | --------- | ---------------------------------- |
| `regexes`   | —         | 向 `converts` push 文本替换        |
| `macros`    | `regexes` | 向 `converts` push Eta 求值        |
| `tools`     | —         | 建工具池；`output` 时执行工具调用  |
| `lorebooks` | `tools`   | 向 `ctx.injects` push 世界书注入器 |
| `memories`  | —         | 向 `ctx.injects` push 记忆注入器   |
| `comfyui`   | —         | 图片生成工具                       |

于是实际执行序约为：`regexes → macros → tools → lorebooks`。

### 上下文接口

```ts
export interface ModelPromptContext extends RealmContext {
  histories: RealmHistory[]; // 从最后一个总结段落开始（开场白也视为总结段落）
  history: RealmHistory; // 当前历史，应为新创建的
  current: boolean; // 是否为一轮的后续（而非重新开始生成）
  converts: ConvertContent[]; // 文本转换器链
  injects: InjectHandler[]; // 消息注入器
}

export interface ModelOutputContext extends RealmContext {
  history: RealmHistory;
}

export interface ModelResultContext extends RealmContext {
  output: RealmOutput;
  message: any; // 引擎原始 delta
  stream: boolean;
  stopped: boolean; // 引擎解析后置真 → 终止工具循环
}
```

## 2. init 阶段

页面加载时（`RealmPage`）依次调用：

```ts
await models.processers.initialize({ realm });
await stories.renderers.initialize({ realm });
```

```ts
async initialize({ realm }) {
  const context: ModelInitContext = { properties: {}, realm };
  await registry.use(async (p) => {
    const cache = await p.init(context);
    realms.initContext(realm, models.key(p.id), cache);   // 缓存到 realm.context
  });
}
```

`models.key(id)` = `model.<id>`，`realms.key(id)` = `realm.<id>`。
**同键重复初始化会抛 BusinessError**（防插件互相覆盖）。

每个 Processer 的 `init` 返回值就是它后续 `prompt` / `output` 收到的 `cache`。

## 3. prompt 阶段：组装上下文

### 3.1 取历史窗口

```ts
async function prompt({ realm, args, current }) {
  const { engine } = modelInfo(realm.model);
  const histories: RealmHistory[] = [];
  for (let i = realm.histories.length; i > 0; i--) {
    const history = await realms.history.get(i, realm);
    histories.push(history);
    if (history.summary) break; // 遇到总结段停止
    if (i === 1) histories.push(realms.opening(realm));
  }
  histories.reverse();

  const context: ModelPromptContext = {
    realm,
    properties: { args },
    current,
    history: histories.at(-1)!,
    histories,
    converts: [],
    injects: [],
  };

  await registry.use(async (p) => {
    await p.prompt?.(context, models.cache(realm, p.id)); // 各 Processer 填充 converts / injects
  });
  return await engine.prompt(context); // 交给引擎组装成具体格式
}
```

**注意顺序**：Processer 只负责往 `converts` 与 `injects` 里**注册**东西，
真正的组装发生在 `engine.prompt()`。

### 3.2 消息组装：before / middle / behind

`src/models/client/engine.ts` 的 `engines.prompt` 是组装核心：

```ts
export interface InjectMessage {
  before?: (index: number) => Promise<void>; // 在 user 注入前
  middle?: (index: number) => Promise<void>; // 在 user 和 ai 注入间
  behind?: (index: number) => Promise<void>; // 在 ai 注入后
}
export type InjectHandler = (ctx: ModelInjectContext) => Promise<InjectMessage>;
```

```ts
async prompt({ realm, histories, converts, injects, current }, ctx) {
  const { prompt, assist, caller } = ctx;
  const handlers = await Promise.all(injects.map(u => u(ctx)));   // 收集所有注入器
  for (let i = 0; i < histories.length; i++) {
    const history = histories[i];
    for (const handler of handlers) await handler.before?.(i);
    await generateInput(history);                                  // user 消息
    for (const handler of handlers) await handler.middle?.(i);
    if (i < histories.length - 1 || current) await generateOutputs(history);
    for (const handler of handlers) await handler.behind?.(i);
  }
}
```

每个历史轮次的时间线：

```
before(i) ──▶ [user 消息] ──▶ middle(i) ──▶ [assistant 输出] ──▶ behind(i)
```

世界书正是利用这三个钩子实现「layer < 100 在 user 前，layer >= 100 在 user 后」。

### 3.3 注入上下文接口

```ts
export interface ModelInjectContext {
  name: (index: number) => string; // 生成调用名（各模型可能不同）
  builder: string; // 构造类型（default / layered）
  prompt: (content: string) => void; // 用户输入
  assist: (content: string, output: RealmOutput | null) => void; // ai 输出（也可能是模拟输出）
  caller: (
    content: string,
    output: RealmOutput | null,
    callings: ToolCall[],
  ) => void; // 工具调用
  system: (content: string) => void; // 系统提示词
}
```

这四个回调就是「往对话里放东西」的全部 API。

### 3.4 输出与输入的处理

```ts
async function generateOutputs(history) {
  const outputs = realms.outputs(history); // 取当前选中的那组输出
  if (!outputs) return;
  for (const output of outputs) {
    const content = await models.convert(converts, output.content, {
      role: 'assistant',
      type: 'output',
      history,
    });
    await tools.calling(realm, output.callings); // 确保工具已执行
    if (output.callings?.length) {
      caller(content, output, output.callings); // 有工具调用 → 走 caller
    } else if (content) {
      assist(content, output);
    }
  }
}

async function generateInput(history) {
  if (!history.prompts.length) return;
  const input = arrUtils.join(history.prompts, '\n', (u) => u.content);
  const content = await models.convert(converts, input, {
    role: 'user',
    type: 'input',
    history,
  });
  if (content) prompt(content);
}
```

### 3.5 ConvertContent 链

```ts
export interface ConvertContext {
  role: string; // 'user' | 'assistant' | 'system' | 'tool'
  type: string; // 'input' | 'output'
  history: RealmHistory | null;
}
export type ConvertContent = (
  text: string,
  ctx: ConvertContext,
) => Promise<string>;

async function convert(
  converts: ConvertContent[],
  text: string,
  ctx: ConvertContext,
) {
  let res = text;
  for (const convert of converts) res = await convert(res, ctx);
  return res.trim();
}
```

正则与宏都只是往这个链上 push 一个函数。
**`role` 与 `type` 让转换器能按场景区分**（如正则的 target 过滤、工具内容不转化）。

## 4. generate 阶段：工具循环与重试

`processers.generate` 是一个 **async generator**，边生成边 `yield` 给 UI。

### 4.1 整体结构

```ts
async *generate({ args, signal, realm }) {
  const { engine, model, iterations } = modelInfo(realm.model);
  const { max: maxRetry = 3, interval = 5 } = model.properties?.retry ?? {};

  const outputs: RealmOutput[] = [];
  const history = await realms.history.get(null, realm);
  history.output = history.outputs.length;
  history.outputs.push(outputs);            // ⭐ 每次生成追加一组输出

  let iteration = iterations;
  while (iteration > 0) {                   // 外层：工具循环
    iteration--;
    const current = outputs.length > 0;     // 是否为一轮的后续
    const { input } = await prompt({ args, current, realm });
    const output: RealmOutput = { content: '', thought: '', variables: [], properties: {} };
    outputs.push(output);
    // ... 内层：重试循环
  }
}
```

`modelInfo` 的成本约束：

```ts
iterations: Math.max(2, model.iterations ?? 20);
```

即**至少 2 轮**，避免工具调用后没有后续。

### 4.2 双重 AbortController 与重试

这是整段代码最复杂的地方，用心在于「外部取消」与「内部重试」是两个不同层级的信号：

```ts
const reply = new AbortController(); // 外部信号（用户取消）
await signal(reply);
signals.setAbort(reply.signal, () => {
  iteration = 0;
}); // 用户取消 → 终止整个回复

let retry = maxRetry;
while (retry > 0) {
  const controller = new AbortController(); // 内部信号（本轮请求）
  signals.setAbort(reply.signal, (event) => {
    controller.abort((event.target as AbortSignal)?.reason); // 外部取消级联到内部
  });
  let finished = false;
  try {
    if (realm.model.stream) {
      let updateTime = new Date();
      const checkTime = () => {
        setTimeout(() => {
          if (finished) return;
          const elapsed = Date.now() - updateTime.getTime();
          if (elapsed > interval * 1000)
            controller.abort('retry'); // ⭐ 卡死即重试
          else if (!finished) checkTime();
        }, interval * 500);
      };
      const response = await models.proxy.engine.generate(
        model.id,
        input,
        controller.signal,
      );
      checkTime();
      if (response.body) {
        for await (const chunk of sseUtils.read(response.body)) {
          updateTime = new Date(); // 每收到一块就刷新计时
          yield generate(true, chunk);
        }
      }
    } else {
      const response = await models.proxy.engine.generate(
        model.id,
        input,
        reply.signal,
      );
      yield generate(true, response);
    }
    retry = 0;
  } catch (err) {
    if (
      isNetworkError(err) ||
      (isAbortError(err) && controller.signal.reason === 'retry')
    ) {
      useRealmState.getState().setRealmInfo({
        title: `realm.retry`,
        content: `(${maxRetry + 1 - retry}/${maxRetry})`,
      });
      retry--;
    } else {
      throw err;
    }
  } finally {
    finished = true;
  }
}
```

设计要点：

- **外部信号与内部信号分离**：因为两者生命周期不同（外部跨越多轮，内部每轮一个），
  所以用「关联」而非「复用」—— 外部 abort 时级联触发内部 abort。
- **卡死检测**：流式请求若超过 `interval` 秒没有新 chunk，就以 `reason = 'retry'`
  abort，然后被 catch 识别为重试（而非用户取消）。
- `signals.setAbort` 是自析构的监听器，触发后自动解绑，避免监听器泄漏。

### 4.3 每个 chunk 的处理

```ts
const generate = async (stream: boolean, delta: any) => {
  const context: ModelResultContext = {
    properties,
    output,
    stream,
    realm,
    message: delta,
    stopped: false,
  };
  await engine.result(context); // 引擎把 delta 解析进 output
  if (context.stopped) iteration = 0; // ⭐ 引擎判定结束 → 退出工具循环
  return { outputs, output };
};
```

`stopped` 由引擎在 `finish_reason === 'stop'` 或 `response.completed` 时置真。
工具调用场景下引擎不置 `stopped`，于是外层循环继续，把工具结果再发一次。

## 5. 流式渲染

在 `realms.generate` 中消费 generator：

```ts
for await (const { output } of models.processers.generate({
  realm,
  signal: async (signal) => {
    await setIndexCur();
    if (signal) setSignal(signal);
  },
})) {
  // 根据 thought / toolArgs / content 的长度变化更新顶部提示
  const curThoughtLen = output.thought.length;
  const curToolArgLen =
    output.callings?.reduce((u, c) => u + c.arguments.length, 0) ?? 0;
  if (curThoughtLen !== thoughtLen) {
    setRealmInfo({ content: `${thoughtLen}`, title: 'realm.thinking' });
  } else if (curToolArgLen !== toolArgLen) {
    setRealmInfo({ content: `${toolArgLen}`, title: 'realm.generating_tool' });
  } else {
    setRealmInfo({
      content: `${output.content.length}`,
      title: 'realm.generating',
    });
  }

  // 流式渲染条件：当前页是最新历史 且 输出页是最新输出
  const { index } = get();
  if (
    index.cur === histories.length &&
    history.output === history.outputs.length - 1
  ) {
    await stories.renderers.stream({ history, realm });
  }
}
```

**流式只在「用户正看着最新内容」时执行** —— 翻看历史时不做无谓渲染。

## 6. 工具循环一图

```
iteration = N
  │
  ├─ prompt()  收集 histories → Processers 填 converts/injects → engine.prompt() 组装
  │
  ├─ engine.generate()  ──SSE──▶ 逐 chunk ──▶ engine.result() ──▶ output.{content,thought,callings}
  │                                                    │
  │                                                    └─ stopped? ──▶ iteration = 0（结束）
  │
  ├─ 若 output.callings 非空：tools.calling() 执行 → 结果写回 callings[i].result
  │
  └─ 下一轮 iteration：把带 result 的 callings 作为历史重新发给模型
```

对应的产出结构：

```
history.outputs = [
  [ output0, output1, output2 ],   // 第一次生成：3 段（含 2 次工具调用）
  [ output0 ],                     // 重新生成：1 段
]
history.output = 1                 // 当前选中第 2 组
```

## 7. output 阶段

生成结束后：

```ts
await models.processers.output({ realm });
```

各 Processer 在此做收尾：

- `lorebooks`：对最终输出的每条 message 重跑 `matchers.analyze`，
  把命中结果**落进 `message.properties.lorebooks`**，供历史重放复现。
- `tools`：再次确保 `tools.calling` 已执行（有 `.filter(u => !u.result)` 守卫）。
- `memories`：把本轮回忆到的记忆写入输出属性。

## 8. 引擎的双层抽象

生成流程依赖两个同名但不同职责的注册表：

| 层       | 文件                          | 注册表         | 接口要点                                                    |
| -------- | ----------------------------- | -------------- | ----------------------------------------------------------- |
| 前端引擎 | `src/models/client/engine.ts` | `model-engine` | `configComponent` / `configureObject` / `prompt` / `result` |
| 后端引擎 | `src/models/server/engine.ts` | `model-engine` | `generate(ctx)`                                             |

**前端引擎负责「格式」**：把回调（`prompt`/`assist`/`system`/`caller`）
组装成 OpenAI 的 `messages` 数组或 Anthropic 的 `messages`，
并解析流式事件写进 `RealmOutput`。

**后端引擎负责「传输」**：调用 SDK，返回流或完整响应。

```ts
// src/models/server/engine.ts
async function generate(model: Model, input: any, signal: AbortSignal) {
  const name = checker.notNullOrWhitespace('engine', model.engine, 'model');
  const engine = registry.records[name];
  checker.notNullEntity(name, engine, 'model.engine');
  const apiKey =
    model.key && model.iv ? hasher.decrypt(model.key, model.iv) : '';
  return await engine.generate({ model, apiKey, signal, input });
}
```

详见 [08-模型接入](./08-模型接入.md)。

## 10. 已知问题

1. **非流式分支的 `stream` 实参可疑**：

```ts
} else {
  const response = await models.proxy.engine.generate(model.id, input, reply.signal);
  yield generate(true, response);   // ⚠️ 传了 true，但这是非流式分支
}
```

`generate(stream, delta)` 的第一个参数注释说是「后端的真实输出」，
这里传 `true` 与 `model.stream === false` 的事实矛盾，**疑似 bug**。

> laotu：bug已改

2. **重试语义混淆**：`retry` 同时承担「网络错误重试」与「流式卡死重试」，
   后者通过 `controller.abort('retry')` 借道 abort 通道实现。
   > laotu：对用户来说其实是一样的，都是网络有问题
3. **`builder: 'layered'` 的消费点**在 `src/models/**` 内找不到，
   它由前端下发给世界书注入器决定用哪种分层策略（见第 05 章）。
   > laotu：其实原来是给个注册器的，但是这layer其实是个测试，根本用不到，一般就用default。如果有必要，后续会改成注册机制。
4. **工具循环可能很费 token**：`iterations` 默认 20，且每轮都会重建完整上下文。
   > laotu：比其他agent好多了，毕竟工具集并不多，而且iterations是限制而不是必须，主要还是靠提示词和ai能力。

## 11. 本章速查

- 想让内容影响发给模型的东西？写一个 **Processer**。
- 想影响用户看到的东西？写一个 **Renderer**。
- 想插入消息？用 `ctx.injects.push(...)` 返回 `before/middle/behind` 钩子。
- 想改写文本？用 `converts.push(...)`。
- 想控制顺序？调 `requires`。
- 生成为什么会中断重试？看 `model.properties.retry` 的 `max` 与 `interval`。
