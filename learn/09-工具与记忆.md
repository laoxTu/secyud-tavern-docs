# 09 · 工具与记忆

工具让 LLM 能「做事」，记忆让 LLM 能「记住」。
两者最终都通过**工具调用通道**参与生成流程。

---

## 1. 工具数据模型

```ts
// src/tools/index.ts
export interface Tool<T = any> {
  type: string; // provider 名，决定由哪个 provider 创建
  macro?: boolean; // 绑定同名宏，开关状态与宏同步
  config: T;
}

export interface ToolCall {
  index: number; // 调用索引
  id: string; // 调用 id
  name: string; // 工具名
  arguments: string; // 参数（JSON 字符串）
  result?: string; // 执行结果
}

const defaultValue: Tool = { type: 'variable', macro: false, config: {} };
```

工具**没有独立表** —— 它是预设条目（`entryType = 'tool'`），
持久化走 preset 的 entry 机制，导出走 `storages.create`。

启用状态存在 **realm properties** 而非数据库列：

```ts
export interface ToolProperty {
  items: Record<string, boolean>;
}
```

源码注释说明「因为一开始都是勾选的，直接存 disabled」。

## 2. 双层 Provider（注意名字相同、接口不同）

| 层     | 文件                            | 注册表名        | 职责                                   |
| ------ | ------------------------------- | --------------- | -------------------------------------- |
| 服务端 | `src/tools/server/providers.ts` | `tool-provider` | 仅**归档**（导出/导入 zip 时拆分文件） |
| 客户端 | `src/tools/client/providers.ts` | `tool-provider` | **创建工具实例**                       |

### 服务端 Provider

```ts
export interface ToolProvider<T> extends Registerable {
  loadArchive(nodes, item: PresetItem<Tool<T>>, name): Promise<void>;
  saveArchive(nodes, item: PresetItem<Tool<T>>, name): Promise<void>;
}
```

只有 `scripts` 与 `agents` 有实质实现（把 `description` / `schema` / `script`
拆成独立文本文件）；其余为空实现。

### 客户端 Provider

```ts
export interface ToolItem<TArgs = any> {
  name: string;
  description: string;
  parameters: JsonSchema; // 暴露给 LLM 的 JSON Schema
  invoke: (args: TArgs) => Promise<string>;
}

export interface ToolProvider<T = any> extends Registerable {
  configComponent?: React.ComponentType;
  configureObject?: (data: FormData, tool: Tool<T>) => Promise<void>;
  create: (entry: PresetItem<Tool<T>>, realm: Realm) => Promise<ToolItem[]>;
}
```

注意 `create` 返回**数组** —— 一个条目可以产出多个工具。

## 3. 工具的组装与执行

### init：建工具池

```ts
// src/tools/client/realm.ts
export const processer: Processer = {
  id: main.name,
  async init({ realm }) {
    const cache: ToolCache = { tools: {} };
    const { items } = tools.property(realm);
    const { checkItems } = macros.property(realm);
    await utils.forEachItemsList(realm.presets, tools.plural, async (entry) => {
      const { disabled, type, macro } = entry;
      if (!type) return;
      const provider = tools.providers.registry.record(type);
      if (!provider) {
        console.warn(`[tool]: provider missing(${type})`); // 缺失只警告，不中断
        return;
      }
      const list = await provider.create(entry, realm);
      for (const tool of list) {
        cache.tools[tool.name] = {
          ...tool,
          get disabled() {
            // ⭐ 动态绑定开关
            return (
              (macro ? checkItems[tool.name] : items[tool.name]) ?? disabled
            );
          },
          set disabled(b) {
            if (macro) checkItems[tool.name] = b;
            else items[tool.name] = b;
          },
        };
      }
    });
    return cache;
  },
  async output({ history, realm }) {
    const outputs = realms.outputs(history);
    if (!outputs?.length) return;
    for (const output of outputs) await tools.calling(realm, output.callings);
  },
};
```

注意 `disabled` 用 getter/setter **直接读写 realm properties**，
所以 UI 勾选立即生效，无需重建缓存。

### calling：执行工具调用

```ts
// src/tools/client/index.tsx（概要）
async function calling(realm: Realm, callings?: ToolCall[]) {
  // 取未禁用的工具，按 name 查表
  // JSON.parse(callings[i].arguments) → tool.invoke(args)
  // 写回 toolCall.result
  // 异常被捕获，写成 `error: ${err.message}` 回灌给模型
}
```

关键设计：**异常不抛出，而是作为工具结果返回给模型**。
这样模型能看到「工具失败了」并自行调整，而不是整轮生成崩溃。

### 暴露给 LLM

```ts
tools.actives(realm); // 返回未禁用的工具
```

前端的 prompt 构造器把它映射成 OpenAI 的 `tools` 数组（`type: 'function'`）。

## 4. 四个内置 Provider

### variables —— 变量读写

| 工具           | 行为                                        |
| -------------- | ------------------------------------------- |
| `get_variable` | 按 `/` 分隔路径读取（含本轮尚未落盘的变更） |
| `set_variable` | 写变量                                      |
| `del_variable` | 删变量                                      |

**关键设计**：`set_variable` / `del_variable` **不直接改数据**，
而是把 JSON Patch 操作 push 到 `currentOutput.variables`，
由 `generateCurrentVariables` 统一应用。

这与 [06-故事与领域](./06-故事与领域.md) 的变量系统一致：
变量变更以**补丁序列**的形式挂在消息上，从而支持按输出翻页回溯。

### fetchers —— 网页抓取

`url_fetch`：

- 最多 `maxResults` 个 URL；
- 经后端 `/api/proxy` 转发（绕过 CORS）；
- HTML/XML 用 `@mozilla/readability` 抽取正文；
- 截断到 `maxLength`。

### scripts —— 自定义脚本工具

```ts
new Function('input', 'context', config.script);
```

`context` 可按开关注入 iframe 的 `document` / `window`，或 realm 的 `variables`。

> ⚠️ **这是任意 JS 执行面**。与预设里的前端 Script 条目不同，
> 这里执行在**服务端调用路径**上（由 AI 工具调用触发）。
> 与项目定位一致（自部署个人应用，部署者即管理员），属于刻意提供的能力。

### agents —— 子 Agent

构造一个子 Realm 并跑**嵌套的生成循环**：

```ts
// properties: { agent: 1 }  用于阻止嵌套 Agent（防止无限递归）
const sub = { ...realm, histories: structuredClone(realm.histories.slice(-config.maxLength)) };
await models.processers.generate({ realm: sub, ... });
```

同时把 thought / tool-arg / content 长度通过 `info()` 回调推送进度给 UI。

## 5. 记忆（Memories）

### 数据模型

```ts
// src/memories/index.ts
export interface Memory {
  text: string;
  sequence: number; // 默认 100
  importance: number; // 默认 5
  type: string; // event | relation | knowledge | other
  tags: string[];
}
```

**记忆没有独立的 SQLite 表** —— 它是**故事条目**（plural `memories`），
通过 `storages.create` 注册到 `stories.storage.registry`。

排序键：

```ts
`${sequence.padStart(6, '0')}${importance.padStart(2, '0')}${name}`;
```

即「序列号升序 → 重要度升序 → 名称」。

### RAG 是纯客户端的

```ts
// src/memories/client/processer.ts
export interface MemoryCache {
  rag: Rag<typeof memorySchema> | null;
  memories: Record<number, StoryItem<Memory>>;
}
```

- 向量库是浏览器内的 **Orama** 实例，**每次 `init` 重建**。
- 嵌入由 `@huggingface/transformers` 本地计算：

```ts
env.localModelPath = '/models/';
env.allowRemoteModels = false; // ⚠️ 模型必须本地预置（prepare 时下载）
```

两个模型：

| 模型                | 维度 |
| ------------------- | ---- |
| `all-MiniLM-L6-v2`  | 384  |
| `bge-small-zh-v1.5` | 512  |

> ⚠️ **性能注意**：每次生成都遍历全部记忆并**重新计算嵌入**、重建 Orama 库。
> 记忆量大时是明显的启动开销，且**不持久化**，刷新即丢。

> laotu：这有什么好办法吗？不重建，换模型就瞎了，重建条目多又很慢。其实可以有缓存机制，前端存cache，如果命中字符串及模型名称就复用，未命中就重新生成，但是依赖前端的内存。如果后端传的化，一个向量其实字符很多，需要截断小数点。缓存池要建多大，清理机制用什么，定时？定量？大概是按时间排序，超出百万条数据清空后十万条？大概1G左右，也不一定，hash后字符串就是256，只需要向量即可

### 检索与写入：两个工具

记忆不是自动注入的，而是通过**工具**由模型主动使用：

#### `get_memory`

参数：`content`、`types`、`tags`、`limit`（默认 3，最大 5）、`min_relevance`（默认 0.3）。

```ts
const embedding = await embed.generate({ content });
const results = await search(database, {
  mode: 'vector',
  vector: { value: embedding, property: 'embedding' },
  similarity: min_relevance,
  limit: limit * 3, // ⭐ 先多取，再重排
  where,
});
// 二次重排
score =
  hit.score + ((importance / 10) * sequence) / (realm.histories.length + 1);
// 取前 limit 个
// 把 entryId 数组 push 进 output.properties.memory
// 返回标题数组的 JSON 字符串
```

**重排公式的含义**：在向量相似度基础上，叠加「重要度 × 序列号 / 历史长度」。
即越重要、越靠后的记忆在长对话中越容易被召回。

#### `set_memory`

生成嵌入 → `stories.proxy.entry.add(...)` → 写缓存 → `insert(database, ...)`。

### 注入：又是伪工具调用

回忆出的记忆以**一次 `get_knowledge` 工具调用的返回值**形态出现：

```ts
callings.push({
  index,
  id: `${name(simulation++)}m`,
  name: models.engines.knowledge.info.name, // 'get_knowledge'
  arguments: models.engines.knowledge.args({ type: 'memory' }),
  result: arrUtils.join(items, '\n', (u) => `- ${u.name}: ${u.text}`),
});
caller('', null, callings);
```

与世界书 `role: 'knowledge'` 用的是同一套技巧，只是 `type` 不同。
去重依赖局部 `visitedKeys` 与跨历史 `visited` 两个集合。

### 与世界书的对比

|                      | 世界书                     | 记忆                          |
| -------------------- | -------------------------- | ----------------------------- |
| 归属                 | 预设条目                   | 故事条目                      |
| 触发                 | 内容/变量/向量**自动**匹配 | LLM **主动**调用 `get_memory` |
| 索引时机             | 每次 prompt 组装时匹配     | init 时建库，生成后回填       |
| `get_knowledge` type | `lorebook`                 | `memory`                      |

## 6. 工具循环（回顾）

工具的执行横跨 `prompt` 与 `output` 两个阶段：

```
第 N 轮：
  prompt()  ──▶ engine.prompt() 把 actives 工具映射成 tools 参数
     │
  engine.generate() ──▶ 模型可能返回 tool_calls
     │                     └─ engine.result() 写进 output.callings（arguments 逐步拼接）
     │
  generateOutputs() ──▶ tools.calling(realm, output.callings)  执行并写回 result
     │
  下一轮：带着已填充 result 的 callings 重新请求
     │
  直到 stopped 或 iteration 耗尽
```

`tools.calling` 在 `output` 阶段还会再被调一次（有 `.filter(u => !u.result)` 守卫防重复执行）。

## 7. 已知问题

1. **记忆 RAG 每次生成重建**：全量重新嵌入 + 重建 Orama，不持久化。
2. **`set_variable` 走 JSON Patch**：读取时要经过 `patch()` 回放才能看到最新值，
   直接读 `history.variables` 会拿到旧值。
3. **scripts 工具的任意代码执行**：属刻意设计，但审计时值得注意。
4. **工具 provider 缺失只 warn**：条目的 `type` 写错时工具静默消失，不报错。
5. **`agents` 的嵌套防护**：靠 `properties.agent` 标记，不是硬性限制。

## 8. 本章速查

- 想加一个工具？写一个客户端 `ToolProvider`（含 `create`），注册到 `tool-provider`。
- 想让工具能被导出？再写一个服务端 `ToolProvider`（含 `loadArchive`/`saveArchive`）。
- 想控制工具的开关？它存 `realm.properties.tool.items`；
  `macro: true` 时改为与宏的 `checkItems` 同步。
- 工具报错会怎样？作为 `error: <msg>` 文本回灌给模型，不会中断生成。
- 记忆怎么进上下文？模型调用 `get_memory`，回忆结果伪装成 `get_knowledge` 工具结果注入。
