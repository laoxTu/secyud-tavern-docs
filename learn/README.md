## 三个最关键的认知

如果只记住三件事，是这三件：

### 1. 一切皆注册表

模块通过 `manifest.json` 声明自己被生成代码引用，
其 `client/index.tsx` 与 `server/index.ts` 的 **default 导出就是注册函数**。
菜单、Tab、按钮、生成处理器、渲染器、匹配器、工具、模型引擎……
全部通过 `Registry` 注册，并用 `requires` 做拓扑排序。

**要找一个功能从哪来，就去对应注册表找 `register` 调用点。**

### 2. Preset 定义玩法，Realm 承载游玩

- **Preset** 是可复用的配置包（宏/正则/脚本/样式/世界书/工具）。
- **Realm** 是 Story 的**运行时投影**（不是数据库表），
  绑定模型 + 预设 + 历史，`context` 字段缓存各插件的 init 结果。

界面完全由预设脚本在未加 sandbox 的同源 iframe 里绘制 ——
**没有预设就是一片空白，这是设计而非缺陷。**

### 3. 编译期生成，而非运行时插件

`pnpm prepare` 扫描 manifest 生成静态 import 的注册表，
保留原生 Next.js 的开发体验；代价是 **改 manifest 必须重新 prepare 并重启**。

## 关于本笔记的可靠性

- 所有代码引用都经过直接阅读，关键处标注了文件路径。
- 发现的可疑行为（疑似 bug）都**明确标注为「疑似」**，
  并说明了不确定的原因，没有当作事实陈述。
- 项目当前测试覆盖很低（仅 4 个测试文件，且其中一个无断言），
  笔记中的行为描述均来自**静态源码阅读**，未经运行时验证。

如果你要基于这些笔记做修改，建议先用一个最小的世界书 / 预设
在开发环境实测一遍相关行为。
