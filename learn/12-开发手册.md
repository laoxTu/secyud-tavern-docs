## 1. 环境搭建

前置：Node.js 20.9+（Next.js 16 最低要求）、pnpm、Git。

```bash
git clone --recursive https://github.com/laoxTu/secyud-tavern.git
cd secyud-tavern
pnpm install
pnpm prepare          # ⚠️ 必须执行
pnpm dev              # → http://localhost:12804
```

- `--recursive` 用于拉取 `docs` 子模块（已 clone 过的执行
  `git submodule update --init --recursive`）。
- 生产构建：`pnpm build && pnpm start -p 12804`。
- 仓库根的 `start.sh` / `start.bat` 是给最终用户的一键脚本，开发时用不到。

### ⚠️ 全新克隆必须先 prepare

`src/generated/*`、`src/app/api/**`、`scripts/generated/*`、`plugins/`、`data/`、
`public/`、`.env` **全部被 gitignore**。
不跑 `pnpm prepare`，`@/generated/*` 与 `@plugins/*` 会全部解析失败。

### `pnpm prepare` 做了什么（6 步）

| #   | 步骤                     | 产出                                                                          |
| --- | ------------------------ | ----------------------------------------------------------------------------- |
| 1   | 复制 favicon             | `public/favicon.svg`                                                          |
| 2   | `migrate(root)`          | `data/` 目录；`drizzle-kit generate` 生成迁移；应用到 `data/secyud-tavern.db` |
| 3   | `generateEnvFile(root)`  | `.env`：`SECRET_SALT`（40 位）+ `SECRET_KEYS`（39 位），文件已存在则跳过      |
| 4   | `downloadModels(root)`   | 下载 embedding 模型到 `public/models/`（默认走 `hf-mirror.com`）              |
| 5   | `analyzeManifests(root)` | 生成 4 个注册表/资源文件                                                      |
| 6   | `api.default(root)`      | 生成 `src/app/api/**` 与 `src/generated/api-path.ts`                          |

第 3 步的细节（`scripts/operations/env.ts`）：用 **`flag: 'wx'`** 写入，
所以**文件已存在时不会覆盖**（捕获 `EEXIST` 并静默忽略其他错误）。
这正是「`.env` 丢了就解不开旧 Key」的机制来源。

第 4 步的镜像配置在 `scripts/build-config.json`：

```json
{ "mirrors": { "huggingface": "https://hf-mirror.com" } }
```

第 5 步的四个产物：

- `src/generated/resources.ts` —— i18n 资源加载器
- `scripts/generated/route.ts` —— 服务端 API 索引（只有 9 个模块有 `server/api.ts`）
- `src/generated/server-registerer.ts` —— `registerServerPlugin()`
- `src/generated/client-registerer.ts` —— `registerClientPlugin()`

**新增、重命名或修改任何 `manifest.json` 后都必须重新 prepare 并重启** —— 编译期插件无法热更新。

> 📌 一个容易忽略的点：**加一个 `server/api.ts` 不需要改 manifest**
> （路由生成只看文件存在），但**加一个 `client`/`server` 注册脚本必须改 manifest**。
> 详见 [01 篇](./01-架构与模块系统.md) §4。

## 2. 常见任务

### 新增一个模块

1. 建目录 `src/<mod>/`，写 `manifest.json`：

```jsonc
{ "id": "mymod", "client": "client", "server": "server" }
```

2. `index.ts` 放类型与元信息（记得导出 `name` / `plural` 对）；
3. `client/index.tsx` 的 **default 导出**写注册逻辑：

```tsx
export default async function () {
  globals.menus.register(mymod.menu);
}
```

4. `server/index.ts` 同样 default 导出注册逻辑；
5. `localization/zh.json` + `en.json`；
6. `pnpm prepare` 并重启。

### 新增一个 API 接口

在模块的 `server/api.ts` 里加嵌套对象，键名即路径，叶子是 HTTP 方法：

```ts
export default {
  mymod: {
    GET: async (request, { searchParams }) => response.json(await list()),
    '{id}': {
      GET: async (request, { params }) => {
        const { id } = await params; // ⚠️ params 是 Promise
        return response.json(await get(id));
      },
    },
  },
};
```

`pnpm prepare` 后前端即可 `get('mymod/{id}', { params: { id } })`（有类型校验）。

### 新增一个预设条目类型

按 `storages.create`（服务端）+ `createPresetEntryState`（客户端）的对称模式：

1. `src/<mod>/index.ts` —— 定义条目接口 + `name` / `plural` / `default`；
2. `src/<mod>/server/storage.ts` —— 调 `storages.create`，提供 `criteria` 与归档钩子；
3. `src/<mod>/server/index.ts` —— 注册进 `presets.storage.registry`；
4. `src/<mod>/client/realm.ts` —— 按需实现 `Processer` / `Renderer`；
5. `src/<mod>/client/content.tsx` —— 编辑 UI，`createPresetEntryState`；
6. `src/<mod>/client/index.tsx` —— 注册 tab / processer / renderer。

### 新增一个工具

1. 写客户端 `ToolProvider`：

```ts
export const provider: ToolProvider<MyConfig> = {
  id: 'mytype',
  configComponent: ConfigUI,
  configureObject: async (data, tool) => { tool.config = ...; },
  async create(entry, realm) {
    return [{
      name: 'my_tool',
      description: '...',
      parameters: { type: 'object', properties: {...} },
      async invoke(args) { return 'result'; },
    }];
  },
};
```

2. 注册到 `tools.providers.registry`；
3. 若要支持导出，再写服务端 `ToolProvider`（`loadArchive` / `saveArchive`）。

### 新增一个模型供应商

写两个引擎并注册：

- `server/engine.ts`：`generate({ model, apiKey, signal, input })` 调 SDK；
- `client/engine.tsx`：`prompt` 组装格式、`result` 解析输出、
  `configComponent` + `configureObject` 做配置 UI。

### 新增一个世界书匹配器

```ts
export const myMatcher: Matcher = {
  id: 'mymatch',
  configComponent: ConfigUI,
  async configureObject(data, lorebook) { lorebook.expression = ...; },
  async match(ctx, lorebook) { return true / false; },
};
```

注册到 `matchers.registry`。

## 3. 代码约定

### 导出风格

- 类型、工厂、hook **直接导出**；
- 工具函数与常量集合**以对象形式导出**（`presets`、`strUtils`、`jsonUtils`、`fileUtils`）。

### 命名约定

- `name` / `plural` 成对出现：`name` 用于 entryType 与注册 id，
  `plural` 用于 `model.entries[plural]` 键名与归档目录名。
- 数据库列名 snake_case，TS 属性 camelCase。

### 格式化

Prettier，单引号、80 列，启用 import 排序与 JSON key 排序插件：

```bash
pnpm format        # ⚠️ 只作用于 src/，不含 tests/scripts/plugins
```

### 提交前必须通过

```bash
pnpm format
pnpm test run
pnpm build
```

提交信息用简短的英文祈使句（`fix lora`、`add json support for macro`），
一个提交只做一件事。**不要在功能 PR 里改版本号。**

### 易被误读的契约（读源码前先看这段）

有几处写法的正确性依赖**代码之外的前提**，只看实现很容易判成 bug。
另有一组是**读代码时的结构规律**，先记住能省很多力气。

**⭐ 「两侧同名」是规律，不是陷阱。**
`model-engine`、`tool-provider`、`comfyui-model-importer`
在 `client/` 与 `server/` 各有一个注册表、名字相同。
这表示「**一个域，两个运行时半边**」：客户端管**界面与交互**
（`configComponent` / `configureObject` / `create`），
服务端管**执行与数据**（`generate` / `download` / 归档）。
看到同名应该立刻想到去找这两面各自做什么，**而不是担心混用**。
完整判据见 [01 篇](./01-架构与模块系统.md) §2。

反过来，**同名却合不成一个域，才是问题**：服务端 `ToolProvider`
只有归档钩子、没有"提供工具"的语义，所以那个名字是有缺口的。

**真正容易混的是这三组「不同名但同形」：**

| 容易混的一对 | 区别 |
| --- | --- |
| `model-processer` vs `realm-processer` | 都在客户端，但一个属于 `models`（影响发给模型的内容）、一个属于 `stories`（影响渲染）；名字里的是**处理对象**，不是运行时侧 |
| `TaskRunner.execute(task)` vs `TaskProvider.execute(args, controller)` | 同名不同签名：前者是基类的抽象方法，后者是 provider 的接口 |
| `src/plugins/` vs `plugins/` | 前者是框架本体（Registry 实现），后者是外部插件目录 —— 这才是真的同名不同物 |

**`jsonUtils.merge(lft, rht)` —— 左值是累加器。**
它会**原地修改 `lft`** 并返回同一个对象；`rht` 的值要么被 `structuredClone`，
要么被递归合并进 `lft`，**永远不会被改动、不会被别名**；
且 `rht` 中值为 `null` / `undefined` 的键会被**跳过**。
所以约定是：`lft` 是「初始值 / 调用方自己的对象」，`rht` 是「外部来的数据」——
这是有意的，不是疏漏。（`buildUrl` 曾是同款问题，现已改为克隆，见 §6 已修复表。）

**`files` 模块的一个字段存两种东西。**
`files.url(id)` 按值分流：能通过 `uuid.validate` 的 → `/api/files/{id}/resource`，
否则当外部 URL 原样返回（`ImageUploader` 会把用户填的外链**直接当 id 存库**）。
所以这个字段的值域是「GUID 或任意 URL」，校验只有「能否 `new URL()`」一层。
当前消费点（`components/media.tsx` 的 `<img>` / `<video>` 的 `src`）不会执行脚本，
但把这个 helper 复用到 `href` / `window.open` 时**必须自己加协议白名单**。

**`deserializeMimeType` / `serializeMimeType` 只保证前段 `type` 有意义。**
`args` 由 `split(';')` 拼出，`boundary="a;b"` 这种带引号内含分号的参数会被切坏、
往返不一致。这是**刻意**的：该字段只用来存取「前面的类型」，`args` 不参与语义。

**`checker` 里只有带 `notNull` 前缀的两个是真必填。**
`notEmpty` 与 `notWhitespace` 用的是 `value?.trim() !== ''`，
`undefined` 会**通过**。要"必填"就写 `notNullOrWhitespace`。

     return structuredClone((await import('./entries.json')).default);

   不确定的行为**不要写 `it.fails` 或断言**，先描述现象再问。
   这条约定解释了为什么 `tests/TODO.md` 里有一大段

### ⚠️ 本机（DSH 沙箱）跑不了完整测试

我这次复核时试过 `npx vitest run`，失败在**配置加载阶段**：

```
Error: Build failed with 1 error:
[plugin externalize-deps]
Error: spawn EPERM
  at ... vite/dist/node/chunks/node.js:2481
```

原因是 Vite 的 `optimizeSafeRealPathSync` 会 `execFile` 一个子进程
（Windows 上用 `dir` 之类的命令解析真实路径），而 **DSH 的文件沙箱
不允许进程开命名管道**，于是 piped stdio 的 `spawn` 直接 `EPERM`。

这不是用例的问题，也不是项目的问题。`tests/GUIDELINES.md` 里
作者也记录过同一个现象并给出了正确结论：

> 如果启动阶段报 `Error: spawn EPERM`（vite 加载配置时会 spawn 子进程），
> 那是沙箱/权限拦截了子进程，不是用例的问题，需要放宽运行权限。

> 📌 **我在这次复核里的做法**：不去绕过沙箱，
> 而是把需要验证的**纯函数抠出来单独跑**（例如 `buildUrl`），
> 其余结论靠静态阅读 + 与 `tests/TODO.md` 交叉印证。
> 这个办法只能验证纯函数，涉及 React 生命周期、EventSource、
> 数据库的部分**必须真跑测试** —— 所以那些结论我一律标注了置信度。

## 5. 安全性的取舍（重要）

`CONTRIBUTING.md` 有一节专门说明，务必先读：

> 本项目的定位是**自部署的个人应用**，部署者即管理员，不存在多租户边界。
> 预设中的脚本、样式、宏允许执行使用者自己编写的 JS 与 CSS，
> 这是产品刻意提供的核心能力，不是缺陷。

代码里一些「看起来危险」的写法属于同类取舍：

- 预设脚本注入 iframe（iframe **未设 `sandbox`**，同源）；
- `tools/scripts` 用 `new Function(...)` 执行任意 JS；
- 宏用 Eta 求值任意表达式；
- ~~Civitai 下载用 `execSync` 拼接 curl 命令~~ → ✅ 已改为 `execFileSync`
  （不再经过 shell，见 [10 篇](./10-ComfyUI.md) §6）；
- `url_fetch` 会把用户/模型给的任意 URL 交给服务端 `/api/proxy` 转发
  （SSRF 面：`/api/proxy` 对目标地址没有白名单）。

> 如果你认为某处确实构成风险，**请先开 Issue 讨论**，
> 不要直接提交「移除这项能力」式的加固 PR —— 这会破坏已有用户的预设与插件。

> 📌 复核时观察到一条**很有说服力的规律**：
> 凡是「前提被写进 `CONTRIBUTING.md`」的地方（iframe 无 sandbox、
> 执行用户脚本），AI 复核提的 issue 都被作者直接引用文档驳回；
> 凡是**没写下前提**的地方，同样的 AI 会反复误报。
> 这个观察在 [13 篇](./13-心得体会.md) §七 里有更完整的展开。

### 🔴 高影响（建议优先关注）

**33.** 🔬 **`files` 的 DELETE 接口会报 500，而文件其实已经删掉了。**

```ts
// src/files/server/api.ts —— DELETE
const models = await files.repository.delete(id);   // ⚠️ 返回 Promise<void>
return response.json(models);                       // → NextResponse.json(undefined)
```

`NextResponse.json(undefined)` 会抛 `TypeError: Value is not JSON serializable`，
被 `errorInterceptor` 兜成 500。对照 `presets` / `models` 的写法则都是显式
`response.json(null)`。**这是三条里唯一「用户能直接感知到」的缺陷**
（删文件之后弹报错，但刷新会发现文件已消失）。

**34.** 🔬 **`interceptors/server` 的 `__initialized` 在 `await` 之前就置真。**

```ts
const global = globalThis as { __initialized?: boolean };
if (!global.__initialized) {
  global.__initialized = true;          // ⚠️ 先置真
  if (process.env.NODE_ENV === 'development') { /* 替换 console.debug */ }
  await registerServerPlugin();         // ⚠️ 再注册；这里失败就永远不会重试
}
```

后果：**模块注册一旦失败（例如某个 provider init 抛错），后续所有请求
都会在「拦截器链为空」的状态下继续跑**，而不是重试或崩溃。
这属于「早失败」原则的反例 —— 与 [01 篇](./01-架构与模块系统.md) §2
里 `Registry` 那套「错了就炸」的态度形成鲜明反差。

**35.** 🔬 **`signals.proxy.subscription` 丢掉连接 id**，任务进度推送无法到达。
完整分析见 [03 篇](./03-接口层与横切.md) §8 第 1 条。

**36.** 🔬 **`tasks` 的 `restart` 不写回 `running`**，新一轮执行收不到取消；
**`success`/`failed` 无条件覆盖 `status`**，取消会被回写成完成/失败。
见 [17 篇](./17-任务与调度.md) §8 第 3、4 条。

**37.** 🔍 **`stories/client/realms/index.ts` 的 create 阶段抛错会让
`generating` 永久卡在 `true`。**

```ts
if (create) {
  try {
    // …
    const { sequence } = await stories.proxy.history.add(realm.id, history);  // ⚠️ 抛在这里
  } catch (err) {
    set({ summary: false, content: '' });
    throw err;                     // ⚠️ rethrow，下面的 try/finally 还没进
  }
}
try {
  // …
} finally {
  set({ generating: false });      // ⚠️ 永远不会执行
}
```

后果：此后 `if (generating) return` 让 `generate` 恒早退，
界面停在 `realm.generating` 提示上，**只能刷新页面**。
这是我在复核时**新发现的**，📄 TODO.md 记录为「已实测」。

### 预设与转换链

**38.** 🔬 **`lorebooks/client/content.tsx` 每次提交都把 `expression` 清空。**

```ts
const entry = {
  data: {
    match: editor.id, content, type,
    expression: {},                  // ⚠️ 先清空
    // …
  },
};
await editor.configureObject?.(data, entry.data!);   // 可选钩子回填
```

`configureObject` 是**可选**的（`Matcher` 接口里带 `?`）。
所以**没有 `configureObject` 的匹配器，保存一次就把已有 `expression` 抹掉**。
目前五个匹配器只有 `vector` 没有 `configureObject` ——
而它本来也不读 `expression`，所以暂时**没有实际受害者**，
但这是个「等着被踩」的坑。

**39.** 🔍 **`lorebooks/client/content.tsx` 的 `match` 指向已删除的匹配器时静默不提交**
（`if (!editor) return;`，无提示、无 warn）。

**40.** 🔬 **`normal` 匹配器要求 `expression.keywordsLength` 必须存在**，
否则 `normalMatch` 第一行就 `return false`。
从外部导入的世界书若缺这个字段，会**恒不匹配且没有任何提示**
（见 [05 篇](./05-世界书.md) §3）。

**41.** **正则用字符串形式的 `replace`**，没有 `new RegExp()`，
也不解析 `/.../g` 标志 —— 写 `/a/g` 会被当字面量。
**应用顺序由条目 `name` 决定**（`sorter` 是 `name`）。

**42.** **`archive.get.fuzzy` 是前缀匹配 + 取第一个命中**
（`Object.keys(nodes).find(...)`）。导出/导入两侧文件名前缀必须一致；
**前缀有歧义时会静默取错文件**。

**43.** **`preset_entry` 的 tags 索引用 `like '%tag%'`**，索引实际无效。

**44.** **`listWithRequires`（现 `traversal`）遇到不存在的依赖静默跳过**，不报错。

### 模型与生成

**45.** 🔬 **`models/client/setting.tsx` 无法清除已保存的 API Key。**

```ts
key: item.key === key || !key ? undefined : key,
```

「输入框留空」与「没改过」都会得到 `!key === true` → `undefined` →
`repository.update` 里 `if (model.key)` 为假，**不会覆盖旧密钥**。
所以想换成「无密钥」的状态在当前 UI 上做不到。

**46.** 🔬 **`checker.validJson` 用解析结果的真值判断。**

```ts
validJson(value?) { if (jsonUtils.parse(value)) return value ?? ''; /* 抛 */ }
```

于是 `'0'` / `'false'` / `'null'` 这些**合法 JSON** 会被判成非法
（`parse` 返回 `0` / `false` / `null`，全是假值）。
注意 `validJsonOrEmpty` 也有同样的问题（它只是多放行了空串）。

**47.** 🔬 **`checker.notEmpty` 与 `notWhitespace` 对 `undefined`/`null` 不抛**
（与 `notNullOrWhitespace` 相反）。「必填」语义只有
`notNullOrEmpty` / `notNullOrWhitespace` 有，见 [03 篇](./03-接口层与横切.md) §3。

**48.** 🔬 **`checker.notNullEntity` 的 code 是 `default.entity_not_found`**，
而其余 checker 都是 `error.*` 前缀（疑似漏了前缀，且缺 i18n key
时会显示原始 code）。

**49.** 🔍 **`errors.serialize` 的 `innerError` 不是 `Error` 时，`inner` 会变成 `{}`**
（因为读取 `undefined.name` 等属性不抛错，只是全 undefined，`JSON.stringify`
会把它们去掉，剩下 `{}`）。

**50.** 🔍 **`forms.int` 仍是裸 `parseInt`**，清空数字输入框即得 `NaN`。
UI 上的 `min` 只约束「有值时的范围」。目前 `iterations` / `retry.max`
都有 `Math.max(...)` 兜底（但**兜不住 `NaN`**），见 [07 篇](./07-生成管线.md) §10 第 3 条。

**51.** 🔬 **`models/client/setting.tsx` 新建模型的 payload 不带 engine**
（`engine` 只在不新建时由 `configureObject` 写入），
所以新建后必须先选一次 provider 才能保存。

**52.** **`iterations` 被 `Math.max(2, ...)` 钳制，最小 2 轮**；
`retry` 同时承担「网络错误重试」与「流式卡死重试」。

**53.** **`realm.context` 同键重复初始化会抛错** —— 插件共用 key 会直接崩。
（这是刻意的保护，见 [06 篇](./06-故事与领域.md) §2。）

### 世界书与记忆

**54.** 🔬 **RAG 关掉后记忆注入链路整体失效**
（`cache.memories` 只在 `if (cache.rag)` 分支里填充）。
`get_memory` 工具会返回 `'warn: RAG is not enabled'`，但自动注入没有任何提示。

**55.** 🔍 **`get_memory` 的 `tags` 过滤对非 ASCII 标签永远命中不到**
（Orama 默认英文分词器会把中文切成空 token）。
用中文标签筛选记忆是无效的。

**56.** 🔬 **`get_memory` / `get_lorebook` 的 JSON Schema `default`
与 `invoke` 里的解构兜底不一致**：schema 声明取全局 RAG 设置（5 / 0.75），
而解构兜底写的是 `limit = 3` / `min_relevance = 0.3`。
模型不传参时用的是后者。

**57.** 🔬 **`rags.cache` 的超限清理固定删最旧 100 条**，
与「超限多少」无关；`cacheLimit: 2` 时写第 3 条会把 3 条全删掉（含刚写的）。

**58.** 🔍 **`scripts` 工具的 `context.variables` 是 `history.variables` 基线快照**，
不是回放补丁后的最新值。

### 前端

**59.** **`realms` 是全局单例**，同页面只能有一个活跃 realm。

**60.** **iframe 的 `key={1}` 不能删**（生产环境引用问题，开发环境复现不了）。

**61.** **iframe 未设置 `sandbox`**，预设脚本拥有完整同源权限。

**62.** 🔬 **`useSse(type, callback)` 的 `useEffect` 依赖数组为空**，
回调变化不重新订阅 —— 传进 `useSnse` 的 callback 必须是稳定引用。

**63.** 🔬 **`useRealmState.setRealmInfo` 只在 `generating` 为真时写入**，
所以生成结束后无法主动清空进度显示。

**64.** 🔬 **`UserInput` 挂到 iframe 上的 `userInput.text.get()`
是挂载那次渲染的 `content` 闭包**（`useEffect` 只依赖 `[inputRef]`），
挂载后再 `setState` 不会反映到 getter。预设脚本通过
`userInput.text.get()` 读输入框会拿到**过期值**。

**65.** 🔍 **`realms.iframe` 在 `generate` 里没有可选链**
（`iframe.contentWindow`），而 `postMessage` 用的是 `?.`，两处不对称。

**66.** 🔍 **`stories` 的 `clone` 不复制条目**：`repository.get(originId)`
没传 `{ entities: true }`，所以克隆出来的故事只有主表字段、没有条目。
对照 `presets` 的 clone 会 `entry.list` + 分组 `make` 复制全部条目。

### 基础设施

**67.** **迁移会执行两次**：`pnpm prepare` 一次，`instrumentation.ts` 再一次（幂等）。

**68.** 🔬 **`SECRET_SALT` / `SECRET_KEYS` 由 `Math.random()` 生成**，
非密码学安全随机源；且**丢失后无法解密已存的 API Key**。
`hasher` 是模块级单例，读一次环境变量后不再更新。

**69.** 🔬 **`hasher` 有 `?? 'secyud'` 兜底** —— 没配 `.env` 时不报错，
而是用公开常量当密钥。排查「换机器解不开 Key」时先看这个。

**70.** 🔍 **`database/server/factory.ts` 的 `registry.record(type)!` 用了非空断言**，
未注册的 `type` 会抛裸 `TypeError`（而不是 `BusinessError`）。

**71.** 🔍 **`repositories.entry.make([])` 会执行 `values([])`**，
drizzle 直接抛 `values() must be called with at least one value`
（`comfyui` 的 workflow repository 同类）。

**72.** 🔍 **`dbStorage.getItem` 有一处双重编码。**

```ts
// src/database/client/storage.ts
const setting = await settings.proxy.get<any>(name);
return JSON.stringify(setting || '{}');
```

取不到设置时返回的是字符串 `"{}"`（4 个字符，含引号），
而不是 `'{}'`。zustand 的 `createJSONStorage` 会再 `JSON.parse` 一次 ——
第一次 `parse('"{}"')` 得到字符串 `'{}'`，于是持久化状态变成**字符串而不是对象**。
另外 `setting || '{}'` 用的是真值判断，`0` / `''` / `false` 都会被当成「没有设置」。

**73.** **有 4 处 store 用 `localStorage` 而不是 `dbStorage`**：
`global/client/state.ts`（菜单开合）、`components/resizeable.tsx`（面板尺寸）、
`comfyui/client/state.ts`（ComfyUI 主页状态）、
`stories/client/realms/state.ts`（realm 的 `pinned`）。
所以「跨设备同步」只覆盖走 `dbStorage` 的那部分。

### 数据与历史（仍然成立的旧条目）

**74.** **`history.get` 按 offset 索引取，不是按 sequence**，
但 HTTP 路径参数名叫 `sequence`；`set` / `del` 用的才是真 sequence。
详见 [06 篇](./06-故事与领域.md) §3。

**75.** **Realm 不是表** —— 是 Story + presets + model 的运行时投影，
`histories` 是填了 `null` 的定长数组（懒加载）。

**76.** **`getRealm` 不加载 story 条目**，需要条目数据要另行请求。

**77.** **`entryId` 用 `max(entry_id) + 1` 分配，删除后会复用。**
配合「条目通过 `entryId` 定位」，如果外部缓存过 `entryId`，
删一条再加一条就可能指向了不同的条目。

**78.** **`files` 用 `hash` 唯一索引做内容去重**：
上传同一份内容会直接返回已有 id，不会新建文件。

## 7. 调试技巧

- **看注册顺序**：`Registry` 会打 `[name] registered: id` 与排序后的 id 列表，
  在 console 里能直接看到拓扑序。
- **看 realm context**：`realms.context` 抛出未初始化错误时会打印
  `Object.keys(realm.context)`，能快速定位缺哪个插件的 init。
- **`console.debug` 的生产行为**：`next.config.ts` 的
  `compiler.removeConsole` 在生产只保留 `error/warn/info`，
  **大量调试日志只在 dev 可见**。
- **准备阶段出错**：`pnpm prepare` 里 `fileUtils.execute` 会跑
  `npx drizzle-kit generate`，schema 写错会在这里失败。
- **改了 manifest 没生效**：一定是忘了 `pnpm prepare` 或没重启。

   不要求是 git 仓库或子模块。

5. **补文档** —— `CONTRIBUTING.md` 里「当前覆盖率较低」那句已经过期；
   `docs/learn`（本目录）是 AI 整理的笔记，也可以修。
