# 12 · 开发手册

这一章是实操向的：环境搭建、常见任务的做法、以及一份**踩坑清单**。

---

## 1. 环境搭建

前置：Node.js 20.9+（Next.js 16 最低要求）、pnpm、Git。

```bash
git clone --recursive https://github.com/laoxTu/secyud-tavern.git
cd secyud-tavern
pnpm install
pnpm prepare          # ⚠️ 必须执行
pnpm dev              # → http://localhost:12804
```

- `--recursive` 用于拉取 `docs` 子模块（已 clone 过的执行
  `git submodule update --init --recursive`）。
- 生产构建：`pnpm build && pnpm start -p 12804`。
- 仓库根的 `start.sh` / `start.bat` 是给最终用户的一键脚本，开发时用不到。

### ⚠️ 全新克隆必须先 prepare

`src/generated/*`、`src/app/api/**`、`scripts/generated/*`、`plugins/`、`data/`、
`public/`、`.env` **全部被 gitignore**。
不跑 `pnpm prepare`，`@/generated/*` 与 `@plugins/*` 会全部解析失败。

### `pnpm prepare` 做了什么（6 步）

| #   | 步骤                     | 产出                                                                          |
| --- | ------------------------ | ----------------------------------------------------------------------------- |
| 1   | 复制 favicon             | `public/favicon.svg`                                                          |
| 2   | `migrate(root)`          | `data/` 目录；`drizzle-kit generate` 生成迁移；应用到 `data/secyud-tavern.db` |
| 3   | `generateEnvFile(root)`  | `.env`：`SECRET_SALT`（40 位）+ `SECRET_KEYS`（39 位），文件已存在则跳过      |
| 4   | `downloadModels(root)`   | 下载 embedding 模型到 `public/models/`（默认走 `hf-mirror.com`）              |
| 5   | `analyzeManifests(root)` | 生成 4 个注册表/资源文件                                                      |
| 6   | `api.default(root)`      | 生成 `src/app/api/**` 与 `src/generated/api-path.ts`                          |

第 5 步的四个产物：

- `src/generated/resources.ts` —— i18n 资源加载器
- `scripts/generated/route.ts` —— 服务端 API 索引
- `src/generated/server-registerer.ts` —— `registerServerPlugin()`
- `src/generated/client-registerer.ts` —— `registerClientPlugin()`

**新增、重命名或修改任何 `manifest.json` 后都必须重新 prepare 并重启** —— 编译期插件无法热更新。

## 2. 常见任务

### 新增一个模块

1. 建目录 `src/<mod>/`，写 `manifest.json`：

```jsonc
{ "id": "mymod", "client": "client", "server": "server" }
```

2. `index.ts` 放类型与元信息（记得导出 `name` / `plural` 对）；
3. `client/index.tsx` 的 **default 导出**写注册逻辑：

```tsx
export default async function () {
  globals.menus.register(mymod.menu);
}
```

4. `server/index.ts` 同样 default 导出注册逻辑；
5. `localization/zh.json` + `en.json`；
6. `pnpm prepare` 并重启。

### 新增一个 API 接口

在模块的 `server/api.ts` 里加嵌套对象，键名即路径，叶子是 HTTP 方法：

```ts
export default {
  mymod: {
    GET: async (request, { searchParams }) => response.json(await list()),
    '{id}': {
      GET: async (request, { params }) => {
        const { id } = await params; // ⚠️ params 是 Promise
        return response.json(await get(id));
      },
    },
  },
};
```

`pnpm prepare` 后前端即可 `get('mymod/{id}', { params: { id } })`（有类型校验）。

### 新增一个预设条目类型

按 `storages.create`（服务端）+ `createPresetEntryState`（客户端）的对称模式：

1. `src/<mod>/index.ts` —— 定义条目接口 + `name` / `plural` / `default`；
2. `src/<mod>/server/storage.ts` —— 调 `storages.create`，提供 `criteria` 与归档钩子；
3. `src/<mod>/server/index.ts` —— 注册进 `presets.storage.registry`；
4. `src/<mod>/client/realm.ts` —— 按需实现 `Processer` / `Renderer`；
5. `src/<mod>/client/content.tsx` —— 编辑 UI，`createPresetEntryState`；
6. `src/<mod>/client/index.tsx` —— 注册 tab / processer / renderer。

### 新增一个工具

1. 写客户端 `ToolProvider`：

```ts
export const provider: ToolProvider<MyConfig> = {
  id: 'mytype',
  configComponent: ConfigUI,
  configureObject: async (data, tool) => { tool.config = ...; },
  async create(entry, realm) {
    return [{
      name: 'my_tool',
      description: '...',
      parameters: { type: 'object', properties: {...} },
      async invoke(args) { return 'result'; },
    }];
  },
};
```

2. 注册到 `tools.providers.registry`；
3. 若要支持导出，再写服务端 `ToolProvider`（`loadArchive` / `saveArchive`）。

### 新增一个模型供应商

写两个引擎并注册：

- `server/engine.ts`：`generate({ model, apiKey, signal, input })` 调 SDK；
- `client/engine.tsx`：`prompt` 组装格式、`result` 解析输出、
  `configComponent` + `configureObject` 做配置 UI。

### 新增一个世界书匹配器

```ts
export const myMatcher: Matcher = {
  id: 'mymatch',
  configComponent: ConfigUI,
  async configureObject(data, lorebook) { lorebook.expression = ...; },
  async match(ctx, lorebook) { return true / false; },
};
```

注册到 `matchers.registry`。

## 3. 代码约定

### 导出风格

- 类型、工厂、hook **直接导出**；
- 工具函数与常量集合**以对象形式导出**（`presets`、`strUtils`、`jsonUtils`、`fileUtils`）。

### 命名约定

- `name` / `plural` 成对出现：`name` 用于 entryType 与注册 id，
  `plural` 用于 `model.entries[plural]` 键名与归档目录名。
- 数据库列名 snake_case，TS 属性 camelCase。

### 格式化

Prettier，单引号、80 列，启用 import 排序与 JSON key 排序插件：

```bash
pnpm format        # ⚠️ 只作用于 src/，不含 tests/scripts/plugins
```

### 提交前必须通过

```bash
pnpm format
pnpm test run
pnpm build
```

提交信息用简短的英文祈使句（`fix lora`、`add json support for macro`），
一个提交只做一件事。**不要在功能 PR 里改版本号。**

### 易被误读的契约（读源码前先看这段）

有几处写法的正确性依赖**代码之外的前提**，只看实现很容易判成 bug。

**`jsonUtils.merge(lft, rht)` —— 左值是累加器。**
它会**原地修改 `lft`** 并返回同一个对象；`rht` 的值要么被 `structuredClone`，
要么被递归合并进 `lft`，**永远不会被改动、不会被别名**；
且 `rht` 中值为 `null` / `undefined` 的键会被**跳过**。
所以约定是：`lft` 是「初始值 / 调用方自己的对象」，`rht` 是「外部来的数据」——
这是有意的，不是疏漏。（`11-前端架构` 里对 `buildUrl` 有过同款提醒。）

**`files` 模块的一个字段存两种东西。**
`files.url(id)` 按值分流：能通过 `uuid.validate` 的 → `/api/files/{id}/resource`，
否则当外部 URL 原样返回（`ImageUploader` 会把用户填的外链**直接当 id 存库**）。
所以这个字段的值域是「GUID 或任意 URL」，校验只有「能否 `new URL()`」一层。
当前消费点（`components/media.tsx` 的 `<img>` / `<video>` 的 `src`）不会执行脚本，
但把这个 helper 复用到 `href` / `window.open` 时**必须自己加协议白名单**。

**`deserializeMimeType` / `serializeMimeType` 只保证前段 `type` 有意义。**
`args` 由 `split(';')` 拼出，`boundary="a;b"` 这种带引号内含分号的参数会被切坏、
往返不一致。这是**刻意**的：该字段只用来存取「前面的类型」，`args` 不参与语义。

## 4. 测试

```bash
pnpm test          # watch 模式
pnpm test run      # 跑一次
```

- Vitest + jsdom，`globals` 已开启；
- 用例放 `tests/<模块>/<名称>.test.ts`，自动收集 `tests/**/*.{test,spec}.{ts,tsx}`；
- `vitest.setup.ts` 已 mock `@teispace/next-themes` 与 `next/navigation`；
- 配置里 `resolve.tsconfigPaths: true` + 手动别名（`@/lib`、`@/hooks` 等）。

## 5. 安全性的取舍（重要）

`CONTRIBUTING.md` 有一节专门说明，务必先读：

> 本项目的定位是**自部署的个人应用**，部署者即管理员，不存在多租户边界。
> 预设中的脚本、样式、宏允许执行使用者自己编写的 JS 与 CSS，
> 这是产品刻意提供的核心能力，不是缺陷。

代码里一些「看起来危险」的写法属于同类取舍：

- 预设脚本注入 iframe（iframe **未设 `sandbox`**，同源）；
- `tools/scripts` 用 `new Function(...)` 执行任意 JS；
- 宏用 Eta 求值任意表达式；
- Civitai 下载用 `execSync` 拼接 curl 命令（未转义）。

> 如果你认为某处确实构成风险，**请先开 Issue 讨论**，
> 不要直接提交「移除这项能力」式的加固 PR —— 这会破坏已有用户的预设与插件。

## 6. 踩坑清单（源码阅读中确认）

> ⚠️ 本清单基线为 `1.3.2.8`。其中**若干条已在 `1.3.3.0` 修复但未就地标注**
> （第 7、13、34、36、40 条），逐条核对前先看
> [13-心得体会 §七](./13-心得体会.md) 的过期项对照表。

### 数据库与模型层

1. `realm_history` 的列名是 **`inputs`**，但 TS 属性名是 `prompts`。
2. `history.get` 按 **offset 索引**取，不是按 `sequence`，
   但 HTTP 路径参数名叫 `sequence`；`set` / `del` 用的才是真 sequence。
3. **Realm 不是表** —— 是 Story + presets + model 的运行时投影，
   `histories` 是填了 `null` 的定长数组（懒加载）。
4. `getRealm` **不加载 story 条目**，需要条目数据要另行请求。
5. `entryId` 用 `max(entry_id)+1` 分配，**删除后会复用**。

### 生成管线

6. `model.iterations` 被 `Math.max(2, ...)` 钳制，**最小 2 轮**（schema 默认 20）。
7. 非流式分支调用 `generate(true, response)`，**传了 `stream: true`** 与事实矛盾（疑似 bug）。
8. `retry` 同时承担「网络错误重试」与「流式卡死重试」，后者借道 `abort('retry')`。
9. `realm.context` **同键重复初始化会抛错** —— 插件共用 key 会直接崩。

### 预设与转换链

10. **正则的 `target` 过滤与实际挂载点不一致**：
    `init` 只挑 `input` / `both`，但同一份 cache 同时被 processer 与 renderer 使用，
    所以标 `input` 的正则也会作用于**输出渲染**。
11. 正则用 `String.prototype.replace(pattern, replacement)` 的**字符串形式**，
    没有 `new RegExp()`，也没有解析 `/.../g` 标志的逻辑。
12. 正则的 `sorter` 是 `name`，**所以正则的应用顺序由条目名称字符串决定**。
13. `Script.defaultEntry.type` 是 `'text/css'`（文档说默认应是
    `application/javascript`），疑似复制粘贴遗留。
14. 宏的 `it.variables` 用 `realms.variables(history, false)`（不含 output 增量），
    而世界书匹配器用默认 `true` —— 同一函数不同调用点语义不同。
15. `archive.get.fuzzy` 依赖**前缀匹配**，导出/导入两侧文件名前缀必须一致。
16. `preset_entry` 的 tags 索引用 `like '%tag%'`，**索引实际无效**。
17. `listWithRequires` 遇到**不存在的依赖静默跳过**，不报错。

### 世界书与记忆

18. **vector 匹配器疑似 bug**：索引写入用 `entry.name`（显示名），
    检索比对用 `lorebook.id`（`preset.id-code`），两处不一致。
19. RAG 未配置时**静默降级**（`rags.create()` 返回 null），vector 型世界书无声失效。
20. **记忆 RAG 每次生成都全量重建**：重新计算所有嵌入 + 重建 Orama 库，且不持久化。
21. 默认 builder 模式**没有真正的 token 预算裁剪**。

### 前端

22. `buildUrl` **原地修改**传入的 `params` 对象，复用会丢字段。
23. `realms` 是全局单例，**同页面只能有一个活跃 realm**。
24. iframe 的 **`key={1}` 不能删**（生产环境引用问题，开发环境复现不了）。
25. iframe **未设置 `sandbox`**，预设脚本拥有完整同源权限。
26. `useSse(type, callback)` 的 `useEffect` 依赖数组为空，**回调变化不重新订阅**。
27. 切换 realm 若不刷新 iframe 会沿用旧脚本（靠 `__injectedScriptInitialized` 守卫）。

### ComfyUI 与工具

28. **Civitai 下载用 `execSync` 拼接 curl 命令，路径与 URL 均未转义**（命令注入面）。
29. `power_lora_select` 生成时会**整体替换节点 inputs**，丢弃其他输入。
30. `configureInput` 写入的是 `name`（路径）而非 `value`（id）；未用的 `lora_i` 必须 `delete`。
31. `model_select` 默认 `type` 是 `'unet'`，但 `comfyuis.model.types` 里没有 `'unet'`。
32. 工具 provider 缺失只 `console.warn`，条目静默消失。

### 基础设施

33. **迁移会执行两次**：`pnpm prepare` 一次，Next 启动时 `instrumentation.ts` 再一次。
34. `checker.validateCode` 的正则 `/^[A-Za-z0-9_]$/` **只匹配单字符**，
    与其导出的 `checker.code`（`+` 量词）不一致。
35. `files.serializeMimeType` 在 `args` 为 null 时产出 `"<type>; null"`，**往返不闭合**。
36. `Registry.sortByRequires` 的循环依赖报错里 `remaining.join(', ')`
    对**对象数组**调用 join，会输出 `[object Object]`。
37. `response.download` 的 `Content-Type` **硬编码为 `text/event-stream`**，
    不适用于普通文件下载。
38. `SECRET_SALT` / `SECRET_KEYS` 由 `Math.random()` 生成，**非密码学安全随机源**；
    且**丢失后无法解密已存的 API Key**。
39. `task.get` 在任务完成后移出 Map，**完成的任务查不到**。
40. Registry 名 `lorebook-macher` **拼写有误**（少了 `t`）。

## 7. 调试技巧

- **看注册顺序**：`Registry` 会打 `[name] registered: id` 与排序后的 id 列表，
  在 console 里能直接看到拓扑序。
- **看 realm context**：`realms.context` 抛出未初始化错误时会打印
  `Object.keys(realm.context)`，能快速定位缺哪个插件的 init。
- **`console.debug` 的生产行为**：`next.config.ts` 的
  `compiler.removeConsole` 在生产只保留 `error/warn/info`，
  **大量调试日志只在 dev 可见**。
- **准备阶段出错**：`pnpm prepare` 里 `fileUtils.execute` 会跑
  `npx drizzle-kit generate`，schema 写错会在这里失败。
- **改了 manifest 没生效**：一定是忘了 `pnpm prepare` 或没重启。
