# 00 · 项目总览

> Secyud Tavern —— 一个高度可定制化的 AI 角色扮演与互动叙事平台。
> 版本 `1.3.2.8`，AGPL-3.0，定位是**自部署的个人应用**（部署者即管理员，不存在多租户边界）。

本目录是阅读源码后整理的学习笔记，用于快速建立对整个项目的结构性认知。
笔记按「先骨架、后血肉」的顺序组织，建议按编号顺序阅读。

---

## 1. 一句话理解这个项目

它把「AI 角色扮演」拆成了**一组可插拔的能力模块**（模型、预设、故事、记忆、ComfyUI……），
用一套统一的 `manifest.json` + `client/` + `server/` 约定把它们组装起来，
然后在 **编译期** 通过代码生成把模块焊接成注册表和 API 路由。

最核心的两个抽象是：

| 抽象 | 含义 |
| --- | --- |
| **Preset（预设）** | 一套「玩法包」。内含宏、正则、脚本、样式、世界书、工具等条目，决定交互长什么样。 |
| **Realm（领域）** | 一次具体的「游玩实例」。由 Story 映射而来，绑定模型 + 预设 + 历史，是生成流程的运行载体。 |

## 2. 技术栈

| 层面 | 选型 |
| --- | --- |
| 框架 | Next.js 16（App Router）+ React 19.2 |
| 语言 | TypeScript 7 |
| 数据库 | **libsql / SQLite**（`@libsql/client`）+ Drizzle ORM |
| 状态 | Zustand 5 |
| UI | Tailwind CSS 4 + shadcn 风格组件 + **`@base-ui/react`**（注意：不是 Radix） |
| 编辑器 | Monaco Editor（脚本、变量 JSON 编辑） |
| 模板引擎 | **Eta**（宏求值） |
| 检索 | **Orama**（向量记忆/世界书检索）+ `@huggingface/transformers`（本地 embedding） |
| 国际化 | next-intl，`zh` / `en` 两种 locale，默认 `zh` |
| 测试 | Vitest 5 + jsdom |
| 包管理 | pnpm（workspace 包含 `plugins/*`） |

> ⚠️ 关于 JSON Schema：项目**没有引入 Zod** 之类的 schema 校验库。
> 工具参数与工作流参数的 JSON Schema 全部是**手写的普通对象**，
> 类型定义在 `src/utils/json-schema.ts`（纯类型，无运行时校验）。

## 3. 目录结构

```
src/
├── app/               Next.js 外壳（layout / page / client 引导）
│   ├── api/           ⚠️ 自动生成，手改无效
│   └── [id]/page.tsx   realm 游玩页
├── <模块>/             每个目录是一个能力模块，结构统一（见下）
├── components/        通用 UI 组件（ui/ 下为 shadcn 基础件）
├── database/          数据库 provider / factory / storage 抽象
├── generated/         ⚠️ 自动生成（注册表、资源、API 路径类型）
├── interceptors/      客户端与服务端的横切关注点
├── localization/      locale 配置与 next-intl request 装配
├── plugins/           模块框架本体（Registry）——不是插件！
├── signal/            SSE 广播与流式解析工具
└── utils/             纯工具函数
scripts/               prepare 流水线与数据库迁移
plugins/               编译期插件（各自独立 Git 仓库，主仓库不跟踪）
docs/                  文档（子模块），本笔记即位于 docs/learn
tests/                 用例
data/                  本地数据库（git 忽略）
```

### 模块的统一结构

`src/` 下每个能力模块都遵循同一套骨架，这是理解本项目最关键的一点：

```
src/<模块>/
├── index.ts          类型、常量、模块元信息（导出复数形式对象，如 presets）
├── manifest.json     模块声明：{ id, client, server, requires, sequence, disabled, version }
├── client/           浏览器侧
│   ├── index.tsx     对外导出并完成注册（default export 是注册函数）
│   ├── component.tsx / content.tsx / state.ts / proxy.ts / factory.ts
│   ├── realm.ts      ⭐ 参与生成流程的 Processer / Renderer 实现
├── server/
│   ├── api.ts        接口定义 → 自动生成 Next.js 路由
│   ├── repository.ts / schema.ts / storage.ts / factory.ts
└── localization/     zh.json + en.json
```

## 4. 从启动到出图：一次完整的数据流

```
浏览器
  └─ app/client.tsx  ──调用──▶  registerClientPlugin()   （自动生成的注册表）
                                  └─ 依次执行每个模块 client/index.tsx 的 default 函数
                                       └─ 向各类 Registry 注册菜单、Tab、Processer、Renderer…

用户进入 /<storyId>
  └─ [id]/page.tsx ──▶ stories.proxy.realm.id(id)   取得 Realm
       ├─ models.processers.initialize({ realm })    ← 各模块 init，构建缓存
       └─ stories.renderers.initialize({ realm })    ← 各模块 renderer init
            └─ realms.realm = realm                  （全局单例式持有）

用户输入 → realms.generate(true)
  ├─ 拼装 prompt：models.processers.prompt()
  │    ├─ 收集 histories（从最近的 summary 段落开始）
  │    ├─ 各 Processer.prompt 依次执行：
  │    │    regexes  → 文本替换
  │    │    macros   → Eta 模板求值（依赖 regexes）
  │    │    tools    → 工具注册
  │    │    lorebooks→ 世界书匹配与分层注入（依赖 tools）
  │    └─ engine.prompt() 汇总成引擎输入
  ├─ 请求模型：models.proxy.engine.generate() → SSE 流
  ├─ engine.result() 逐块解析 → RealmOutput
  └─ 循环（工具调用最多 iterations 轮，默认 20，最小 2）
       └─ stories.renderers.stream() → 把内容 postMessage 进 iframe 渲染
```

最终呈现的交互界面，是**预设里的脚本在 iframe 中自己画的**——
没有预设时是一片空白，这正是「高度可定制化」的由来。

## 5. 关键设计决策（读源码时最容易困惑的点）

1. **编译期插件，而非运行时插件。**
   所有模块在 `pnpm prepare` 时被扫描 `manifest.json`，生成静态 import 的注册表。
   好处是保留原生 Next.js 的开发调试体验；代价是**改动 manifest 必须重新 prepare 并重启**。

2. **约定优于配置的 API。**
   你只在模块的 `server/api.ts` 里写一个嵌套对象，`scripts/operations/api.ts` 会递归找出
   `GET/POST/PUT/DELETE` 键，生成真实的 `route.ts`，并同步生成前端可用的路径联合类型
   （`src/generated/api-path.ts`），让 `get('presets/{id}')` 这样的调用获得类型检查。

3. **模块之间靠 Registry 解耦，靠 `requires` 定序。**
   `Registry#sorted()` 用 Kahn 算法做拓扑排序，`sequence` 作为同层级的次序。
   `requires` 引用了不存在的模块会**直接抛错**，循环依赖也会抛错。

4. **iframe 作为渲染沙箱。**
   预设脚本/样式执行在 iframe 里，通过 `postMessage` 与主应用通信
   （`realms.message.post`）。预设脚本可以自行注册 `userInput.inputBuilders` 来改写用户输入。

5. **变量系统用 JSON Patch。**
   每条消息都带 `variables: Operation[]`，通过 `@/utils/json-patch` 的 `patch()`
   在历史基线上顺序回放，得到当前变量快照。

6. **明确的取舍：允许执行用户脚本。**
   预设中的脚本、样式、宏允许执行使用者自己编写的 JS 与 CSS，这是**刻意提供的核心能力**。
   `CONTRIBUTING.md` 明确说明：不要提「移除这项能力」式的加固 PR。
