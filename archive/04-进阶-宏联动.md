# 进阶：宏驱动的开关与计算

> 前置：[01-存档结构](./01-存档结构.md)、[02-手写存档指南](./02-手写存档指南.md)。
> 本篇讲的是**只用存档文件**（不加插件、不改代码）就能做到的四类玩法：
>
> 1. **宏 ↔ 工具联动**：勾一个宏，工具从"模型可用列表"里出现/消失，说明书同时进出提示词
> 2. **宏 ↔ 世界书联动**：勾一个宏，整条常驻规则出现/消失
> 3. **总开关 + 分项**（"总分控制"的结构读法）：一个总闸管住一整块内容
> 4. **数值计算与迭代**（"总分/迭代"的计算读法）：用 Eta 在注入文本里求和、分支、循环，随回合推进
>
> 全部机制都已对照源码核对，末尾有可直接导入的完整示例。

---

## 0. 地基：`checkItems[code]` 是什么

一个**故事级**的小状态表，存在 `realm.properties` 里：

```ts
// src/presets/macros/client/index.tsx
interface MacroProperty {
  checkItems: Record<string, boolean>; // code → 是否被禁用
  selections: Record<string, string | undefined>; // 单选组 key → 选中的 code
}
```

只有 **`multiple: true`（复选宏）** 的 `code` 会进 `checkItems`；单选宏走 `selections`，**不写** `checkItems`
（这是"单选宏不能当开关"的根因）。

有且只有三处读写它：

| 谁 | 位置 | 行为 |
| --- | --- | --- |
| 宏面板（勾选框） | `src/presets/macros/client/feature.tsx` | 勾上 → `entry.disabled = !checked` → `checkItems[code] = false` |
| 工具面板（勾选框） | `src/tools/client/feature.tsx` | 开关 → `checkItems[macro]`（绑了 `macro` 时） |
| 世界书 `fixed()` | `src/presets/lorebooks/client/builder.ts` | `!checkItems[macro]` 才注入 |

三处共享同一份数据，所以**宏面板和工具面板是同一批开关的两个视图**：在工具面板里关掉，
等于在宏面板里取消勾选，反之亦然；状态在关闭面板时写回 `realm.properties`（跟着故事走）。

> 硬约束：`checkItems` 的键是宏的 **`code`**，`true` 表示**禁用**（注意这是取反的）。
> 没被任何人勾选过的宏，用条目自己的 `disabled` 当初始值。

## 1. 配方 A：宏 ↔ 工具联动（最有用的一条）

### 1.1 三件套

```text
① 宏（开关 + 说明书）        code = roll_dice, key = tools, multiple = true
② 工具（绑开关）             type = script, macro = roll_dice, config.code = roll
③ 常驻世界书（注入说明书）    always, role = system, 正文里写 <%~ it.tools %>
```

**① 宏** `macros/tool-roll_dice.meta.json`

```json
{
  "name": "骰子工具",
  "code": "roll_dice",
  "key": "tools",
  "value": "- `roll`: 需要随机数时调用，参数 min/max。",
  "json": false,
  "multiple": true,
  "hidden": false,
  "disabled": false
}
```

**② 工具** `tools/roll.meta.json`

```json
{
  "name": "骰子",
  "type": "script",
  "disabled": false,
  "macro": "roll_dice",
  "config": {
    "code": "roll",
    "description": "返回 [min, max] 之间的随机整数",
    "schema": "$file$roll.schema.json",
    "script": "$file$roll.script.js"
  }
}
```

**③ 世界书** `lorebooks/rules.meta.json`

```json
{
  "name": "工具说明",
  "code": "tool_docs",
  "type": "markdown",
  "match": "always",
  "expression": { "last": false },
  "content": "# tools\n\n<%~ it.tools %>\n",
  "priority": 100,
  "layer": 80,
  "role": "system",
  "disabled": false
}
```

### 1.2 为什么这样就能"一念生死"

- 宏启用时，它的 `value` 会被拼进 `it.tools`（`key: "tools"` 那一组），③ 把它注入系统提示；
- 宏被取消勾选时：`it.tools` 里没有这段文字（**说明书消失**），并且工具的 `disabled` 变成 true
  → `tools.actives()` 过滤掉它（**模型看不到这个函数**）；
- 反过来，在**工具面板**里关掉它，等于把同一个 `checkItems.roll_dice` 置 true，
  宏面板里的勾也会跟着掉——两处 UI 是同一个开关。

收益是三份开销一起省：函数定义（schema）、调用机会、说明书 token。

### 1.3 这就是内置模板的写法

`docs/templates/root/默认设置/` 就是这个结构：

| 宏 `code` / `key` | 绑定的工具 | 说明 |
| --- | --- | --- |
| `variable` / `tools` | 变量工具（`macro: "variable"`） | 说明书是 `get_variable`/`set_variable`/`del_variable`/`set_temp` 四条 |
| `lorebook` / `tools` | 世界书工具（`macro: "lorebook"`） | |
| `memory` / `tools` | 记忆工具（`macro: "memory"`） | |
| `ask_user` / `tools` | 提问用户：**`macro: "elicit"`（对不上）** | 反例，见 §5.2 |

`lorebooks/rules.content.md` 里那句 `<%~ it.tools %>` 就是把上面四段说明合集注入系统提示的地方。

### 1.4 关键点

- **`macro` 要填宏的 `code`，不是工具名**；工具的暴露名是 `config.code`，两者可以不同名
  （模板里 `name: "随机数"` / `config.code: "roll"` / `macro: "roll_dice"` 三套名字互不相干）。
- 一个宏 `code` 可以被**多个**工具同时绑定 → 它们联动同进同退。
  想"一个总闸控制一组工具"，就给他们填同一个 `macro`。
- 宏的 `value` 是说明书正文；**只要开关不要说明书**就写 `""`
  （空串同样会拼进 `it.tools`，但什么也不加）。
- 工具没绑 `macro` 时用 `items[toolName]`（工具面板里的独立开关），与宏无关。

## 2. 配方 B：宏 ↔ 世界书联动

世界书条目加一个 `expression.macro`：

```json
{
  "name": "战斗规则",
  "code": "battle_rules",
  "type": "markdown",
  "match": "always",
  "expression": { "last": false, "macro": "battle_on" },
  "content": "$file$battle.md",
  "priority": 100,
  "layer": 80,
  "role": "system",
  "disabled": false
}
```

- 宏 `battle_on` 启用 → 这条世界书每轮注入；取消勾选 → **整条消失**（不是内容变空）。
- 适用于"大段常驻规则/表格/口吻设定"的分组开关：关一块就真的不占 token、也不干扰模型。

**只有 `match: "always"` 支持 `macro`。** `normal` / `event` / `variable` / `vector` 的 `expression` 里写 `macro`
不会被读（`fixed()` 只处理 always 的 `before`/`after` 队列），写了等于没写。

> 和 §1 配合：**同一个 `code`** 可以既绑世界书、又绑工具、又是宏面板里的勾选框，
> 于是一个勾同时控制"规则注入 + 工具暴露 + 说明书文本"三件事——这就是这套机制最舒服的用法。

## 3. 配方 C：总开关 + 分项（"总—分"结构）

想做"一键关闭整个玩法模块，但保留其中细项"，用**两条层级**：

```text
总开关宏   battle_on    (multiple, value = "")
├─ 容器世界书  expression.macro = "battle_on",  正文 = <%~ it.battle_parts %>
└─ 分项宏组     key = battle_parts（多条 multiple 宏，各自一段文本）
```

- 勾着总开关：分项里**已勾选**的文本依次拼进 `it.battle_parts` → 注入；
- 关掉总开关：容器世界书整条不注入 → 分项文字一个都不出现（哪怕分项还勾着）；
- 只关某个分项：容器还在，只是少了那一段。

总开关宏：

```json
{ "name": "战斗模块", "code": "battle_on", "key": "_switch", "value": "",
  "json": false, "multiple": true, "hidden": false }
```

分项宏（`key` 相同、`code` 各不相同）：

```json
{ "name": "战斗：回合制", "code": "battle_turn", "key": "battle_parts",
  "value": "每回合只推进一个动作。", "json": false, "multiple": true, "hidden": false }
```

```json
{ "name": "战斗：伤害表", "code": "battle_damage", "key": "battle_parts",
  "value": "伤害 = 攻击 - 防御，最低 1。", "json": false, "multiple": true, "hidden": false }
```

**局限（务必知道）**：总开关只拦"注入文本"，**不拦工具**。
工具绑的是分项 `code`，所以"总关掉、工具还在"是正常现象。
推荐分工：**文本用总开关，工具用分项开关**；若希望工具也跟着总闸走，就把工具的 `macro` 直接填总开关的 `code`
（代价是分项管不住工具）。

## 4. 配方 D：数值计算 —— 求和与阈值（"总分"的计算读法）

宏本身只是字符串容器，但注入文本会经过 **Eta** 求值，而 Eta 里能拿到：

| 数据 | 含义 |
| --- | --- |
| `it.<宏key>` | 该 `key` 组拼好的文本（`json: true` 的宏是合并后的对象） |
| `it.variables` | 当前回合的变量快照 |
| `it.space` | 当前输出的空间属性 —— **世界书里恒为 `{}`**（builder 传入 `history: null`），别用 |
| `it.<参数名>` | 子 agent 调用参数（**摊平在顶层**，没有 `it.args`） |

所以"总分"完全可以在一条常驻世界书里算：

```markdown
<%
const a = it.variables.attrs ?? {};
const total = (a.str ?? 0) + (a.dex ?? 0) + (a.con ?? 0) + (a.int ?? 0);
%>
当前六维总分：<%~ total %>。
<% if (total >= 250) { %>这个角色强得离谱，描写时给出压迫感。<% } %>
```

要点：

- `<% %>` 是代码块，`<%~ %>` 原样输出，`<%= %>` 会做 HTML 转义（写提示词一律用 `~`）。
- 变量来自故事当前回合；用**变量工具**（`set_variable`）更新后，**下一轮**这里就是新值。
- 数值请自己兜底 `?? 0`：Eta 拿到 `undefined` 会算成 `NaN`，输出 `NaN` 不会报错。
- 代码块会把自己的换行留在输出里（上面就会在开头多一个空行）。想干净一点用 trim 标记：
  `<%_ … _%>` 会吃掉标签两侧的空白/换行（实测：`"<%_\nconst a=1\n_%>\nX"` → `"X"`）。

### 4.1 用 json 宏积累"选项分值"

`json: true` + 相同 `key` 的多条宏会被**深度合并**成 `it.<key>`（这就是"勾选即累积"的结构）。
装备 A（`macros/gear-sword.meta.json`）：

```json
{ "name": "装备：短剑", "code": "gear_sword", "key": "gear",
  "value": "{\"sword\":{\"atk\":5}}",
  "json": true, "multiple": true, "hidden": false }
```

装备 B（`macros/gear-shield.meta.json`）：

```json
{ "name": "装备：圆盾", "code": "gear_shield", "key": "gear",
  "value": "{\"shield\":{\"def\":3}}",
  "json": true, "multiple": true, "hidden": false }
```

然后：

```markdown
<%
const parts = Object.entries(it.gear ?? {})
  .filter(([, v]) => v && typeof v === 'object');
const atk = parts.reduce((s, [, v]) => s + (v.atk ?? 0), 0);
const def = parts.reduce((s, [, v]) => s + (v.def ?? 0), 0);
%>
玩家装备：<%~ parts.map(([k]) => k).join('、') %>；攻击 <%~ atk %>，防御 <%~ def %>。
```

> ⚠️ **合并出来的 `it.gear` 自带一个 `toString` 方法**（源码里为了让对象能当字符串插值：
> `{ ...json, toString() { return 文本 } }`）。它是**自有可枚举属性**，
> 所以 `Object.keys(it.gear)` 会变成 `["sword", "toString"]`：
>
> - 直接 `parts.map(([k]) => k).join('、')` 会多列出一个 `toString`；
> - 求和时若不兜底（写 `s + v.atk` 而不是 `s + (v.atk ?? 0)`）会算出 `NaN`。
>
> 上面统一先 `typeof v === 'object'` 过滤一层，两个坑一起躲掉。

## 5. 配方 E：迭代

### 5.1 渲染迭代（列表/表格）

注入文本里直接循环变量：

```markdown
背包：
<%~ (it.variables.items ?? []).map((i) => `- ${i.name}（${i.n ?? 1}）`).join('\n') %>
```

配合 §4 的求和，就能做"状态栏"式的常驻块：**每次变量变化，这段文字自动重算**。

### 5.2 跨回合迭代（每轮重新求值）

`macros` 的 `apply` 在**每次生成**时重建，所以注入文本每轮都会用**当轮变量**重新渲染。
只要变量在推进，文本就会"迭代"：

```markdown
<% const log = it.variables.log ?? []; %>
<% if (log.length) { %>最近发生：<%~ log.slice(-3).join('；') %>。<% } %>
```

`log` 由模型通过 `set_variable`（JSON Patch 追加）维护，或者直接在故事的**消息编辑面板**里手改变量
（那里有一个每回合的 `variables` JSON 编辑器）——这是能"每轮写一次"的两条通道。
想让数字自己递增，就在提示词里明确要求：**每回合调用 `set_variable` 把 `/turn` 加 1**，
再用 `it.variables.turn` 做索引：

```markdown
<%~ (it.variables.scripts ?? [])[ (it.variables.turn ?? 0) % 3 ] %>
```

（模型不一定会老实计数，重要逻辑尽量用"已存在的数据"当索引，比如日期、地点、好感度档位。）

### 5.3 叠层迭代（多条宏拼接）

同一 `key` 下所有**已勾选**的 multiple 宏会依次拼接成 `it.<key>`——勾一个多一段，天然是"叠加"。

> ⚠️ **拼接顺序不保证**：宏的 `sorter` 是 `${key}${+multiple}${+hidden}`，同组宏完全相同，
> 数据库排序退化成行顺序。需要固定顺序时，别靠多条宏，改成**一条宏 + 5.1 的循环**。

### 5.4 模板复用（子 agent 参数）

给 `agent` 型工具挂同一套世界书时，世界书里的 `it.<参数名>` 就是本次调用的参数（摊平、无 `it.args`）。
一份模板可以被不同参数反复"迭代"调用，例如：

```markdown
请以 <%~ character %> 的视角，只输出一段内心独白。
```

## 6. 排错清单

| 现象 | 原因 |
| --- | --- |
| 勾选没反应、世界书永远在 | 绑定的是**单选宏**（`multiple: false`）——单选宏不写 `checkItems`，`fixed()` 永远读到 `undefined` |
| 工具开关点了没用 | `tool.macro` 的 `code` 没有任何宏提供（模板里 `提问用户` 就是：`macro: "elicit"`，而宏 `code` 是 `ask_user`） |
| 世界书 `expression.macro` 不生效 | 该条目不是 `match: "always"` |
| 系统提示里出现字面量 `undefined` | 模板引用了不存在的 `key`；**先确认那条宏被勾上**（未勾选时 `it.<key>` 是 `""` 而不是 `undefined`，`undefined` 一般意味着 key 拼错） |
| 关掉宏后工具仍在 | 工具没绑 `macro`（此时工具面板里那个开关写的是 `items[工具名]`，是另一套状态） |
| 总分算成 `NaN` | 变量缺字段（用 `?? 0` 兜底），或把合并对象的 `toString` 也 reduce 进去了（见 §4.1） |
| 世界书里 `it.space` 永远是空 | builder 传的是 `history: null`，世界书注入时拿不到 space，改用 `it.variables` |
| 同一段说明注入了两遍 | 两道世界书都在 `<%~ it.tools %>`，或同一 `key` 被两个容器世界书引用 |

其它注意：

- 宏的 `key` 用 `[A-Za-z0-9_]`，并且**别用纯数字开头**（`it.123` 不是合法属性访问，要用 `it['123']`）。
- `hidden: true` 只是把这条从宏面板里藏起来，值照样参与拼接；整组都 hidden 时连组都不显示。
- 勾选状态存在**故事**的 `realm.properties` 里，换故事就是默认值（条目的 `disabled`）。

## 7. 完整示例：一个"战斗模块"预设

```

├── meta.json
├── lorebooks/
│   ├── tool_docs.meta.json      + tool_docs.md      容器：<%~ it.tools %>
│   ├── battle_rules.meta.json   + battle_rules.md   expression.macro = "battle_on"
│   └── status.meta.json         + status.md         总分 + 循环
├── macros/
│   ├── switch-battle.meta.json  code battle_on      key _switch
```

三份正文：

`lorebooks/tool_docs.md`

```markdown
# tools

<%~ it.tools %>
```

`lorebooks/battle_rules.md`

```markdown
<%~ it.battle_parts %>
```

`lorebooks/status.md`（总分 + 循环，演示 §4/§5）

```markdown

const a = it.variables.attrs ?? {};

const sum = (it.variables.nums ?? []).reduce((s, n) => s + n, 0);
%>
```
