# 手写存档指南（文件编辑方式）

> 只想做出**第一个**预设？去 [00-快速上手](./00-快速上手.md)（10 分钟，每步都有验收点）。
> 本篇是**完整版**：多预设集合、实例化校验、打包坑、结构层/语义层两级排错。

> 目标：不打开应用的编辑界面，只用编辑器 + 一条打包命令，做出一个能被"预设 → 导入"直接吃下的 zip。
> 结构细节见 [01-存档结构](./01-存档结构.md)；只想复制骨架见 [03-JSON-骨架速查](./03-JSON-骨架速查.md)。

本文的打包命令与目录形态都在**中文 Windows + PowerShell 5.1** 上实测过；
"能不能被导入"那部分是按源码（`zipToArchive` + `storage.save`）逐条复刻校验的，
界面上的操作步骤则是照源码描述的。

> 规则按 `optimize cover image` 之后的那版：`cover` / `opening` / `variables` 都是
> **"meta 引用式"**（写字段、指文件），不再靠文件名约定。旧存档的迁移方法见
> [01-存档结构](./01-存档结构.md) 的 §11「规则变更记录」。

---

## 0. 先决定要做什么

| 形态 | 目录形态 | 说明 |
| --- | --- | --- |
| 单个预设 | `root/<预设>/` | 最小可用 |
| **预设集合** | `root/<预设A>/`、`root/<预设B>/`… | 一次导入多个，界面里可以勾选 |
| 带依赖的集合 | 集合 + `meta.requires` 指向集合内其它预设 | 导出时按依赖闭包打包；**导入时要一起勾上**，否则依赖悬空 |
| 带工作区 | 集合 + `root/model/`、`root/comfyui/` | 只有 `agent` / `comfyui` 工具会引用它们 |

建议先做"两个预设的小集合"：`demo_core`（提供世界书/宏/正则/脚本/样式/工具）+ `demo_story`（依赖 core，只写故事内容）。
下面的示例就是它，§10 有全部文件内容。

## 1. 搭目录骨架

在任意位置建一个工作目录（**这个名字随便，不会进 zip**），里面只放一个 `root`：

```
demo/
└── root/
    ├── demo_core/
    │   ├── meta.json
    │   ├── variables.json
    │   ├── opening.txt
    │   ├── lorebooks/
    │   ├── macros/
    │   ├── regexes/
    │   ├── scripts/
    │   ├── styles/
    │   └── tools/
    └── demo_story/
        ├── meta.json
        └── lorebooks/
```

PowerShell 一条命令建好骨架：

```powershell
$root = 'D:\demo\root'
'demo_core\lorebooks','demo_core\macros','demo_core\regexes','demo_core\scripts','demo_core\styles','demo_core\tools','demo_story\lorebooks' |
  ForEach-Object { New-Item -ItemType Directory -Path (Join-Path $root $_) -Force | Out-Null }
```

命名规则（照抄即可）：

- 预设目录名：随便，但**推荐直接用预设 id**（和导出保持一致，方便对照）。
- 六个条目目录名：**必须**是 `lorebooks` / `macros` / `regexes` / `scripts` / `styles` / `tools`，少一个字母都不行。
- 文件名：**一律 ASCII**（`a-z A-Z 0-9 . _ -`）。原因见 §6.3，中文只写在文件内容里。
- `variables.json` / `opening.txt` / `cover.png` 只是**内容文件**，必须在 `meta.json` 里被引用才生效
  （见 §2、§3），光把文件扔进目录是没用的。

## 2. 写 `meta.json`

`root/demo_core/meta.json`：

```json
{
  "id": "demo_core",
  "name": "示例核心",
  "version": "1.0.0",
  "description": "最小可用的核心预设",
  "tags": ["setting"],
  "requires": [],
  "properties": {},
  "cover": "cover.png",
  "variables": "$file$variables.json",
  "opening": "$file$opening.txt"
}
```

- `id` 是主键：**全库唯一**、非空；建议 `[a-z0-9_]+`。重复导入相同 `id` = 覆盖。
- `name` 非空。
- 基础字段全可省（`version` 默认 `1.0.0`，`tags`/`requires` 默认 `[]`，`properties` 默认 `{}`）。
- **`opening` / `variables` 就写在这里**，值可以是 `"$file$文件名"`（外置）或直接内联文本；
  **只把文件放进目录、meta 里不引用，导入时会当它不存在**。
- **`cover` 写图片的包内文件名**（`cover.png`），不是 uuid；没有封面就整条省略。
- `coverType` 已经废弃，不要写。

最小可用版本（真的只需要两行）：

```json
{ "id": "demo_core", "name": "示例核心" }
```

## 3. 初始化变量与开场白

两者都是 **meta 字段 + 可选的内容文件**，字段是必需的、文件是可选的（也可以内联）。

### 3.1 `variables`

`root/demo_core/meta.json` 里：

```json
{ "variables": "$file$variables.json" }
```

`root/demo_core/variables.json`（**名字随你，与 `$file$` 一致即可**）：

```json
{
  "hp": 100,
  "day": 1,
  "related_dates": []
}
```

- 内容必须是合法 JSON 对象；写坏了不会报错，只会被当成 `null`。
- 想内联就直接写字符串：`"variables": "{\"hp\":100,\"day\":1}"`（引号要转义，长内容不建议）。
- 多预设叠加时按顺序深度合并：对象递归合并、数组整体替换、`null` 跳过。后加载的预设优先级更高。

### 3.2 `opening`

`root/demo_core/meta.json` 里：

```json
{ "opening": "$file$opening.txt" }
```

`root/demo_core/opening.txt`：

```
你在荒岛的浅滩上醒来，潮水正在退去。
```

- 文件名任意（`opening.txt` / `intro.md` / `开场.txt`——但中文名会踩 §6.3 的坑），旧版"必须以 `opening.` 开头"的要求已取消。
- 也可以内联：`"opening": "你在荒岛的浅滩上醒来……"`。
- 多个预设的开场白会用换行拼成同一条开场消息。

## 4. 写六种条目

规则先记住三条：

1. 每个条目 = `<plural>/` 目录下一个 `*.meta.json`；**文件名随便**（推荐 `<code>.meta.json`）。
2. 大段文本两种写法：**内联**（直接写在 JSON 里）或**外置**（`"$file$文件名"`，文件放在与 meta 同级）。
3. `code` 决定运行时去重，同一预设内要唯一。

> 只有 `lorebooks.content`、`macros.value`、`scripts.content`、`styles.content`、
> `tools.config.{description,schema,script}` 这几个字段会被 `$file$` 解析；
> `regexes` 是纯内联，写 `$file$` 也没用。

### 4.1 世界书（最常用）

`root/demo_core/lorebooks/rules.meta.json`：

```json
{
  "name": "基础规则",
  "code": "rules",
  "type": "markdown",
  "match": "always",
  "expression": { "last": false },
  "content": "$file$rules.md",
  "priority": 100,
  "layer": 99,
  "role": "system",
  "disabled": false
}
```

`root/demo_core/lorebooks/rules.md`：

```markdown
你是一个荒岛求生故事的叙述者。

- 每次回复都要推进至少一个事件。
- 不要替玩家做决定。
```

要点：

- `type`：`plaintext` / `markdown` / `json` / `yaml` / `xml`（只影响导出扩展名与 json 的压缩，不影响读取）。
- `role`：`system` 系统提示、`user`、`assistant`、`knowledge`（以工具结果形式注入，最省"存在感"）。
- `layer`：`< 100` 插在当前消息**前**，`>= 100` 插在**后**；默认 100。
- `priority`：同一 layer 内的排序（`layer*10000 + priority`）。
- `match` 与 `expression`：

  | match | expression | 何时注入 |
  | --- | --- | --- |
  | `always` | `{"last": false}`，可加 `"macro": "开关宏code"` | 恒定 |
  | `normal` | `{"keywords":[["词1","词2"]],"keywordsLength":1,"fitCount":1}` | 每组任一关键词命中算 1 组，命中组数 ≥ fitCount |
  | `event` | `normal` 字段 + `minDate`/`maxDate`（`{year,month,day}`） | 变量 `related_dates` 落在区间且关键词命中 |
  | `variable` | `{"path":"hp","value":"100"}` | 变量路径取值字符串相等于 value |
  | `vector` | `{"keywords":"可选关键词"}` | RAG 检索命中 |

- 想按目录分类整理条目？**可以嵌套子目录**，例如 `lorebooks/region/keeper.meta.json`（`$file$` 指向的
  内容文件要和该 meta 放在**同一个目录**里）。`docs/templates/root/终末/lorebooks/` 就是多级嵌套的真实例子。

### 4.2 宏

`root/demo_core/macros/tone.meta.json`（内联写法）：

```json
{
  "name": "文风：克制",
  "code": "tone_plain",
  "key": "tone",
  "value": "含蓄克制，多用短句，不写心理描写。",
  "json": false,
  "multiple": false,
  "hidden": false,
  "disabled": false
}
```

- `key` 是模板里的变量名：其它条目（世界书、正则替换、脚本内容……）里写 `<%~ it.tone %>` 就会被替换
  （Eta 的数据名固定为 `it`）。
- `multiple:false` = 同 `key` 下的单选组（只生效一个 `code`）；`multiple:true` = 复选组（全部拼接）。
- `json:true` 时 `value` 会被 JSON 解析，可以用 `<%~ it.tone.某字段 %>`。
- 引用一个没人提供的 `key` 不会报错，只会原样输出字面量 `undefined`——拼预设时容易在这里翻车。
- 大段文本改成外置：`"value": "$file$tone.md"` + 同目录 `tone.md`。

### 4.3 正则（纯内联，没有内容文件）

`root/demo_core/regexes/bracket.meta.json`：

```json
{
  "name": "去掉书名号",
  "pattern": "《",
  "replacement": "「",
  "target": "output",
  "disabled": false
}
```

- `target`：`input`（送模型前）/ `output`（渲染前）/ `both`。
- `pattern` 是**字符串**，不是 `/.../g`：只替换第一个匹配，没有 flags。
- 执行顺序由条目的 `name` 排序决定（不是你在列表里看到的位置）。
- 正则**不去重**，多个预设的同名模式会重复执行。

### 4.4 脚本

`root/demo_core/scripts/panel.meta.json`：

```json
{
  "name": "面板",
  "code": "panel",
  "content": "$file$panel.js",
  "priority": 100,
  "type": "module",
  "disabled": false
}
```

`root/demo_core/scripts/panel.js`：

```javascript
// 注入到互动页面的 iframe 里，只执行一次
const root = document.createElement('div');
root.id = 'demo-panel';
root.textContent = '示例面板';
document.body.appendChild(root);

window.addEventListener('message', (event) => {
  const data = window.__messageData?.[event.data?.type];
  console.log('[demo-panel]', event.data, data);
});
```

- `type`：`application/javascript`（默认，内联）/ `module`（内联 ES module）/ `link`（`content` 当 URL，插 `<script src>`）/ `importmap`（多条目合并成一张表）。
- 按 `priority` 升序注入，按 `code` 去重（DOM id = `sct-<code>`）。

### 4.5 样式

`root/demo_core/styles/panel.meta.json`：

```json
{
  "name": "面板样式",
  "code": "panel",
  "content": "$file$panel.css",
  "priority": 100,
  "type": "text/css",
  "disabled": false
}
```

`root/demo_core/styles/panel.css`：

```css
#demo-panel {
  position: fixed;
  right: 12px;
  bottom: 12px;
  padding: 8px 12px;
  border-radius: 8px;
  background: #000c;
  color: #fff;
  font-size: 12px;
  z-index: 9999;
}
```

- 与脚本同构：`text/css` 内联，`link` 时 `content` 当 URL。按 `code` 去重（`stl-<code>`）、`priority` 升序。

### 4.6 工具（以最常用的 `script` 型为例）

`root/demo_core/tools/random.meta.json`：

```json
{
  "name": "随机数",
  "type": "script",
  "disabled": false,
  "config": {
    "code": "roll",
    "description": "返回 [min, max] 之间的随机整数",
    "schema": "$file$random.schema.json",
    "script": "$file$random.script.js",
    "enableDoc": false,
    "enableVariable": false
  }
}
```

`root/demo_core/tools/random.schema.json`：

```json
{
  "type": "object",
  "properties": {
    "min": { "type": "number", "default": 1 },
    "max": { "type": "number", "default": 6 }
  },
  "required": ["min", "max"],
  "additionalProperties": false
}
```

`root/demo_core/tools/random.script.js`（**是函数体，要自己 return**）：

```javascript
const min = Math.ceil(input.min);
const max = Math.floor(input.max);
return Math.floor(Math.random() * (max - min + 1)) + min;
```

要点：

- **`config.code` 才是暴露给模型的名字**，条目的 `name` 只是界面显示名。重名工具后者覆盖前者。
- `type` 必须是已注册的 provider：`variable` / `lorebook` / `memory` / `elicit` / `fetcher` / `mcp` / `script` / `agent` / `comfyui`。
  **写错会导致整个导入失败**（不是跳过）。
- 无配置的工具（`variable` / `lorebook` / `memory` / `elicit`）只需要 `{"name":"...","type":"variable"}`；
  模板里常带 `"macro": "variable"` 用来把工具开关绑到同名宏上。

## 5. 第二个预设：形成"集合"，并建立依赖

`root/demo_story/meta.json`（顺便演示 `variables` 用**自定义文件名**、`opening` 用**内联**）：

```json
{
  "id": "demo_story",
  "name": "示例故事",
  "version": "1.0.0",
  "tags": ["story"],
  "requires": [{ "name": "示例核心-1.0.0", "value": "demo_core" }],
  "variables": "$file$vars.json",
  "opening": "潮水退了，你在沙地上看见一行脚印。"
}
```

`root/demo_story/vars.json`：

```json
{
  "day": 2,
  "hp": 100
}
```

`root/demo_story/lorebooks/world.meta.json`（内联内容，不需要额外文件）：

```json
{
  "name": "世界背景",
  "code": "world",
  "type": "plaintext",
  "match": "always",
  "expression": { "last": false },
  "content": "这是一座无人的荒岛，只有潮声与椰林。",
  "priority": 100,
  "layer": 100,
  "role": "knowledge",
  "disabled": false
}
```

关于集合与依赖：

- 一个 zip 里放多少个预设目录都行，导入界面会列出来让你勾选。
- `requires[].value` 必须是被依赖预设的 **`id`**，不是目录名；`name` 只用于显示（约定 `名称-版本`）。
- 运行时依赖会被展开：**依赖排在前面**，使用者在后面（`presets.repository.traversal` BFS 后反转）。
- ⚠️ **导入不会自动补依赖**：如果只勾 `demo_story`，`demo_core` 不会跟着进来，故事里就会缺内容。全勾上即可。
- 想让两个预设"共享"同一个条目，就把它写在被依赖的预设里，别在两个预设里各写一份（各写会触发各自的去重规则，见 01 文档 §6）。

## 6. 打包成 zip

### 6.1 推荐命令（实测可用）

在 `root` 的**父目录**执行：

```powershell
cd D:\demo
tar -a -c -f demo.zip root
```

- 生成的条目全部是 `root/...`（正斜杠），正是导入端要的形态。
- 用压缩包名任意，`demo.zip` / `存档.zip` 都行（应用按内容识别，不看文件名）。
- 这条命令和应用自带模板的构建脚本一致：`docs/templates/build.bat` 就是 `tar -a -c -f "default.zip" "root"`。

打包后**一定要检查条目名**：

```powershell
tar -tf demo.zip | Select-Object -First 10
```

期望看到 `root/demo_core/meta.json` 这样的路径。
若看到 `root\demo_core\meta.json`（反斜杠）或 `demo/root/...`（多一层），说明打错了，导入会是**空列表**且不报错。

### 6.2 不要用这两种方式（实测会把包打坏）

| 方式 | 结果 |
| --- | --- |
| `Compress-Archive -Path .\root -DestinationPath demo.zip` | 条目名用 `\` 分隔 → 导入端按 `/` 切分，**全部丢弃**，导入列表为空 |
| `[IO.Compression.ZipFile]::CreateFromDirectory('.\root','demo.zip')` | 一是同样 `\` 分隔，二是把 `root` 这一层**吃掉**，条目直接从 `demo_core/...` 开始 → 同样全部丢弃 |

资源管理器右键"发送到 → 压缩(zipped)文件夹"用的是正斜杠，形态是对的，
但名字编码和 `tar` 一样取决于系统代码页，所以**只适用于 ASCII 文件名**。

### 6.3 中文文件名：唯一的硬限制

读取端（`jszip`）一律用 UTF-8 解码 zip 里的文件名。而中文 Windows 上，
`tar`、资源管理器压缩实际写进去的是本地代码页（GBK）字节，于是：

- 中文**目录名**乱了 → 无所谓（导入不看目录名）；
- 中文**条目文件名**乱了 → 无所谓（只按 `*.meta.json` 后缀扫）；
- 中文**内容文件名**乱了 → `$file$中文名.md` 命中不到，**内容静默变空**。

仓库自带的 `docs/templates/default.zip` 就有这个毛病（`$file$抽奖-0.schema.json` 这类引用会落空）。

**结论：文件名、目录名全用 ASCII。** 中文写在文件内容里完全没问题（内容是 UTF-8 字节）。

如果确实需要中文文件名，用 Node + 本仓库已有的 `jszip` 重新打包（写入端会给非 ASCII 名字打 UTF-8 标记）：

```powershell
cd D:\Projects\secyud-tavern\main
@'
const fs = require('fs'), path = require('path'), JSZip = require('jszip');
const src = 'D:/demo/root', out = 'D:/demo/demo.zip';
const zip = new JSZip();
(function walk(dir, prefix) {
  for (const e of fs.readdirSync(dir, { withFileTypes: true })) {
    const abs = path.join(dir, e.name);
    const rel = prefix ? prefix + '/' + e.name : e.name;
    if (e.isDirectory()) walk(abs, rel);
    else zip.file(rel, fs.readFileSync(abs));
  }
})(src, 'root');
zip.generateAsync({ type: 'nodebuffer', compression: 'DEFLATE', compressionOptions: { level: 6 } })
  .then((b) => fs.writeFileSync(out, b))
  .then(() => console.log('done:', out));
'@ | Out-File -Encoding utf8 pack.cjs
node pack.cjs
Remove-Item pack.cjs
```

## 7. 导入

### 7.1 界面

预设（左栏预设列表）→ 右上 **导入** 按钮 → 选 zip → 弹出待导入预设清单（默认全勾）→ 确认。

- 想保留旧数据就先别勾同 id 的；勾了就是**覆盖**（同 id 先删后建）。
- 导入完成后会选中"这次最后创建"的那个预设（应用导出的包里通常就是最上层那个，因为导出按依赖在前排序）。

### 7.2 接口（适合脚本化/无界面校验）

```powershell
# 1) 解析：返回 [{ name, value }]，value 是预设 id
$sid = [guid]::NewGuid().ToString()
curl.exe -s -F "file=@D:\demo\demo.zip" "http://127.0.0.1:12804/api/presets/import?sessionId=$sid"

# 2) 确认：body 是要导入的 id 数组
curl.exe -s -X PUT -H "Content-Type: application/json" -d '["demo_core","demo_story"]' `
  "http://127.0.0.1:12804/api/presets/import?sessionId=$sid"
```

> 端口跟 `pnpm dev` / `pnpm start` 一致，默认 `12804`（见 `package.json` 的 scripts）。

第 1 步返回空数组 `[]` = zip 结构有问题（见 §9）。
第 2 步返回 `{"id":"最后创建的预设id"}`。

导出对照：`GET /api/presets/{id}/export` 会下载 `preset_<名称>.zip`，内容是依赖闭包 + 被引用的 model/comfyui。

## 8. 导入前自检清单

- [ ] zip 里每个条目路径都以 `root/` 开头，且用 `/` 分隔（`tar -tf` 看一眼）
- [ ] 每个预设目录下都有 `meta.json`，JSON 合法、UTF-8 无 BOM 也行（BOM 会被自动忽略）
- [ ] `meta.json` 里 `id`、`name` 都非空，`id` 不与现有预设重复（或确实想覆盖）
- [ ] 六个条目目录名精确：`lorebooks` `macros` `regexes` `scripts` `styles` `tools`
- [ ] 每个条目目录里的条目文件都以 `.meta.json` 结尾
- [ ] 每处 `"$file$xxx"` 都有同目录下名字**完全一致**的 `xxx`（含预设级的 `variables` / `opening`）
- [ ] 想有开场白 / 初始变量 → **`meta.json` 里有 `"opening"` / `"variables"` 字段**（外置或内联）
- [ ] 想有封面 → `meta.json` 里 `"cover": "<图片文件名>"`，且该文件真的存在
- [ ] `requires[].value` 指向的 id 也在同一个 zip 里，且导入时会一起勾选
- [ ] 所有 `tools/*.meta.json` 的 `type` 都是已注册的 provider
- [ ] 文件名没有中文（除非用 §6.3 的方式打包）

## 9. 失败了怎么查

| 现象 | 排查方向 |
| --- | --- |
| 导入后提示成功但列表没变化 | zip 条目名分隔符是 `\`、或多套了一层目录（`root` 不在第一段）→ 日志里 `zipToArchive` 会静默 `continue` |
| 只进来一部分预设 | 缺 `meta.json` 的目录被跳过；`meta.json` 解析失败的会被 `console.warn` 后跳过（看服务端终端） |
| 预设进来了但没有条目 | 条目目录名拼错（例如 `lorebook` 少了 `s`）；条目文件不是 `.meta.json` 结尾 |
| 条目在，但正文是空的 | `$file$` 名字与实际文件不一致（大小写 / 扩展名 / 多一层目录 / 中文名编码），或内容文件是 0 字节 |
| 开场白、变量是空的 | `meta.json` 里没写 `"opening"` / `"variables"`（只有文件没用），或 `$file$` 名字与文件不一致 |
| 封面没了 | `meta.cover` 不是包内文件名（旧包是 uuid），或文件没跟着打包 |
| 界面直接报 500 | 多半是某个工具 `type` 没有对应 provider；也可能是 `id`/`name` 为空 |

想看服务端细节：`zipToArchive` 与 `storage.save` 失败路径基本是**静默的**，
可以在终端观察 `jsonUtils.parse` 的 `[json](parse error)` 警告，以及工具 provider 的
`[tool]: provider missing(...)` 警告。

### 9.1 导入成功了，但跑起来不对

这类问题**不是存档结构错**，而是字段语义写反/写错，排查时对照这张表：

| 现象 | 原因 |
| --- | --- |
| 正文里出现字面量 `undefined` | 模板写错：Eta 的数据名是 `it`（`<%~ it.tone %>`），引用了没人提供的 `key` 也不报错 |
| 绑宏的世界书方向反了 | `expression.macro` 是"宏**启用时**才注入"（`!checkItems[macro]` 才 push） |
| `event` 世界书永不触发 | 它读的是 `variables.related_dates`（下划线命名），值是 `{year,month,day}` 数组 |
| 单选宏取消勾选后又自己回来了 | 单选组（`multiple:false`）不读 `disabled`，只能在同组中换一个；要"能关掉"就用复选组 |
| 工具在列表里开关是死的 | `tool.macro` 填的 `code` 没有任何宏提供，勾选只写进一个没人读的键 |
| 改一个宏，另一个宏跟着变 | 两个宏用了同一个 `code`（同 `code` 共享禁用状态） |
| 脚本/样式没注入 | `code` 撞车被去重（先注入的生效）；或脚本 `type` 用了 `link` 但 `content` 不是 URL |
| 两个工具只有一个能用 | 工具按暴露名（`config.code`）进同一张表，后者覆盖前者 |

## 11. 进阶

> 这里只讲**存档字段层面**的进阶（封面、agent/comfyui 工具、覆盖更新）。
> 想玩"宏当开关控制世界书/工具""Eta 求和与循环"这类玩法，见
> [04-进阶-宏联动](./04-进阶-宏联动.md)。

### 11.1 带封面

1. 把图片放进预设目录，名字随意（示例用 `cover.png`）；
2. `meta.json` 里写 **`"cover": "cover.png"`**（值就是文件名，不是 uuid）；
3. **不要写 `coverType`**——它已废弃，MIME 由导入端从图片字节里嗅探，扩展名写错也不影响（`cover.txt` 装着 PNG 也能识别）。

```json
{ "id": "demo_core", "name": "示例核心", "cover": "cover.png" }
```

> 旧格式（`"cover": "<uuid>"` + `"coverType"`）导入后会丢封面：uuid 会被当成文件名去找。
> 迁移就一步：把图片文件名填进 `cover`，删掉 `coverType`。

### 11.2 带 `agent` 子智能体工具

`agent` 型工具会引用一个模型配置和若干预设：

```json
{
  "name": "思维分析",
  "type": "agent",
  "disabled": false,
  "config": {
    "code": "agent_mind",
    "description": "分析角色心理",
    "disablePreset": true,
    "disableTags": [],
    "model": { "name": "default", "value": "721d5c7d-352e-43eb-be54-7ab3332fa487" },
    "presets": [{ "name": "心理分析Agent-1.0.0", "value": "agent_mind" }],
    "schema": "$file$mind.schema.json"
  }
}
```

- `config.model.value` 必须能在 `root/model/<该值>.model.json` 找到，否则导入时读不到模型（静默跳过）。
- `config.presets[].value` 会在**导出**时把那些预设一起打包；**导入**时不会自动补。
- 模型文件结构见 01 文档 §7.1。`properties` 建议**整段照抄模板**——`option` 是整段替换而非逐字段合并，
  只写 `{"option":{"model":"..."}}` 这类残缺对象会让引擎读不到必需字段（如 `thinking.type`）而报错。

### 11.3 带 `comfyui` 绘图工具

需要两个文件：`root/comfyui/<workflowId>.comfyui.json`（元数据 + 参数）与
`root/comfyui/<workflowId>.workflow.json`（工作流正文）。工具里用
`"config": { "code": "...", "description": "...", "workflow": { "name": "...", "value": "<workflowId>" } }` 引用。
结构见 01 文档 §7.2，真实样例见 `docs/templates/root/comfyui/`。

### 11.4 覆盖式更新

改完文件、重新打包、用**相同 `id`** 再导入一次即可：确认阶段会先删旧预设（含其全部条目）再创建。
所以"更新存档"不需要手动删东西，但**手改过的内容会被整包覆盖**。
