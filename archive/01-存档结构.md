# 存档结构

> 📖 **这是手册，不是教程。** 第一次做预设请先走 [00-快速上手](./00-快速上手.md)（10 分钟），
> 遇到"某个字段到底什么意思"再回来查本篇。

> 本文只讲**文件形态**：一个存档 zip 里应该长什么样、每个字节/文件被谁读、字段是什么意思。
> 运行时的「条目怎么进模型上下文、怎么注入 iframe」不在本文范围，见 `../learn/`。
> 手写操作步骤见 [02-手写存档指南](./02-手写存档指南.md)。
>
> 规则基线：`src/presets/server/storage.ts`（commit `optimize cover image` 之后）。
> 该版本把 `cover` / `opening` / `variables` 改成了**"meta 引用式"**，与旧版不兼容，
> 差异见文末 §11「规则变更记录」。

## 0. 一句话版本

一个**存档** = 一个 **zip**；zip 里所有文件都挂在 `root/` 下；
`root/` 的第一层是若干**预设目录**，外加可选的 `model/`、`comfyui/` 两个工作区目录。

```
存档.zip
└── root/
    ├── <预设A>/        ← 预设（Preset）
    │   ├── meta.json   ← 必须有；用 $file$ 指向 opening/variables、用文件名指向 cover
    │   ├── variables.json / opening.txt / cover.png   ← 被 meta 引用的内容文件
    │   └── lorebooks/ macros/ regexes/ scripts/ styles/ tools/   ← 条目（Entry）
    ├── <预设B>/
    ├── model/          ← 模型配置（被工具引用时才会出现）
    └── comfyui/        ← ComfyUI 工作流（被工具引用时才会出现）
```

---

## 1. 三层结构

| 层     | 载体               | 单位                          | 关键约束                                   |
| ------ | ------------------ | ----------------------------- | ------------------------------------------ |
| 容器层 | 一个 `.zip`        | zip 条目（文件）              | 路径第一段必须是 `root`                    |
| 预设层 | `root/<目录>/`     | 一个 `meta.json` = 一个预设   | 目录名随便，`meta.json` 里的 `id` 才是身份 |
| 条目层 | `<预设>/<plural>/` | 一个 `*.meta.json` = 一个条目 | `plural` 必须精确等于六种之一              |

对应源码：

- 容器层：`src/utils/archive.ts`（`archiveToZip` / `zipToArchive` / `get` / `set`）
- 预设层：`src/presets/server/storage.ts`（`storage.load` / `storage.save`）
- 条目层：`src/presets/server/factory.ts`（`storages.create` 的 `loadArchive` / `saveArchive`）
- 导入接口：`src/presets/server/api.ts`（`presets.import.POST` / `PUT`）

## 2. 容器层：zip → `root/`

### 2.1 只认 `root/`

`zipToArchive` 逐条扫描 zip 条目：

```ts
const parts = entry.name.split('/');
if (parts[0] !== 'root') continue; // ← 不是 root 开头的条目，直接丢弃
```

由此得到几条硬规则：

| 情况                                                       | 结果                                               |
| ---------------------------------------------------------- | -------------------------------------------------- |
| 条目路径是 `root/...`                                      | 正常读取                                           |
| 条目路径是 `./root/...`                                    | 正常读取（JSZip 会把开头的 `./` 规整掉，实测有效） |
| 条目路径是 `xxx/root/...`（多套了一层）                    | **整包被丢弃**，导入结果为空，且不报错             |
| 条目路径是 `root` 的**直接子文件**（如 `root/readme.txt`） | 会成为一个顶层 file 节点，但预设导入会跳过它       |
| 目录（目录项本身）                                         | 不进入树，只有文件进入                             |

> ⚠️ **中文/非 ASCII 的"路径名"是最大的坑**，见 §2.4。

### 2.2 `root` 本身不是节点

`root` 只作为前缀存在：`root/x/y` 在内存里变成 `{ x: { y } }`。所以顶层节点 = `root/` 的直接子项。
预设导入只遍历顶层节点，所以**预设目录必须是 `root/` 的直接子目录**。

### 2.3 文本编码

读端：`strUtils.buffer` → `new TextDecoder()`（默认 UTF-8），写端：`TextEncoder`（UTF-8）。
所以 `*.json` / `*.md` / `*.txt` / `*.css` / `*.js` 一律按 **UTF-8** 存取。

- UTF-8 BOM 会被 `TextDecoder` 默认丢掉，不影响 `JSON.parse`。
- 反例：`utf16le`、GBK 写的 `meta.json` 会解析失败（`jsonUtils.parse` 只 `console.warn` 然后返回 `null`），该预设被**静默跳过**。

### 2.4 文件名编码（务必读）

文件名、目录名的字节编码由**打包工具**决定，而读取端一律按 UTF-8 解码（`jszip` 的
`decodeFileName` 就是 `utf8decode`）。两者不一致时，名字会变成一串 `U+FFFD`（`efbfbd`），于是：

- 目录名乱了 → 无所谓（导入不看目录名）；
- 条目文件名乱了 → 无所谓（只按 `*.meta.json` 后缀扫描）；
- **`$file$` 引用的内容文件名乱了 → 内容静默丢失**。

本仓库自带的 `docs/templates/default.zip` 就有这个问题（用 `tar` 打的包，名字是本地代码页字节）：
`tools/抽奖-0.schema.json` 在读端会变成乱码，于是 `$file$抽奖-0.schema.json` 命中不到、schema 丢失。
相对地，`世界书.meta.json` 这类**条目文件名**乱码是无害的——条目只按 `.meta.json` 后缀扫描。

**结论：存档内的文件/目录名请一律用 ASCII**（`[A-Za-z0-9._-]`）。内容里的中文不受影响，
因为内容是 UTF-8 的字节，与文件名编码无关。

### 2.5 空内容

- 导出：`if (content?.length)` 才写文件，所以**空字符串不会进包**。
- 导入：0 字节文件读出来是 `''`，不是 `undefined`。

## 3. 预设层：`root/<任意目录名>/`

### 3.1 `meta.json`（必需）

唯一的入口文件。没有它 / 解析失败 → 整个目录被跳过（无报错）。

字段来源：`src/presets/index.ts` 的 `Preset`、`src/presets/server/schema.ts` 的 `presetSchema`。

| 字段          | 类型           | 缺省    | 说明                                                                                        |
| ------------- | -------------- | ------- | ------------------------------------------------------------------------------------------- |
| `id`          | string         | —       | **必需的实体主键**，即预设编码。建议 `[A-Za-z0-9_-]+`，全库唯一；重复导入会覆盖同 id 的预设 |
| `name`        | string         | —       | **必需**的显示名                                                                            |
| `version`     | string         | `1.0.0` | 仅展示用；`requires` 里的 `name` 约定写成 `名称-版本`                                       |
| `description` | string \| null | —       | 列表里的描述                                                                                |
| `tags`        | string[]       | `[]`    | 只用于 `LIKE %tag%` 过滤，不做枚举校验                                                      |
| `requires`    | NameValue[]    | `[]`    | 预设级依赖，元素为 `{ name, value }`，`value` 是**被依赖预设的 id**                         |
| `properties`  | object         | `{}`    | 预留的自由字段，当前代码没有读取点，原样存库                                                |
| `cover`       | string         | —       | 存档内**封面文件名**（如 `cover.png`），导入按这个名字取文件，见 §3.4                        |
| `opening`     | string         | —       | 开场白：`"$file$文件名"` 或直接内联，见 §3.3                                                |
| `variables`   | string         | —       | 初始变量：`"$file$文件名"` 或内联 JSON 文本，见 §3.2                                        |
| `coverType`   | string         | —       | **已废弃**：现由导入端嗅探图片 MIME，写了也被忽略                                           |

未被识别的多余字段不会报错：落库时 drizzle 只按表的列取值，多出来的键被直接丢掉。

> ⚠️ 这里有一处规则变更：`opening` / `variables` **不再是"写了也没用"**。
> 它们现在是存档里的正式字段（值可以是 `$file$引用` 或内联），`cover` 存的是**包内文件名**，
> 而 `coverType` 已经废弃。详见 §3.2–§3.4。

### 3.2 `variables`（可选）

初始变量，一段 **JSON 文本**（对象）。字段本身就写在 `meta.json` 里，值有两种形态：

```json
{ "variables": "$file$variables.json" }
```

```json
{ "variables": "{\"hp\":100,\"day\":1}" }
```

- **外置**：`$file$` 后面是"同目录下的文件名"，导入时按名字精确读取。
  `variables.json` 只是**导出时的习惯名**，手写时可以叫 `vars.json`、`init.json`……只要 `$file$` 与真实文件名一致。
- **内联**：直接写 JSON 文本（注意这是字符串，引号要转义）。
- 字段缺失 / 空串 → 不设置；`$file$` 指向的文件不存在 → 字段变成 `undefined`（**静默**）。
- 多个预设叠加时按预设顺序**深度合并**（`jsonUtils.merge`：对象递归合并，数组整体替换，`null`/`undefined` 跳过）。
- 内容解析失败只会变成 `null`，不会中断导入。
- 导出时**总是**写成 `"$file$variables.json"`；变量为空则不产生这个文件（于是引用悬空，导入后回到 `undefined`）。

### 3.3 `opening`（可选）

开场白文本。规则与 `variables` 完全一致：`$file$` 引用或内联。

```json
{ "opening": "$file$opening.txt" }
```

- **旧版的"文件名必须以 `opening.` 开头"规则已经取消**（以前用 `get.fuzzy('opening.')` 前缀匹配，现在按 meta 里的名字精确读）。
- 导出时写成 `"$file$opening.txt"`。
- 多个预设的开场白会以 `\n` 拼接，作为故事第 0 条（`sequence: -1`）消息的正文。

### 3.4 `cover`（可选）

封面图，二进制。**`meta.cover` 存的是"存档内文件名"，不是文件表 uuid。**

- 手写：把图片放进预设目录，然后在 meta 里写它的**文件名**：

  ```json
  { "id": "demo_core", "name": "示例核心", "cover": "cover.png" }
  ```

  文件名叫什么都行（`cover.png`、`art.webp`、`cover-1`），扩展名也不参与判断，只要与 `cover` 完全一致。

- 导入：`get.buffer(nodes, meta.cover ?? '')` 按名字取文件 → 用 `file-type` **嗅探真实 MIME**（不看扩展名）
  → 落文件表（同内容按 sha256 去重）→ 把 `cover` 换成新的文件 uuid。
- **`coverType` 已废弃**：写了也会被忽略，MIME 由字节内容决定。
- 导出：从文件表读出封面，按 MIME 反查扩展名写成 `cover.<ext>`，并把 meta 里的 `cover` 改成这个文件名；
  封面用 `level: 0`（STORE，不压缩）。若 MIME 不在下表里，则**不写封面文件**，meta 里会残留原来的 uuid。
- ⚠️ **旧格式存档的封面会丢**：老包是 `"cover": "<uuid>"` + `"coverType": "image/png"`，
  新导入端会把这个 uuid 当文件名去找，找不到就静默跳过。迁移办法：把图片命名为 `cover.png`（或任意名），
  再把 meta 的 `cover` 改成该文件名，删掉 `coverType`。
- 不想带封面就整条省略 `cover`，不要留一个悬空的 uuid（界面上会显示成裂图）。
- 另外：界面上封面也允许填**外链 URL**（此时库里存的不是 uuid）。这种封面**不会被打包**——
  导出只处理文件表里的 uuid，外链会被跳过（`if (item.cover && validate(item.cover))`）。

下表只用于**导出**时把 MIME 换成扩展名（`src/presets/server/storage.ts` 的 `extensionMap`）：

| MIME                                        | 扩展名          |
| ------------------------------------------- | --------------- |
| `image/png`                                 | `png`           |
| `image/jpeg` / `image/jpg`                  | `jpg`           |
| `image/gif`                                 | `gif`           |
| `image/webp`                                | `webp`          |
| `image/svg+xml`                             | `svg`           |
| `image/bmp`                                 | `bmp`           |
| `image/x-icon` / `image/vnd.microsoft.icon` | `ico`           |
| `image/tiff`                                | `tiff`          |
| `image/avif`                                | `avif`          |
| `image/heic` / `image/heif`                 | `heic` / `heif` |
| `image/apng`                                | `apng`          |

导入方向完全不看这张表（也不看扩展名），只看字节内容。

### 3.5 预设目录里的其它东西

除 `meta.json`、被 `$file$` 引用的文件、封面文件与六个条目目录外，其它文件/目录**一律被忽略**
（不会报错，也不会被带进库）。换句话说，存档不支持"预设自带静态资源"。

## 4. 条目层：`<预设目录>/<plural>/`

### 4.1 六个 `plural`

| 目录名（必须精确） | 条目类型 | `entryType` / storage id | 单独内容文件        |
| ------------------ | -------- | ------------------------ | ------------------- |
| `lorebooks/`       | 世界书   | `lorebook`               | ✅ `content`        |
| `macros/`          | 宏       | `macro`                  | ✅ `value`          |
| `regexes/`         | 正则     | `regex`                  | ❌ 全内联           |
| `scripts/`         | 脚本     | `script`                 | ✅ `content`        |
| `styles/`          | 样式     | `style`                  | ✅ `content`        |
| `tools/`           | 工具     | `tool`                   | ✅ 视 provider 而定 |

### 4.2 `*.meta.json` = 一条

- 扫描规则：目录（含任意层子目录）下所有**以 `.meta.json` 结尾**的文件，每个文件 = 一个条目。
- 文件名的前缀部分**随便取**，不影响身份；真正的身份在 JSON 里的 `code`（工具/正则看 `name`）。
- **允许嵌套子目录**（`docs/templates/root/终末/lorebooks/帝都/人物/role_hs_22.meta.json` 就是例子），
  扫描是广度优先的，层数不限。
- 同目录下不是 `.meta.json` 的文件都是"内容文件"，只有被 `$file$` 指向时才会被读。

### 4.3 `$file$` 引用机制

`src/utils/archive.ts` 的 `set.value` / `get.value` 实现：

- 写入时把字段值挪到单独文件，字段本身变成 `"$file$<文件名>"`；
- 读取时，字段值若以 `$file$` 开头，就取**同一目录下**名字精确等于后面那串的文件内容，填回字段。

因此：

1. `$file$` 后面是**完整文件名（含扩展名）**，且必须与 meta 同级；
2. 名字精确匹配，大小写敏感；
3. 引用不到文件 → 字段变成 `undefined`，**静默不报错**；
4. 不以 `$file$` 开头的字符串**原样保留** → 内联内容完全合法（`docs/templates` 里大量条目就是内联的）；
5. 只有下表中的字段会被解析，其它字段里写 `$file$` 只是普通字符串。

| 条目              | 会被 `$file$` 解析的字段                                 | 导出时的默认文件名                                       |
| ----------------- | -------------------------------------------------------- | -------------------------------------------------------- |
| `preset`（预设级）| `variables` / `opening`                                  | `variables.json` / `opening.txt`                         |
| `lorebook`        | `content`                                                | `<code>-<序号>.content.<txt\|md\|json\|yaml\|xml>`       |
| `macro`           | `value`                                                  | `<code>-<key>-<序号>.value.<txt\|json>`                  |
| `script`          | `content`                                                | `<code>-<序号>.script.<js\|txt\|json>`                   |
| `style`           | `content`                                                | `<code>-<序号>.style.<css\|txt>`                         |
| `tool`（script）  | `config.description` / `config.schema` / `config.script` | `<name>-<序号>.desc.txt` / `.schema.json` / `.script.js` |
| `tool`（agent）   | `config.description` / `config.schema`                   | `<name>-<序号>.desc.txt` / `.schema.json`                |
| `tool`（comfyui） | `config.description`                                     | `<name>-<序号>.desc.txt`                                 |
| `regex`           | 无                                                       | —                                                        |

> 「导出时的默认文件名」只是导出的习惯，导入**不检查**这个名字，只要 `$file$` 与真实文件名一致即可。
> 扩展名同理：`.md` 还是 `.txt` 由你决定，程序不看后缀（只有导出时按类型挑一个）。
>
> 预设级的 `variables` / `opening` 走的是同一套 `$file$` 机制（`src/presets/server/storage.ts` 里的
> `accessor`），所以它们和条目内容一样：**文件名自由、可以内联、引用不到就静默变空**。

### 4.4 条目通用字段

来自 `src/presets/index.ts` 的 `PresetItem<T> = DisableDto & T & EntryItem`：

| 字段       | 说明                                                       |
| ---------- | ---------------------------------------------------------- |
| `name`     | 条目显示名（存 `name` 列）。工具的 `name` 只是界面显示     |
| `disabled` | `true` 时该条目在运行时被跳过；缺省 `false`                |
| 其余       | 就是各条目 `T` 的字段，见 §5                               |
| `entryId`  | 数据库分配的序号，导入时**会被忽略并重新分配**，写不写都行 |
| `masterId` | 导入时会被剥掉，不用写                                     |

导入时落库的对应关系（`src/presets/server/factory.ts` 的 `save`）：

```
name, disabled  →  列
其余一切        →  data(JSON) 列，原样保留（包括你不小心写的 entryId）
```

所以条目里**没有**严格的字段白名单：多写字段只会躺在 `data` 里，少写字段就用运行时默认值兜底。

## 5. 六种条目的字段

### 5.1 世界书 `lorebooks/`

```ts
// src/presets/lorebooks/index.ts
interface Lorebook {
  code: string; // 预设内去重用；运行时 id = `${预设id}-${code}`
  type: string; // 内容类型：plaintext|markdown|json|yaml|xml（决定导出扩展名）
  match: string; // 匹配器：always|normal|vector|event|variable
  expression: any; // 匹配表达式，随 match 变化
  content?: string; // 正文（可 $file$）
  priority: number; // 默认 0
  layer: number; // 默认 100，决定注入位置
  role: 'assistant' | 'user' | 'system' | 'knowledge'; // 默认 knowledge
}
```

- `type` → 导出扩展名：`json→json`、`plaintext→txt`、`markdown→md`、`yaml→yaml`、`xml→xml`，其它按 `txt`。
- `role` 决定注入方式：`system`→系统提示、`user`→用户侧、`assistant`→助手侧、
  `knowledge`→以"工具调用结果"的形式塞进上下文。
- 注入顺序 = `layer * 10000 + priority` 升序；`layer < 100` 的插在当前消息**之前**，`layer >= 100` 的插在**之后**
  （`src/presets/lorebooks/client/builder.ts`）。
- `code` 在**同一预设内**要唯一，否则运行时 `${预设id}-${code}` 撞车。

`expression` 按 `match` 的形态（`src/presets/matchers/client/*.tsx`）：

| `match`    | `expression` 形状                                                    | 触发条件                                                                                 |
| ---------- | -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `always`   | `{ last?: boolean, macro?: string }`                                 | 恒定注入。`last:true` = 常驻后置；`macro` 绑定同名宏做开关（**宏处于启用状态时才注入**，用法见 [04](./04-进阶-宏联动.md)） |
| `normal`   | `{ keywords: string[][], keywordsLength: number, fitCount: number }` | 关键词组内任一命中算 1 组，命中组数 ≥ `fitCount`                                         |
| `event`    | `normal` 的字段 + `{ minDate, maxDate }`（`{year,month,day}`）       | 先看 `variables.related_dates` 是否落在区间，再走 `normal`                               |
| `variable` | `{ path: string, value: string }`                                    | 变量 `path` 的当前值 `=== value`（字符串比较）                                           |
| `vector`   | `{ keywords?: string }`                                              | 向量检索命中（需要故事开启 RAG）                                                         |

### 5.2 宏 `macros/`

```ts
// src/presets/macros/index.ts
interface Macro {
  code: string; // 去重/选择标识
  key: string; // 变量名，模板里用 <%~ it.key %>
  value?: string; // 值（可 $file$）
  json: boolean; // value 是否按 JSON 解析
  multiple: boolean; // true=复选组，false=单选组（同 key 里选一个 code）
  hidden: boolean; // 是否在宏面板里隐藏
}
```

- 模板引擎是 Eta（`varName` 默认 `it`，`autoEscape` 默认开）：`<%~ it.key %>` 原样内插（写提示词请用这个），
  `<%= it.key %>` 会把 `& < > " '` 转成实体。
  上下文 = 所有宏 `key` + 故事变量 `it.variables`；子 agent 传进来的参数是**摊平到顶层**的
  （schema 里有 `character` 就写 `it.character`，不存在 `it.args`）。
- Eta 拿到 `undefined` 不会报错，会原样输出字面量 `undefined`——写宏引用前先确认这个 `key` 有人提供。
- 合并规则（`src/presets/macros/client/realm.ts`）：
  - 含 `json:true` 的条目 → 所有 JSON 深度合并，纯文本拼到合并对象的 `toString()` 上；
  - 全是纯文本 → 直接拼接；
  - `multiple:false` 时，同 `key` 下只生效一个 `code`。
- 多预设叠加时 `code` + `key` 共同决定去重/共享，详见 §6。
- 写宏时的两个坑（都在 `src/presets/macros/client/realm.ts`）：
  - **单选组（`multiple:false`）里 `disabled` 不参与判定**：选中项只看"用户选过哪个 `code`"，
    没选过就取同组里 `sorter` 最小的那个。想要"默认不启用"，只能用复选组（`multiple:true`，
    此时 `disabled:false` 才是有效的初始勾选状态）。
  - **同 `code` 不同 `key` 的两个宏共享同一个开关**（源码注释里的规则 1），
    设计上用来让多个预设继承/共享一条宏；不相干的宏不要写成同一个 `code`。

| ----------------- | ------------------------------------------- | ---------- |

### 5.5 正则 `regexes/`

```ts
// src/presets/regexes/index.ts
interface Regex {
  pattern: string; // 传给 String.prototype.replace 的第一个参数（字符串形式）
  replacement: string;
  target: string; // input | output | both
}
```

- **没有内容文件**（没有 `loadArchive`/`saveArchive`），全部字段必须写在 `.meta.json` 里。
- `pattern` 是字符串而不是 `/.../g` 字面量：只替换**第一个**匹配，且没有 flags。
- 执行顺序由条目的 `name` 排序（`sorter = name`），不是列表位置；`target` 决定作用于输入还是输出。

### 5.6 工具 `tools/`

```ts
// src/tools/index.ts
interface Tool<T = any> {
  type: string; // provider id，必须有对应 provider，否则整个导入失败
  macro?: string; // 绑定同名宏，状态与宏开关联动（模板里有写成 false 的，等价于不绑定；玩法见 04 文档）
  config: T; // 视 provider
}
```

可用的 `type`（都要在服务端注册过）：

| `type`     | 来源                                       | `config` 字段                                                                                               |
| ---------- | ------------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| `variable` | `src/tools/variables`                      | `{}`（变量编辑工具，无配置）                                                                                |
| `lorebook` | `src/presets/lorebooks/server/provider.ts` | `{}`（让模型按需检索世界书）                                                                                |
| `memory`   | `src/stories/memories`                     | `{}`（故事记忆，通常由故事侧注册）                                                                          |
| `elicit`   | `src/tools/elicits`                        | `{}`（向用户提问）                                                                                          |
| `fetcher`  | `src/tools/fetchers`                       | `{ maxResults, timeout, maxLength }`                                                                        |
| `mcp`      | `src/tools/mcp`                            | `{ code, url, headers, timeout, maxLength, includes }`                                                      |
| `script`   | `src/tools/scripts`                        | `{ code, description?, schema?, script?, enableDoc?, enableVariable? }`                                     |
| `agent`    | `src/tools/agents`                         | `{ code, description?, schema?, model: NameValue\|null, presets: NameValue[], disablePreset, disableTags }` |
| `comfyui`  | `src/comfyui`                              | `{ code, description?, workflow: NameValue }`                                                               |

`script` 型最常用，要点：

- 暴露给模型的名字是 **`config.code`**（不是条目的 `name`）；同名工具后注册的覆盖先注册的。
- `config.script` 是**函数体**（`new Function('input','context', script)`），所以必须自己 `return`。
- `config.schema` 是 JSON Schema 文本。
- `enableDoc:true` 会在 `context` 里给 `document`/`window`；`enableVariable:true` 会给 `context.variables`。

`agent` / `comfyui` 型是**跨目录引用**：它们会把 `model/<id>.model.json`、`comfyui/<id>.comfyui.json`
一起写进/读出存档（见 §7），并在导出时把 `config.presets` 里的预设追加进导出集合。

## 6. 排序与去重速查

`criteria` 决定数据库里的 `sorter`（界面排序）和 `filter`（搜索/过滤用），`code` 决定运行时的去重。

| 条目       | `sorter`                       | `filter`                             | 运行时去重 / 顺序                                       |
| ---------- | ------------------------------ | ------------------------------------ | ------------------------------------------------------- |
| `lorebook` | `${match}${code}${name}`       | 同左                                 | id = `${预设id}-${code}`；注入序 `layer*10000+priority` |
| `macro`    | `${key}${+multiple}${+hidden}` | `${key}${name}`                      | `code`+`key` 联合判定（同 key 单选 / 复选 / 共享禁用）  |
| `script`   | `${name}${code}`               | `${type}${补齐5位的priority}${name}` | 按 `code` 去重（`sct-<code>`），`priority` 升序         |
| `style`    | `${name}${code}`               | 同 script                            | 按 `code` 去重（`stl-<code>`），`priority` 升序         |
| `regex`    | `${name}`                      | `${target}${name}`                   | **不去重**，全部按 `name` 顺序依次 replace              |
| `tool`     | `${type}${name}`               | 同左                                 | 按暴露出来的工具名（`config.code` 等）覆盖              |

## 7. 工作区目录

这两个目录是**可选的**，只有当预设里的工具引用了它们才会出现在存档里。

### 7.1 `model/<uuid>.model.json`

模型配置实体，由 `agent` 工具通过 `config.model.value` 引用
（`src/models/server/storage.ts`，文件名 `<id>.model.json`，`id` 必须与引用值一致）。

```json
{
  "builder": "default",
  "engine": "deepseek",
  "id": "721d5c7d-...",
  "iterations": 20,
  "name": "default",
  "properties": {
    "config": {},
    "option": { "max_tokens": 0, "model": "deepseek-flash", "temperature": 1 },
    "retry": { "interval": 3, "max": 3 }
  },
  "stream": true
}
```

> 注意：导出的是数据库整行（`databases.get` 不带列映射），如果该模型配过 API Key，
> 存档里会带上加密后的 `key` 与 `iv`（`iv` 会被 JSON 成 `{"type":"Buffer","data":[...]}`）。
> 分享存档前请检查，跨机器解密不保证可用。

字段语义（`src/models/index.ts`、`src/models/server/schema.ts`）：

| 字段                | 取值                                | 说明                                                                                                                |
| ------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `id`                | uuid 字符串                         | 同时也是文件名；`agent` 的 `config.model.value` 引用的就是它                                                        |
| `name`              | string                              | 显示名，`config.model.name` 用它                                                                                    |
| `engine`            | `deepseek` / `openai` / `anthropic` | 接口协议                                                                                                            |
| `builder`           | `default` / `layered`               | 上下文构造方式（`layered` 与模型侧分层有关，和世界书的 `layer` 不是一回事）                                         |
| `stream`            | boolean                             | 是否流式                                                                                                            |
| `iterations`        | number                              | 单轮最多调用几次模型（带工具时会多轮），默认 20                                                                     |
| `properties.config` | object                              | 引擎接入配置：deepseek `{token}`；openai `{url, format: chat\|responses, extras, token}`；anthropic `{url, extras}` |
| `properties.option` | object                              | 采样参数，按引擎不同（deepseek 有 `model`/`thinking.type`/`reasoning_effort`/`temperature`/`top_p`/`max_tokens`…）  |
| `properties.retry`  | `{interval, max}`                   | 流式超时重试间隔 / 最大次数                                                                                         |
| `key` / `iv`        | 密文 / IV                           | API Key 及其加密向量，见上面的提示                                                                                  |

> 手写模型时建议**整段照抄模板的 `properties`**：`option` / `config` 是"有则整段使用、没有才用默认值"，
> 不做逐字段合并。比如只写 `{"option":{"model":"deepseek-flash"}}`，deepseek 引擎读
> `option.thinking.type` 时会直接抛错。

### 7.2 `comfyui/<uuid>.comfyui.json` + `<uuid>.workflow.json`

由 `comfyui` 工具通过 `config.workflow.value` 引用（`src/comfyui/server/storage.ts`）：

`<id>.comfyui.json` —— 元数据 + 参数表：

```json
{
  "params": [
    {
      "config": { "key": "string_b", "node": "85", "prompt": "1girl" },
      "name": "提示词",
      "sequence": 0,
      "type": "text"
    }
  ],
  "workflow": {
    "description": "",
    "id": "94bb6ad1-...",
    "name": "krea2_example",
    "properties": {}
  }
}
```

`<id>.workflow.json` —— 工作流正文（ComfyUI 导出的 api 格式 JSON，原样存文本）：

```json
{
  "1": {
    "class_type": "CheckpointLoaderSimple",
    "inputs": { "ckpt_name": "model.safetensors" }
  }
}
```

读取时用前缀匹配 `${id}.workflow.` 找正文，所以扩展名可以变。

`comfyui.json` 的字段：

- `workflow`：工作流实体（`id` / `name` / `properties`，`description` 可省），正文不在这个文件里。
- `params[]`：绘图工具可调的参数表。
  - `masterId`：所属工作流 id（同 `id`）
  - `sequence`：参数序号，也就是绘图工具 `config.params[].id` 引用的值
  - `name`：生图表单里的标题
  - `type`：呈现与写值方式，已注册的有 `text` `prompt` `agent_text` `number` `select` `model_select` `power_lora_select` `image_callback`
  - `config`：随类型不同，一般至少有 `node`（工作流节点号字符串）与 `value`

> 导入时同 `id` 的工作流先删后建。工作流里引用的 lora / 大模型只是本地文件名，**不随包走**。

### 8.2 `other/archive/`（手写的存档，可作为"文件编辑"范例）

```
root/
├── 弹幕/  meta.json(id=bullet)
│          lorebooks/{bullet.meta.json, bullet.content.md}
│          scripts/{panel.meta.json, panel.script.js, panel.script-min.js}
```

## 9. 导入到底做了什么

接口：`src/presets/server/api.ts`

### 9.1 两步式

```
POST /api/presets/import?sessionId=<uuid>       multipart，字段名 file
   → 解析 zip，逐个顶层目录 storage.save() 出 Preset 对象（含全部条目）
   → 结果暂存到缓存（key = preset_import_<sessionId>）
   → 返回 [{ name, value(id) }, ...]（供界面勾选）

PUT  /api/presets/import?sessionId=<uuid>        body = 选中的 id 数组
   → 从缓存取回，逐个：同 id 已存在则 delete 再 create
   → 返回 { id }（最后一个成功的 id）
```

界面（`src/presets/client/content.tsx`）默认**全选**，但只提交你勾上的那些——
**依赖不会自动带上**：若 A 依赖 B 而你只勾 A，导入后 A 的 `requires` 会指向一个不存在的 id。

### 9.2 单个预设的读入顺序

`storage.save` 依次做：

1. 读 `meta.json`（失败 → `null`，整个目录跳过）；
2. `get.value` 解析 `variables`：`$file$X` 读同目录的 `X`，否则保留内联文本；
3. `get.value` 解析 `opening`：同上；
4. `get.buffer(meta.cover ?? '')` 按**文件名**取封面字节 → `file-type` 嗅探 MIME → 落文件表 → 把 `cover` 换成新 uuid；
5. 依次调用每种条目 storage 的 `saveArchive`，各自扫描自己那个 `plural` 目录；
6. 交给 `repository.create` 落库（`if (entries) storage.manager.save(...)` 写条目）。

### 9.3 什么会"静默失败"

| 现象 | 原因 |
| --- | --- |
| 导入列表为空 | zip 里没有 `root/` 前缀（多套了一层目录，或用了反斜杠分隔符，见 §2.4 与 02 文档） |
| 少了某个预设 | 该目录没有 `meta.json`，或 `meta.json` 不是合法 UTF-8 JSON（`console.warn` 后跳过） |
| 少了某个条目 | 目录名不是六个 `plural` 之一；或 `.meta.json` 解析失败；或文件名没有以 `.meta.json` 结尾 |
| 条目内容为空 | `$file$` 指向的文件名对不上（编码、大小写、多一层目录、写错扩展名） |
| 开场白/变量为空 | **`meta.json` 里没有 `$file$` 引用**（只把文件放进去是没用的），或引用的名字与实际文件不一致 |
| 封面丢失 | `meta.cover` 不是包内真实文件名（典型：旧包的 uuid + `coverType`），或根本没有 `cover` 字段 |
| 整个导入 500 | 某个工具的 `type` 没有注册对应 provider（`tools/server/storage.ts` 直接抛 `BusinessError`） |
| id 或 name 为空 | 在 PUT（确认）阶段 `repository.create` 抛错；注意此时同 id 的旧预设可能已被删掉 |

## 10. 导入 vs 导出：宽严对照

导出是"应用自己写出来的样子"，导入是"应用愿意接受的样子"。后者明显更宽松：

| 维度           | 导出                                                                                | 导入                                                       |
| -------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 顶层           | 固定 `root/`，路径分隔符 `/`                                                        | 必须 `root/`（`./root/` 可），分隔符必须是 `/`             |
| 预设目录名     | `= 预设 id`（`root[item.id]`；仓库里的 `default.zip` 目录被改成了显示名，同样可用） | 任意                                                       |
| 预设目录位置   | `root/` 直接子目录                                                                  | 同样必须直接子级                                           |
| `meta.json`    | 必写；剔除 `entries`，但**保留** `variables`/`opening`（`$file$` 形式）与 `cover`   | 必读；三者的值决定怎么取文件                               |
| `opening`/`variables` | 一律外置成 `$file$variables.json` / `$file$opening.txt`                      | `$file$引用` 或**内联**都行，文件名任意                    |
| `cover`        | 写**包内文件名**（`cover.<ext>`）+ 图片文件                                         | 按 `meta.cover` 这个**文件名**取图，MIME 靠嗅探            |
| `coverType`    | 不再写出                                                                            | 已废弃，出现也被忽略                                       |
| 条目目录       | 固定 `plural`                                                                       | 固定 `plural`（这条一样严）                                |
| 条目文件名     | `<code\|name>-<序号>`                                                               | 任意，后缀 `.meta.json`                                    |
| 条目子目录     | 导出时是平的                                                                        | 支持任意层嵌套                                             |
| 内容           | 一律 `$file$` 外置                                                                  | `$file$` 或直接内联                                        |
| 内容文件扩展名 | 按类型固定                                                                          | 任意（要与 `$file$` 一致）                                 |
| `entryId`      | 会带上（历史遗留，来自 `data` 里残留字段）                                          | 忽略并重新分配                                             |
| 打包顺序       | 依赖闭包 BFS 后反转（依赖在前）                                                     | 就是 zip 里的目录顺序，不做依赖补全                        |
| 空内容         | 不写文件（`$file$` 引用会悬空）                                                     | 0 字节 = 空串；悬空引用 = 字段 `undefined`                 |

## 11. 规则变更记录（cover / opening / variables）

这一版（`optimize cover image`）把三项从"文件名约定"改成了"meta 引用"，**旧存档需要手工迁移**。

| 项 | 旧规则 | 现规则 |
| --- | --- | --- |
| `variables` | 固定读 `variables.json`，读完直接覆盖 meta 里的 `variables`（所以写进 meta 等于没用） | 按 meta 里的 `variables` 取：`"$file$X"` 读同目录的 `X`；不是 `$file$` 开头的就原样内联使用 |
| `opening` | `get.fuzzy('opening.')` 前缀匹配 `opening.*`，取目录里第一个命中的 | 按 meta 里的 `opening` 精确取（`"$file$X"`）或内联 |
| 封面 | meta 里 `cover` = 文件表 uuid，`coverType` = MIME，读取时用 MIME 反查 `cover.<ext>` | meta 里 `cover` = **包内文件名**，直接按名字读文件；MIME 由 `file-type` 从字节嗅探 |
| 导出 `meta.json` | 剔除 `variables`/`opening`，额外写 `coverType` | 保留 `variables`/`opening`（`$file$` 形式），`cover` 写文件名，**不再写 `coverType`** |
| 旧包导入 | — | 旧包里"uuid + coverType"的封面会**丢**；`opening.txt`/`variables.json` 若 meta 里没有引用也**不生效** |

**迁移一个旧预设**（三步）：

1. `meta.json` 里加 `"variables": "$file$variables.json"`、`"opening": "$file$opening.txt"`（文件已存在的话，名字照抄）；
2. 有封面的话：把图片改名为 `cover.png`（或任意名），`cover` 写成该文件名，删掉 `coverType`；
3. 重新打包导入。因为同 `id` 会先删后建，这一步就是原地覆盖。
