# 07 · 模拟经营：变量结构与小手机面板

> **对应预设**：`docs/templates/root/模拟经营/`（id `app_simulation`，3 个条目）｜**前置**：[05](./05-默认交互-渲染层.md)、[06](./06-弹幕-变量驱动的界面.md)｜**难度**：★★★
> **你将得到**：一套"变量 schema + 悬浮面板"的状态显示方案，面板点一下还能把内容写回输入框。

---

## 一、引言

"How old is 变量" 这个问题，在有 UI 的玩法里会变成三件事：

1. **变量该长什么样**（结构）——要写进提示词，模型才知道怎么更新；
2. **谁来写它**（写入）——变量工具打 JSON Patch；
3. **怎么看得见**（呈现）——iframe 里的面板只读不写。

`模拟经营` 就是这三件事的最小完整实现：**一个宏**（变量结构说明）+ **一个脚本**（小手机面板）
+ **一个样式**。它自己不写变量、不做计算，纯粹是"变量的显示器"。

---

## 三、理论

### 3.1 变量是唯一数据源

```
模型 → 变量工具 set_variable（JSON Patch）
     → 本轮输出保存时统一应用
     → 主应用 postMessage('variables', {...变量, space})
     → 面板 useMessageData('variables') 重新渲染
```

面板**不缓存**业务数据：每次渲染都从 `variables` 里 `get`。这样"模型改了变量 → 界面自动变"，
不需要任何额外的通信协议。

### 3.2 变量结构写在一段宏里

`macros/variable-sim.meta.json` 是一条 `key: "variable"` 的复选宏，`value` 是一百来行说明：
`/user`、`/charas`、`/buildings`、`/items` 四个路径 + 各自的 TS 类型 + 更新规则（"首次出现整体设置，
之后只改变动字段""键用字母下划线""字段非空"……）。

这段文本最后会通过 `it.variable` 插进 `默认设置` 的"变量格式"世界书里（那条世界书还绑了变量工具的开关）。
也就是说：**变量结构 = 一份给模型看的接口文档**，和工具 schema 的作用类似，只是它约束的是"数据"而不是"调用"。

> 📦 **备注 · 示例变量结构（节选，简化版）**
>
> ```ts
> // /user
> { name: string; desc: string;
>   property: { str: number; dex: number; con: number;
>               int: number; wis: number; cha: number } }
>
> // /charas
> { [key: string]: { name: string; desc: string;
>                    relation: '友好' | '中立' | '敌对';
>                    status: '健康' | '危险' | '死亡';
>                    statusDesc: string; property: Property } }
>
> // /buildings
> { [key: string]: { name: string; type: BuildingType;
>                    level: number; status: BuildingStatus; desc: string } }
>
> // /items
> { [key: string]: { name: string; type: ItemType; status: string; desc: string } }
> ```
>
> 注意 `status` 这类字段同时用于**显示**（颜色/图标）——所以值域要写死，别让模型自由发挥。

### 3.3 面板骨架

```js
const { STab, SFloating, SRadarChart, SExpand, SVariableImage } = window.sComponents;
const { get, useMessageData, appendItemInput, renderComponent } = window.sUtils;

function App() {
  const [variables] = useMessageData('variables');
  return SFloating({
    button: () => '🔮',
    className: 'sim-floating',
    children: () => h(STab, {
      layout: (header, content) => h('div', { className: 'sim-panel' }, header, content),
      tabs: [
        { id: 'property',  header: () => '🩺 个人状态', content: () => h(PropertyTab, { user: get(variables,'user',{}) }) },
        { id: 'charas',    header: () => '👥 角色列表', content: () => h(CharasTab,   { charas: get(variables,'charas',{}) }) },
        { id: 'buildings', header: () => '🏗️ 建筑',     content: () => h(BuildingsTab,{ buildings: get(variables,'buildings',{}) }) },
        { id: 'items',     header: () => '🎒 物品',     content: () => h(ItemsTab,    { items: get(variables,'items',{}) }) },
      ],
    }),
  });
}
renderComponent(App, 'sim-app');
```

> 📦 **备注 · `sComponents` 的 props**
>
> | 组件 | props |
> | --- | --- |
> | `SFloating` | `{ children, button, className }`：可拖动的悬浮球，点开显示 `children` |
> | `STab` | `{ tabs: [{ id, header, content }], layout(header, content), className }` |
> | `SRadarChart` | `{ items: [{ name, value }], max, min }` |
> | `SExpand` | `{ header, children, className }` 折叠卡 |
> | `SVariableImage` | `{ name, className, defaultComponent }` 按名字取图，缺图用兜底 |

### 3.4 反向交互：点卡片写回输入

```js
h('div', { onClick: () => appendItemInput({ name: item.name }) }, item.name);
```

`appendItemInput` 会把 `[名称]` 插到**主应用输入框的光标处**（它依赖 `window.userInput`，
由主应用在 iframe 里挂出来）。这就是"点一下物品，输入框自动补上引用"的实现，一行搞定。

### 3.5 为什么依赖 `preset_tiandao`

`模拟经营` 自己不写"怎么说话、怎么思考"，它只加一条变量说明 + 一个面板。
规则、文风、工作流都来自 `preset_tiandao`（它又依赖 `settings` + `ui_default`）。
所以导入时是四件套：**settings → ui_default → tiandao → simulation**（导入不会自动补依赖）。

`macros/vars.meta.json`（变量结构，20 行就够）：

```json
{
  "name": "变量结构",
  "code": "status_vars",
  "key": "variable",
  "value": "变量路径：/hp（数字, 0-100）、/mood（乐观|平静|低落）、/bag（{ [物品名]: 数量 }）。\n每轮用 set_variable 更新；字段缺失就补上，不要新造路径。",

  "multiple": true,

  "disabled": false
```

`scripts/app.meta.json` / `styles/app.meta.json` 照 [05](./05-默认交互-渲染层.md) 的写法（`module` / `""`）。

`scripts/app.js`：

```js
import { h } from 'preact';
import { useMemo } from 'preact/hooks';

const { STab, SFloating, SRadarChart, SExpand } = window.sComponents;
const { get, useMessageData, appendItemInput, renderComponent } = window.sUtils;

function HpTab({ hp, mood }) {
  return h('div', { className: 'sp-hp' },
    h('b', {}, `HP ${hp ?? '?'} / 100`),
    h('div', { className: 'sp-bar' }, h('i', { style: `width:${hp ?? 0}%` })),
    h('p', {}, `心情：${mood ?? '未知'}`));
}

function BagTab({ bag }) {
  const entries = Object.entries(bag ?? {});
  if (!entries.length) return h('p', {}, '背包是空的');
  return h('div', {},
    entries.map(([name, count]) =>
      h(SExpand, { header: () => `${name} ×${count}` },
        h('button', { onClick: () => appendItemInput({ name }) }, `引用「${name}」`))));
}

function App() {
  const [variables] = useMessageData('variables');
  const hp = get(variables, 'hp', 0);
  const mood = get(variables, 'mood', '');
  const bag = get(variables, 'bag', {});

  return SFloating({
    button: () => '🎒',
    className: 'sp-floating',
    children: () => h(STab, {
      layout: (header, content) => h('div', { className: 'sp-panel' }, header, content),
      tabs: [
        { id: 'hp', header: () => '❤️ 状态', content: () => h(HpTab, { hp, mood }) },
        { id: 'bag', header: () => '🎒 背包', content: () => h(BagTab, { bag }) },
      ],
    }),
  });
}
renderComponent(App, 'sp-app');
```

`styles/app.css`（够用就行）：

```css

.sp-bar { height: 8px; background: #333; border-radius: 4px; margin: 6px 0; }
.sp-bar i { display: block; height: 100%; background: #e35; border-radius: 4px; }
```

## 五、自检与下一步

| 现象 | 原因 |
| --- | --- |
| 面板一片空白 | 模型没写变量；或变量路径和你 `get()` 的不一致（变量是"模型写什么就有什么"） |
| 雷达图是 `NaN` | 传了字符串或 undefined，`value` 必须是数字 |
| 点按钮没反应 | `appendItemInput` 依赖 `window.userInput`（主应用挂的），离线预览页里没有 |
| 改了面板没变化 | `renderComponent` 只在首次执行；面板更新靠 `useMessageData`，别自己 `render` |
| 悬浮球被正文挡住 | 调 `z-index` / `pointer-events`（参考模板的 `sim-floating` 样式） |
