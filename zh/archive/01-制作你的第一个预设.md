# 01 · 制作你的第一个预设

> **对应**：自己从零建的 `hello` 预设（不依赖模板）｜**前置**：无｜**难度**：★
> **你将得到**：一个能导入、能进故事、有一条世界书、右下角有个小角标的预设。

---

## 一、引言

模板里的预设立刻能用，但它们都默认你已经懂三件事：条目怎么组织、内容怎么引用、界面从哪来。
所以第一个预设不抄模板，而是做**最小闭环**：

- 世界书管"模型说什么"；
- 脚本 + 样式管"玩家看到什么";
- 变量把两者连起来。

一共 5 个文件、不到 40 行代码，做完你就拥有了后面所有教程的"底盘"。

---

## 二、教学目的

完成本教程后，你应该会：

- [ ] 说清"存档 / 预设 / 条目"三者的关系，知道哪些名字不能改
- [ ] 写出最小可用的 `meta.json`，并知道多一个字段/少一个字段的后果
- [ ] 区分**内联内容**与 `$file$` 外置内容，并能排查"内容为空"
- [ ] 用 `tar` 打包、导入、覆盖更新
- [ ] 写一个注入 iframe 的最小脚本 + 样式，并订阅变量让界面更新

---

## 三、理论

### 3.1 预设就是"一个目录 + 一个 meta.json"

应用不认你的目录名，只认 `meta.json` 里的 `id`。**没有 `meta.json` 的目录会被静默跳过**，
所以"导入后什么都没有"的第一个排查点永远是：这个目录里有没有合法的 `meta.json`。

> 📦 **备注 · `meta.json` 字段**
>
> | 字段          | 必填 | 说明                                                         |
> | ------------- | ---- | ------------------------------------------------------------ |
> | `id`          | ✅   | 主键，全库唯一；重复导入 = 覆盖。建议 `[a-z0-9_]+`           |
> | `name`        | ✅   | 显示名                                                       |
> | `version`     |      | 默认 `1.0.0`，仅展示                                         |
> | `description` |      | 列表里的描述                                                 |
> | `tags`        |      | 字符串数组，只用于标签过滤（不做枚举校验）                   |
> | `requires`    |      | 依赖的其它预设：`[{ "name": "显示名", "value": "对方 id" }]` |
> | `variables`   |      | 初始变量，值写 `"$file$variables.json"` 或内联 JSON 文本     |
> | `opening`     |      | 开场白，值写 `"$file$opening.txt"` 或直接内联                |
> | `cover`       |      | 封面：**写包内文件名**（如 `cover.png`），不是 uuid          |
>
> 别写 `coverType`（已废弃），也别指望 `meta.json` 里放别的自定义字段能被读到。

### 3.2 六个条目目录，为什么固定

存档扫描器只遍历这六个名字：`lorebooks` `macros` `regexes` `scripts` `styles` `tools`
（对应条目类型 `lorebook` / `macro` / `regex` / `script` / `style` / `tool`）。
它们**必须精确、复数、小写**；少一个字母，整个目录的条目都不会被读，而且**不报错**。

每个条目就是目录里的一个 `*.meta.json`：文件名随便（推荐 `<code>.meta.json`），身份在 JSON 里。
可以再嵌子目录，层数不限。

> 📦 **备注 · `lorebook` 字段**（本教程只用这一种）
>
> | 字段            | 常用值                                        | 说明                                                            |
> | --------------- | --------------------------------------------- | --------------------------------------------------------------- |
> | `name` / `code` | 任意 / 唯一串                                 | `code` 在同一预设内唯一即可（运行时 id = `预设id-code`）        |
> | `match`         | `always`                                      | 其它还有 `normal`（关键词）/`event`（日期）/`variable`/`vector` |
> | `expression`    | `{ "last": false }`                           | `always` 下可加 `macro` 绑定开关；`last:true` = 每轮最后注入    |
> | `content`       | 文本或 `$file$…`                              | 正文                                                            |
> | `role`          | `system` / `user` / `assistant` / `knowledge` | 决定塞进哪一类消息                                              |
> | `layer`         | `< 100` 前置、`>= 100` 后置                   | 默认 100；注入顺序 = `layer*10000 + priority`                   |
> | `priority`      | 默认 0                                        | 同层内排序                                                      |
> | `disabled`      | `false`                                       | `true` = 运行时不注入                                           |

### 3.3 内容放哪里：内联还是 `$file$`

两种写法等价：

```json
{ "content": "你是一个安静的旁白。" }
```

```json
{ "content": "$file$rules.md" }
```

后者把正文放到同目录的独立文件里，便于编辑与版本管理。**导入时按名字精确读取**，
找不到就把该字段当空（静默），所以"内容为空"几乎总是名字对不上（大小写、扩展名、中文名编码）。

> 📦 **备注 · `$file$` 只对这几个字段生效**
>
> `lorebook.content`、`macro.value`、`script.content`、`style.content`、
> `variables`、`opening`、以及工具的 `config.description/schema/script`。
> 其它字段写 `$file$…` 只会被当成普通字符串。

### 3.4 界面从哪来

`scripts` 里的脚本和 `styles` 里的样式会被**注入到互动页面的 iframe** 里：

- 样式：内联 `<style>`（`type` 不是 `link` 时）或 `<link>`；
- 脚本：内联 `<script>`（`type: "module"` 就是 ES module），`document` 就是那个渲染页面。

关键点：**脚本只注入一次**（用 DOM id 去重）。所以"界面跟着故事变"要靠监听主应用推来的消息，
这一点在第 6 步做。

> 📦 **备注 · `script` / `style` 字段**
>
> | 字段             | 说明                                                                          |
> | ---------------- | ----------------------------------------------------------------------------- |
> | `code`           | 注入去重键（DOM id = `sct-<code>` / `stl-<code>`），同名只注入一次            |
> | `content`        | 代码/CSS 正文，可 `$file$`                                                    |
> | `priority`       | 升序注入；默认 100                                                            |
> | `type`（script） | `application/javascript` / `module` / `link`（`content` 当 URL）/ `importmap` |
> | `type`（style）  | `text/css` / `link`；写 `""` 也当内联样式                                     |

## 四、实践

工作目录：`D:\demo\root\hello\`（下称 `hello/`）。

### 步骤 1：建目录

```powershell
mkdir D:\demo\root\hello\lorebooks
mkdir D:\demo\root\hello\scripts
mkdir D:\demo\root\hello\styles
```

### 步骤 2：最小 `meta.json` → 第一次导入

`hello/meta.json`：

```json
{ "id": "hello", "name": "你好预设" }
```

```powershell
cd D:\demo
tar -a -c -f demo.zip root
tar -tf demo.zip        # 看到 root/hello/meta.json 才算对
```

应用 → 预设 → 导入 → 勾选"你好预设"→ 确认。

✅ 预设列表出现"你好预设"。
❌ 列表为空：zip 里没有 `root/` 前缀，或用了反斜杠路径（别用 `Compress-Archive`）。

### 步骤 3：加一条世界书（内联）

`hello/lorebooks/rules.meta.json`：

```json
{
  "code": "rules",
  "content": "你是一个安静的旁白，只用一句话描述画面。",
  "disabled": false,
  "expression": { "last": false },
  "layer": 99,
  "match": "always",
  "name": "基础规则",
  "priority": 100,
  "role": "system",
  "type": "plaintext"
}
```

重新打包 → 重新导入（同 `id` 覆盖）→ 进故事说一句话。

✅ 回答明显变得更"旁白"。
❌ 完全没变化：检查文件名是不是 `.meta.json` 结尾、目录是不是 `lorebooks`。

> 第一次进故事前要先去设置里配一个**默认模型**，否则"进入故事"会被拦。

### 步骤 4：加开场白与初始变量

`hello/meta.json` 改成：

```json
{
  "id": "hello",
  "name": "你好预设",
  "opening": "$file$opening.txt",
  "variables": "$file$variables.json"
}
```

`hello/opening.txt`：

```
墙上的钟停了，只有你听见它在走。
```

`hello/variables.json`：

```json
{ "day": 1, "mood": "平静" }
```

✅ 新建故事时第一句就是这段开场白。

> ⚠️ 只把文件放进去**没用**，必须由 `meta.json` 引用。
> 另外：预设变量只在**新建故事**时拷贝一次，已有故事用的是它自己的变量快照。

### 步骤 5：加一个看得见的角标

`hello/styles/panel.meta.json`：

```json
{
  "code": "hello",
  "content": "$file$panel.css",
  "disabled": false,
  "name": "角标",
  "priority": 100,
  "type": "text/css"
}
```

`hello/styles/panel.css`：

```css
#hello-badge {
  position: fixed;
  right: 12px;
  bottom: 12px;
  padding: 6px 10px;
  border-radius: 6px;
  background: #111c;
  color: #fff;
  font-size: 12px;
  pointer-events: none;
}
```

`hello/scripts/panel.meta.json`：

```json
{
  "code": "hello",
  "content": "$file$panel.js",
  "disabled": false,
  "name": "角标",
  "priority": 100,
  "type": "module"
}
```

`hello/scripts/panel.js`（纯 DOM，不依赖任何库）：

```js
const el = document.createElement('div');
el.id = 'hello-badge';
el.textContent = 'hello';
document.body.appendChild(el);
```

✅ 故事页面右下角出现 `hello` 小角标。

### 步骤 6：让角标跟着变量变

脚本只注入一次，所以要监听主应用推来的消息。把 `panel.js` 换成：

```js
const el = document.createElement('div');
el.id = 'hello-badge';
document.body.appendChild(el);

function render() {
  const vars = window.__messageData?.variables ?? {};
  el.textContent = `第 ${vars.day ?? '?'} 天 · ${vars.mood ?? '未知'}`;
}

render(); // 首屏
window.addEventListener('message', (e) => {
  // 主应用每次推数据都会来一条
  if (e.data?.type === 'variables') render();
});
```

✅ 角标显示"第 1 天 · 平静"；新建一个故事（改 `day` 后重新导入）会看到新值。

### 步骤 7：验收

| 检查项       | 期望             |
| ------------ | ---------------- |
| 预设列表     | 出现"你好预设"   |
| 新故事第一句 | 墙上那行开场白   |
| 右下角       | `第 1 天 · 平静` |
| 说一句话     | 回答是一句话旁白 |

## 五、自检与下一步

**最常见四个"静默失败"**：

1. 条目目录名错 → 条目不存在，不报错；
2. `$file$` 名字对不上 → 字段变空，不报错；
3. `meta.json` 没引用 `opening`/`variables` → 文件被忽略；
4. zip 路径不对 → 整个包被丢弃。
