# 03 · 预设天道：提示词骨架与宏插槽

> **对应预设**：`docs/templates/root/预设天道/`（id `preset_tiandao`，11 个条目）｜**前置**：[01](./01-制作你的第一个预设.md)｜**难度**：★★
> **你将得到**：一套"身份 + 规则 + 可选项"结构的提示词预设，内容能像插件一样开关。

---

## 一、引言

提示词写到最后都会遇到同一个问题：**哪些是恒定的，哪些是玩家可选的？**

- "你是这个世界的天道、必须按流程思考" —— 恒定，不该每轮变；
- 文风、人称、篇幅 —— 玩家想换，换的时候还希望"不喜欢的整段消失"，而不是留一句空话。

`预设天道` 的答案很干脆：**恒定部分写成两条常驻世界书，可选部分做成宏插槽**。
于是 9 个宏撑起了一整套"可配置的提示词"，本体只有两个文件。

---

## 二、教学目的

- [ ] 会拆"身份（identity）+ 规则（rules）"两层常驻提示，并给它们排 `layer`
- [ ] 会在提示词里留插槽 `<%~ it.xxx %>`，用宏去填
- [ ] 区分三种宏：**单选组**、**复选组**、**隐藏宏**，知道各自适合放什么
- [ ] 知道"插槽没人提供"会发生什么（字面量 `undefined`）
- [ ] 能为自己的玩法设计一套 `key` 命名

---

## 三、理论

### 3.1 两层常驻提示

| 条目 | 内容 | 定位 |
| --- | --- | --- |
| `identity` | 天道身份 7 条 + `agent_run` 四步流程（收集信息→视角分析→剧情推演→生成输出） | 位于 `layer: 99`，插在用户消息**之前** |
| `rules` | 用词禁忌、文风、人称、输出长度 | `layer: 100`，在之后 |

两者都是 `match: "always"` + `role: "system"`，于是每轮都在，且顺序固定。`layer` 只影响"插在哪"，
`priority` 影响"同一层内谁先"。

> 📦 **备注 · 世界书的注入顺序**
>
> 排序键 = `layer * 10000 + priority`，升序。`layer < 100` 的整批在"当前消息之前"注入，
> `layer >= 100` 的在"之后"。`role` 再决定落到 system / user / assistant / knowledge 哪一类。

### 3.2 宏插槽：提示词里的"变量位"

`rules.content.md` 里有四处插槽：

```markdown
## 文风
<%~ it.write_styles %>

## 人称
世界的主角是<%~ it.user %>，使用<%~ it.perspective %>视角进行描写。

## 输出长度
在输出正文时，保证正文的token数量约为 <%~ it.text_length %> 。
```

- `it.<key>` 就是"同 `key` 的所有宏拼起来的文本"；
- 引用谁，就等于把那个 `key` 组的内容贴在这里；
- 宏面板里勾/选什么，这里就变成什么。

### 3.3 三种宏，三种用途

| 形态 | 例子 | 行为 |
| --- | --- | --- |
| **复选组**（`multiple: true`） | `write_styles`：两套文风 | 同 `key` 下**可多选**，勾几条拼几条（`it.write_styles` 是拼接结果） |
| **单选组**（`multiple: false`） | `perspective` / `text_length` | 同 `key` 下**只能选一个**，面板是单选框 |
| **隐藏宏**（`hidden: true`） | `author` = `无名` | 整组都 hidden 时面板不显示，但值照样生效——当"常量/设置项"用 |

> 📦 **备注 · `Macro` 数据结构**
>
> | 字段 | 说明 |
> | --- | --- |
> | `code` | 去重/选择标识，同一预设内唯一；**开关就是它**（`checkItems[code]`） |
> | `key` | 插槽名，模板里写 `<%~ it.key %>`；建议 `[A-Za-z0-9_]`，别用纯数字开头 |
> | `value` | 文本（可 `$file$`）；`json: true` 时按 JSON 解析，能当对象用 |
> | `multiple` | `true` 复选（会写 `checkItems`）、`false` 单选（走 `selections`） |
> | `hidden` | 只在宏面板隐藏，不影响取值 |
> | `disabled` | 初始状态：复选组里 `false` = 默认勾上；**单选组不读它** |
>
> 单选组的默认项 = 同组里第一个 `disabled: false` 的 `code`（都 disabled 则取第一个）。
> 所以"某个选项默认选中"要靠 `disabled` 的写法，而不是排序。
>
> `hidden` 是**组级**的：整组都 `hidden: true`，这个组才不在面板出现（模板里的 `user`/主角名就是这样）；
> 组里只要有一条非 hidden，单选列表会把 hidden 的那条也列出来——所以隐藏常量要单独占一个 `key`。

### 3.4 模板表达式：Eta

插槽是 **Eta** 模板（`varName` 默认 `it`）：

| 写法 | 含义 |
| --- | --- |
| `<%~ it.key %>` | 原样内插（**写提示词用这个**） |
| `<%= it.key %>` | 会做 HTML 转义（`& < > " '`），提示词里别用 |
| `<% … %>` | 代码块，可以写 `if` / `for` / 变量 |

上下文里能拿到：所有宏的 `key`、`it.variables`（当前回合变量）、子 agent 传进来的参数（**摊平在顶层**）。
注意：世界书注入时 `it.space` 恒为 `{}`（注入那一刻没有"当前输出"），别指望它。

### 3.5 为什么用插槽而不是复制粘贴

- **一处定义，多处引用**：`it.user` 被 identity 和 rules 都用，改一次全变；
- **可选内容能整段消失**：单选组换项 = 旧文本彻底不出现，不会留半句；
- **可复用**：别的预设只要写 `<%~ it.write_styles %>`，就能吃到别人提供的文风包（见 [04](./04-特殊-插件式文本包.md)）。

## 四、实践

做一个自己的"旁白风格"预设 `narrator`（比天道小，但结构一样）。

### 步骤 1：目录与 meta

```powershell
mkdir D:\demo\root\narrator\lorebooks
mkdir D:\demo\root\narrator\macros
```

`narrator/meta.json`：

```json
{ "id": "narrator", "name": "旁白预设", "version": "1.0.0", "tags": ["preset"] }
```

### 步骤 2：身份（恒定部分）

`narrator/lorebooks/identity.meta.json`：

```json
{
  "name": "身份",
  "code": "identity",
  "type": "markdown",
  "match": "always",
  "expression": { "last": false },
  "content": "$file$identity.md",
  "priority": 100,
  "layer": 99,
  "role": "system",
  "disabled": false
}
```

`narrator/lorebooks/identity.md`：

```markdown
你是这部作品的旁白，不是角色。

一次回应只做两件事：
1. 用一句话描述此刻的画面（光线、声音、动作）；
2. 停在这里，把下一步留给玩家。
```

### 步骤 3：规则（带插槽）

`narrator/lorebooks/rules.meta.json` 与身份同构，`layer` 改为 `100`、`code` 改 `rules`；
`narrator/lorebooks/rules.md`：

```markdown
## 语气
<%~ it.tone %>

## 篇幅
每次描述控制在 <%~ it.length %> 字以内。

## 禁忌
<%~ it.bans %>
```

### 步骤 4：宏——一个单选组、一个复选组、一个隐藏项

`narrator/macros/tone-cold.meta.json`（单选组：冷）

```json
{
  "name": "语气：冷",
  "code": "tone_cold",
  "key": "tone",
  "value": "克制、简短，不带情绪判断。",
  "json": false,
  "multiple": false,
  "hidden": false,
  "disabled": false
}
```

`narrator/macros/tone-warm.meta.json`（单选组：暖，默认不选）

```json
{
  "name": "语气：暖",
  "code": "tone_warm",
  "key": "tone",
  "value": "温和，允许一点善意的调侃。",
  "json": false,
  "multiple": false,
  "hidden": false,
  "disabled": true
}
```

`narrator/macros/length-50.meta.json`（单选组：50 字）

```json
{ "name": "篇幅：短", "code": "len_s", "key": "length", "value": "50",
  "json": false, "multiple": false, "hidden": false, "disabled": false }
```

`narrator/macros/length-150.meta.json`（单选组：150 字）

```json
{ "name": "篇幅：中", "code": "len_m", "key": "length", "value": "150",
  "json": false, "multiple": false, "hidden": false, "disabled": true }
```

`narrator/macros/ban-list.meta.json`（复选组：两条禁忌可叠加）

```json
{ "name": "禁忌：成语", "code": "ban_idiom", "key": "bans", "value": "- 不使用四字成语。\n",
  "json": false, "multiple": true, "hidden": false, "disabled": false }
```

```json
{ "name": "禁忌：心理描写", "code": "ban_mind", "key": "bans", "value": "- 不写角色心理活动。\n",
  "json": false, "multiple": true, "hidden": false, "disabled": false }
```

`narrator/macros/author.meta.json`（隐藏组：固定署名，独立 `key`）

```json
{ "name": "作者署名", "code": "author", "key": "author", "value": "无名",
  "json": false, "multiple": false, "hidden": true, "disabled": false }
```

> 隐藏宏要**单独占一个 `key`**：`hidden` 是"组级"的——整组条目都 hidden，这个组才不会出现在面板里。
> 组里混了非 hidden 的条目，单选列表会把 hidden 的那条也列出来（面板不过滤单选条目）。

在 `rules.md` 末尾加一行用上它：

```markdown
本期讲述者：<%~ it.author %>。
```

### 步骤 5：打包、导入、验收

```powershell
cd D:\demo
tar -a -c -f demo.zip root
```

- ✅ 宏面板里出现三个组：`tone`（单选框 ×2）、`length`（单选框 ×2）、`bans`（复选框 ×2）；
  `author` 组看不到（整组 hidden），但提示词里有"本期讲述者：无名"。
- ✅ 默认选中"语气：冷"和"篇幅：短"（因为它们是各自组里第一个 `disabled: false` 的）。
- ✅ 切到"语气：暖"，模型说话明显变软；再取消勾选"禁忌：心理描写"，那段规则彻底消失。

### 步骤 6：故意制造一次 `undefined`

把 `rules.md` 里的 `<%~ it.bans %>` 改成 `<%~ it.banz %>`（拼错）。重新导入后看模型复述规则。

❌ 会看到字面量 `undefined`——Eta 找不到 key 不报错。这是拼预设时最常见的低级事故。

## 五、自检与下一步

| 现象 | 原因 |
| --- | --- |
| 提示词里出现 `undefined` | key 拼错，或提供该 key 的宏没被勾/没被装 |
| 单选项怎么都取消不掉 | 单选组没有"空"状态，只能在同组中换一个；要能关掉就用复选组 |
| 两套文风同时生效 | 它们写在 `multiple: true` 的组里且都被勾上了——这是复选组的正常行为 |
| 常量被玩家改掉 | 用了非 hidden 的宏；想藏起来就 `hidden: true` |
| 改了文本没变化 | 忘了重新打包导入；应用不会读你的磁盘文件 |
