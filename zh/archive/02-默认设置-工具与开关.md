# 02 · 默认设置：工具与开关

> **对应预设**：`docs/templates/root/默认设置/`（id `settings`，14 个条目）｜**前置**：[01](./01-制作你的第一个预设.md)｜**难度**：★★
> **你将得到**：一个能自己加工具、并且能"一键摘掉工具 + 摘掉它的说明书"的预设。

---

## 一、引言

工具是让模型"动手"的唯一方式（写变量、掷骰、绘图、开会话）。但工具不是白给的：

- 每个工具的 **schema** 都常驻在请求里（吃 token）；
- 模型看得见工具就会想调（调错、空转、重复调都在烧钱）；
- 一个玩法模块往往需要"工具 + 一段使用说明"，两者必须同生同死。

于是有了这套**三件套**：**宏（开关+说明书）+ 工具（绑门开关）+ 常驻世界书（注入说明书）**。
`默认设置` 就是这套东西的底座：14 个条目 = 2 条世界书 + 5 个宏 + 7 个工具，没有脚本/样式/正则。

---

## 二、教学目的

- [ ] 看懂一个工具从 `meta.json` 到"模型能调用"的完整链路
- [ ] 会写三种工具：无配置型、`script` 型、引用外部实体的 `agent`/`comfyui` 型
- [ ] 会用宏当开关：**工具开关** 与 **世界书开关** 两种绑定
- [ ] 理解为什么"工具面板"和"宏面板"是同一批开关
- [ ] 能解释"关掉宏之后，工具和它的说明书同时消失"是怎么做到的

## 三、理论

### 3.1 工具是怎么被模型看到的

```
meta.json (tools/xxx.meta.json)
   ↓ 按 type 找 provider（variable / script / agent / comfyui …）
provider.create(entry, realm) → ToolItem { name, description, parameters, invoke }
   ↓ 存进 cache.tools[name]（同名后者覆盖前者）
tools.actives(realm) → 过滤 disabled → 三个引擎各自塞进请求的 tools 字段
```

所以**暴露给模型的名字是 `ToolItem.name`，不是条目的 `name`**。`script` 型的 `name` 取 `config.code`，
条目 `name` 只是预设编辑界面里的显示名。

### 3.2 开关：一个故事级的 `checkItems[code]`

`checkItems` 存在 `realm.properties` 里，只有 **`multiple: true` 的宏** 会读写它（`true` = 禁用）。
三个地方共享同一份数据：

| 谁 | 行为 |
| --- | --- |
| 宏面板里的勾选框 | 勾上/取消 → 写 `checkItems[宏 code]` |
| 工具面板里的勾选框 | 绑定过 `macro` 的工具 → 也是写 `checkItems[macro]` |
| 世界书 `fixed()` | `expression.macro` 指向的 code 若为"启用"才注入 |

这就是"两处 UI 是同一个开关"的原因：**在工具面板里关掉它，宏面板里的勾也会掉**。

### 3.3 说明书怎么进提示词

说明书文本不写在工具里，而是写在**宏的 `value`** 里，`key` 统一用 `tools`；
再由一条常驻世界书把整组文本注入（`默认设置/lorebooks/rules.content.md`）：

```markdown
# tools

<%~ it.tools %>
```

于是：勾上 = 工具可用 + 说明书就位；取消 = 两者一起消失。

> 📦 **备注 · 三件套的数据结构**
>
> ```jsonc
> // ① 宏：开关 + 说明书
> { "code": "roll_dice", "key": "tools", "value": "- `roll`: 需要随机数时调用",
>   "multiple": true, "hidden": false, "disabled": false, "json": false }
>
> // ② 工具：绑开关（macro 填宏的 code，不是工具名）
> { "name": "骰子", "type": "script", "macro": "roll_dice", "disabled": false,
>   "config": { "code": "roll", "description": "返回 [min,max] 随机整数",
>               "schema": "$file$roll.schema.json", "script": "$file$roll.script.js" } }
>
> // ③ 世界书：容器（一条就够，所有工具共用）
> { "code": "rules", "match": "always", "expression": { "last": false },
>   "content": "# tools\n\n<%~ it.tools %>", "layer": 80, "role": "system" }
> ```

### 3.4 七种工具类型

| `type` | 配置 | 说明 |
| --- | --- | --- |
| `lorebook` / `variable` / `memory` / `elicit` | `{}`（可省） | 固定能力：知识检索 / 变量读写 / 记忆 / 向玩家提问 |
| `script` | `{ code, description, schema, script }` | 最常用：函数体 + JSON Schema，`input` 是参数 |
| `agent` | `{ code, model, presets, disablePreset, disableTags, schema }` | 子智能体，见 [10](./10-思维分析Agent-子智能体.md) |
| `comfyui` | `{ code, workflow }` | 绘图：引用 `root/comfyui/` 里的工作流 |
| `fetcher` / `mcp` | `{ maxResults, timeout, maxLength }` / `{ code, url, headers… }` | 抓网页 / 远端 MCP 工具 |

- `script` 的 `config.script` 是**函数体**（`new Function('input','context', 源码)`），必须自己 `return`；
  `config.schema` 是 JSON Schema 文本。
- 无配置型只要三行：`{ "name": "变量工具", "type": "variable", "macro": "variable" }`。
- `agent` / `comfyui` 会**引用存档里的其它实体**：`root/model/<id>.model.json`、`root/comfyui/<id>.*`。

### 3.5 变量工具与"变量格式"世界书

`默认设置` 里还有一条容易被忽略的联动：`lorebooks/variable.meta.json` 的内容是 `<%~ it.variable %>`
（变量 schema 说明），并且 `"expression": { "macro": "variable" }` —— 它绑的是**变量工具那个宏的 code**。
也就是说：**关掉变量工具，变量格式说明也一起不注入了**。这正是 §3.2 的第二类绑定。

## 四、实践

我们用"加一个骰子工具"走完整流程。可以直接在 `docs/templates/root/默认设置/` 上改，
也可以复制一份到 `D:\demo\root\my_settings\` 并改 `meta.json` 的 `id`（比如 `my_settings`）。

### 步骤 1：加宏（开关 + 说明书）

`macros/tool-dice.meta.json`：

```json
{
  "name": "骰子工具",
  "code": "dice",
  "key": "tools",
  "value": "- `roll`: 需要随机数时调用，参数 min/max。",
  "json": false,
  "multiple": true,
  "hidden": false,
  "disabled": false
}
```

`multiple: true` 是**硬要求**：单选宏不写 `checkItems`，绑上去也关不掉。

### 步骤 2：加工具并绑开关

`tools/roll.meta.json`：

```json
{
  "name": "骰子",
  "type": "script",
  "disabled": false,
  "macro": "dice",
  "config": {
    "code": "roll",
    "description": "返回 [min, max] 之间的随机整数",
    "schema": "$file$roll.schema.json",
    "script": "$file$roll.script.js"
  }
}
```

`tools/roll.schema.json`：

```json
{
  "type": "object",
  "properties": {
    "min": { "type": "number", "default": 1 },
    "max": { "type": "number", "default": 6 }
  },
  "required": ["min", "max"],
  "additionalProperties": false
}
```

`tools/roll.script.js`：

```javascript
const min = Math.ceil(input.min);
const max = Math.floor(input.max);
return String(Math.floor(Math.random() * (max - min + 1)) + min);
```

容器世界书已经存在（`lorebooks/rules.content.md` 里那句 `<%~ it.tools %>`），不用改。

### 步骤 3：验收开关

打包导入，进故事，打开**宏选择器**：`tools` 组里多了一个"骰子工具"。

- 取消勾选它 → 打开**工具面板**，`roll` 也不见了（反之亦然）；
- 看系统提示（或让模型复述可用工具）→ `roll` 的说明也一起消失了。

### 步骤 4：加一条"跟开关走"的世界书

`lorebooks/dice_rule.meta.json`：

```json
{
  "name": "骰子规则",
  "code": "dice_rule",
  "type": "plaintext",
  "match": "always",
  "expression": { "last": false, "macro": "dice" },
  "content": "凡是需要随机结果的地方，必须调用 roll 工具，不要自己编数字。",
  "priority": 100,
  "layer": 85,
  "role": "system",
  "disabled": false
}
```

✅ 勾着 `dice` 时这条规则在；一取消，整条从提示词里消失（不是内容变空）。

> 📦 **备注 · `expression.macro` 的两个约束**
>
> 1. 只对 `match: "always"` 生效（`normal`/`event`/`variable`/`vector` 上写 `macro` 不会被读）；
> 2. 值必须是**宏的 `code`**，而且那个宏必须是 `multiple: true`。
> 语义是"宏启用 → 注入"（内部判的是 `!checkItems[macro]`）。

### 步骤 5：小结

你刚刚做的事，就是 `默认设置` 里 4 个工具的关系：
`tool-variable` / `tool-lorebook` / `tool-memory` / `elicit`（注意最后这个宏的 `code` 曾叫 `ask_user`，
现在已统一成 `elicit`，和工具的 `macro` 对上）。

## 五、自检与下一步

| 现象 | 原因 |
| --- | --- |
| 勾选没反应 | 绑定的是单选宏（`multiple: false`），或 `tool.macro` 的 code 没有对应宏 |
| 关掉宏后工具还在 | 工具没写 `macro`（此时它跟工具面板的独立开关，不跟宏） |
| 导入直接 500 | 某个工具的 `type` 没有注册 provider（写错一个字母就会） |
| 两条说明书都出现了 | 容器世界书引用 `it.tools`，而两处都注入了同一段文本——查是否复制出了两条同 `key` 的宏 |
