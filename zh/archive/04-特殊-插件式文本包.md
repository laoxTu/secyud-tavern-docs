# 04 · 特殊：插件式文本包

> **对应预设**：`other/archive/root/特殊/`（id `specials`，1 个条目）
> ——注意它**不在** `docs/templates/` 里，是草稿区（`other/`）的作品｜**前置**：[03](./03-预设作家-提示词骨架.md)｜**难度**：★
> **你将得到**：一个"只提供一段文本"的预设；本教程用它讲机制，并带你写一个**"克制"文风包**。

---

## 一、引言

写多套预设之后，常见痛点是：**同一段设定要在 N 个预设里各存一份**，改一次要改 N 遍，
放在同一个故事里还会互相打架。

`特殊` 给出的答案是：把这段文本**抽成一个独立预设**，用同一个 `key` 对接别人的插槽。
它一共只有一个条目（一个宏），却是"组合优于复制"的最小示范：

```
特殊/
├── meta.json
└── macros/write_style-*.meta.json + .value.md     ← 一条 key=write_styles 的宏
```

它自己不自带文风内容之外的任何东西——**没有世界书、没有脚本、没有工具**。
至于那段文本写什么，完全看你：下面我们就以"克制"文风为例，从零写一个同构的包。

---

## 二、教学目的

- [ ] 理解"`key` 是插槽名，跨预设共享"
- [ ] 会写一个只含宏、不含世界书/脚本的极简预设
- [ ] 知道 `multiple: true` 才能与其他同 key 宏**叠加**
- [ ] 明白"单独装看不出任何变化"不是 bug
- [ ] 能写一段"规则清单"式的文风文本，并挂到插槽上

## 三、理论

### 3.1 `it.<key>` 是"跨预设的拼接结果"

运行时把所有已加载预设的宏**扁平遍历**（`realm.presets` 里每个预设的 `macros`），
按 `key` 分组、按启用状态过滤、拼接：

```
预设A 的 key=write_styles ─┐
预设B 的 key=write_styles ─┼→ it.write_styles = "A 的文本" + "B 的文本"
预设C 的 key=write_styles ─┘
```

所以"插件包"能不能生效，只取决于两件事：**别人的提示词里有没有这个 `key`**，以及**你是不是 `multiple: true`**。

### 3.2 为什么必须 `multiple: true`

| `multiple`      | 面板形态           | 取值                       |
| --------------- | ------------------ | -------------------------- |
| `true`（复选）  | 复选框，可多选     | 同组所有勾选的文本**拼接** |
| `false`（单选） | 单选框，只能选一个 | 只取被选中的那一条         |

文风是"叠加型"需求（克制 + 网文、克制 + 冷硬），所以必须是复选。
做成单选的话，它会和已有文风互斥——挂上去等于"换掉"而不是"加料"。

### 3.3 它单独装为什么没效果

`特殊` 没有世界书、没有脚本，唯一作用是把文本塞进 `it.write_styles`。
如果栈里**没有任何提示词引用** `it.write_styles`，这段文本永远不会出现在提示词里。

现成的插槽在模板的 `预设作家` 里：

```markdown
## 文风

<%~ it.write_styles %>
```

只要故事里同时装了"提供插槽的预设"和"提供文本的包"，勾选就生效。

> 📦 **备注 · 最小宏（以你要写的"克制"宏为例）**
>
> ```jsonc
> {
>   "code": "ws_restrained", // 去重/开关标识，同组内不重复
>   "key": "write_styles", // 插槽名，别人提示词里写的就是它
>   "value": "$file$write_style-restrained.value.md", // 文本，可内联或外置
>   "json": false, // true 则按 JSON 解析（可当对象用）
>   "multiple": true, // 复选：与同 key 其它宏叠加
>   "hidden": false, // 组级隐藏，见 03
>   "disabled": false, // 复选下 false = 默认勾上
>   "name": "文风：克制",
> } // 面板显示名
> ```

### 3.4 "规则清单"式的文风为什么好用

好的文风包不点名剧情，只约束手法。下面这段可以当模板（短句、白描、克制）：

```text
## 克制
- 短句为主，一句话只做一件事。
- 只写能被看见、被听见的东西：动作、光线、声音、位置。
- 不写心理活动，情绪靠动作和停顿露出来。
- 形容词每段至多一个；不用四字成语、排比、比喻串。
- 留白：该说的说完就停，不解释含义，不在结尾升华。
- 一段里只推进一个变化。读者没被告知的，就当没发生。
```

因为它不绑世界观，所以能挂到任何预设上；因为它是"禁止项 + 手法"，模型比"请写得优美"更能执行。

### 3.5 版本与配套

`特殊` 的 `version` 是 `1.1.3`，和 `默认设置` 一致——说明它是**配套加料**，不是独立玩法。
`requires` 为空也合理：它只提供文本，不依赖任何工具或界面。

## 四、实践

### 步骤 1：先看现成的那个包

打开 `other/archive/root/特殊/`：一个 `meta.json` + 一个宏（含 `.value.md`）。
这就是全部结构——你接下来要造的包与它同构，只是换 `id`、换文本。

把它和模板里的 `预设作家` 一起导入，进故事打开宏选择器：`write_styles` 组里会多出它那一条；
勾上/取消，插槽那段文字跟着出现/消失。（它自带的那段规则与本节示例无关，你可以整段替换掉。）

### 步骤 2：写你的"克制"包

```powershell
mkdir D:\demo\root\style_pack\macros
```

`style_pack/meta.json`：

```json
{ "id": "style_pack", "name": "文风包", "tags": ["preset"], "version": "1.0.0" }
```

`style_pack/macros/style-restrained.meta.json`：

```json
{
  "code": "ws_restrained",
  "disabled": false,
  "hidden": false,
  "json": false,
  "key": "write_styles",
  "multiple": true,
  "name": "文风：克制",
  "value": "$file$style-restrained.value.md"
}
```

`style_pack/macros/style-restrained.value.md`：

```markdown
## 克制

- 短句为主，一句话只做一件事。
- 只写能被看见、被听见的东西：动作、光线、声音、位置。
- 不写心理活动，情绪靠动作和停顿露出来。
- 形容词每段至多一个；不用四字成语、排比、比喻串。
- 留白：该说的说完就停，不解释含义，不在结尾升华。
- 一段里只推进一个变化。读者没被告知的，就当没发生。
```

再写一条可选的口语版，验证"叠加"：

```json
{
  "code": "ws_plain",
  "disabled": true,
  "hidden": false,
  "json": false,
  "key": "write_styles",
  "multiple": true,
  "name": "文风：口语",
  "value": "用日常口语写，允许不完整的句子和不礼貌的打断。\n"
}
```

注意 `disabled`：复选组里 `false` = 默认勾上、`true` = 默认不勾。
（单选组不读 `disabled`，见 [03](./03-预设作家-提示词骨架.md)。）

### 步骤 3：打包验证

```powershell
cd D:\demo
tar -a -c -f demo.zip root
```

导入时同时勾 `预设作家` 和 `文风包`：

- ✅ `write_styles` 组里出现"克制"（默认勾）和"口语"（默认不勾）；
- ✅ 只勾"克制"时：句短、少形容词、没有"他感到……"；
- ✅ 再勾"口语"：两段文本叠加，风格是"克制 + 口语"；
- ✅ 取消所有勾选：插槽位置空着，提示词不报错。

### 步骤 4：验证"单独装没用"

只装 `文风包`、不装任何带插槽的预设：什么都看不到。✅ 这是正确的。

## 五、自检与下一步

| 现象               | 原因                                                                              |
| ------------------ | --------------------------------------------------------------------------------- |
| 装了没反应         | 没有预设引用这个 `key`，或你只装了包本身                                          |
| 两段文本顺序很怪   | 同 `key` 同 `multiple` 的宏排序键相同，拼接顺序不保证——需要固定顺序就合并成一条宏 |
| 勾选后只有一条生效 | 写成了 `multiple: false`（单选），同组只能选一个                                  |
| 标签筛不出来       | `tags` 只做模糊匹配；`特殊` 里写成 `settings`（复数）而代码枚举是 `setting`       |
