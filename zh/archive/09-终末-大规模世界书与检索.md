# 09 · 终末：大规模世界书与检索

> **对应预设**：`docs/templates/root/终末/`（id `story_terminal`，**98 个条目**：97 条世界书 + 1 个宏）｜**前置**：[03](./03-预设作家-提示词骨架.md)｜**难度**：★★
> **你将得到**：一套能装几百条设定、只在"需要时"才注入的世界书体系（向量检索）。

---

## 一、引言

世界观写到一定规模就撞墙：

- 全塞进提示词 → token 爆炸、模型抓不住重点；
- 只塞"当前区域" → 玩家一提别处的人，模型就开始编。

`终末` 的做法是**分两层**：一条"世界总述"永远在场，其余 96 条细节**只在被检索到时**注入。
它的目录结构、命名约定、内容写法，都是从"几百条规模"倒推出来的工程实践。

---

## 二、教学目的

- [ ] 会用 `match: "vector"` 写"按需检索"的世界书条目
- [ ] 理解 RAG 链路：条目入库 → 工具检索 → 命中注入
- [ ] 会用目录 + 命名约定管理几十上百条设定
- [ ] 知道两条硬前置：**装了世界书工具** + **故事开了 RAG**
- [ ] 掌握"总述 vs 细节"的拆分原则

## 三、理论

### 3.1 两种条目，两种命运

|          | `match: "always"`        | `match: "vector"`                    |
| -------- | ------------------------ | ------------------------------------ |
| 数量     | 1 条（`world_bj_0`）     | 96 条                                |
| 何时注入 | 每轮                     | **只有被检索命中时**                 |
| 写什么   | 纪元、整体格局、三条铁律 | 某个人、某个势力、某件物品、某段历史 |
| 成本     | 常驻 token               | 命中才花                             |

> 拆分原则：总述只写"不看细节也能推进剧情"的信息；细节一律进 `vector`。
> 总述里可以用 `[实体]` 点名，但**不要**把实体设定写在总述里。

### 3.2 RAG 链路

```
启动（进故事）
  每个 vector 条目 → 取 embedding 文本（有 expression.keywords 用它，否则用整段 content）
                   → 写入内存检索库（orama），文档 key = 条目 id、title = 条目 name

生成中
  模型调用 get_lorebook({ content: "问句/关键词" })
     → 向量检索（默认 limit 3、相似度阈值 0.3）
     → 命中的条目 id 记进本轮输出属性
  匹配阶段
     vector 匹配器：id 在命中列表里 → 该条注入（role: knowledge）
```

两个"不生效"的常见原因都在前置：**没装世界书工具**（模型没有检索入口）、**故事没开 RAG**（工具会直接返回
`warn: RAG is not enabled`）。

> 📦 **备注 · `vector` 条目的字段**
>
> ```jsonc
> {
>   "code": "role_hs_22",
>   "name": "韩霜",
>   "type": "plaintext",
>   "match": "vector",
>   "expression": {}, // 空对象即可；要自定义检索文本就写 { "keywords": "关键词…" }
>   "content": "角色：韩霜。…", // 没有 keywords 时，整段 content 参与向量化
>   "priority": 100,
>   "layer": 100,
>   "role": "knowledge",
>   "disabled": false,
> }
> ```
>
> `role: "knowledge"` 是关键：它让注入以"知识检索结果"的形态出现，不占系统提示的宝座。

### 3.3 目录就是索引

```
lorebooks/
├── world_bj_0.meta.json            ← 世界总述（always）
├── 帝都/  江南/  蜀中/              ← 按区域
│   ├── world_*.meta.json           ← 该区域总述
│   ├── 人物/ 势力/
│   └── 事件/<时期>/                ← 再按纪元分期
├── 物品与知识/                     ← 跨区域的设定（符文、材料…）
└── 跨区/                           ← 跨区域关系（rel_*）与跨区事件
```

条目可以无限嵌套子目录，扫描器只认 `*.meta.json` 后缀，层级不影响功能——**目录是给人看的**。

### 3.4 命名约定

`终末` 的 97 个文件全部按 `<类型>_<缩写>_<序号>.meta.json`：

| 前缀     | 数量 | 含义                                                           |
| -------- | ---- | -------------------------------------------------------------- |
| `world_` | 3    | 世界/区域总述（`world_bj_0` = 帝都，`_jn_` 江南，`_sz_` 蜀中） |
| `role_`  | 20   | 角色                                                           |
| `org_`   | 8    | 势力/组织                                                      |
| `item_`  | 16   | 物品与知识                                                     |
| `rel_`   | 11   | 人物关系（放 `跨区/`）                                         |
| `event_` | 39   | 事件，文件名带时间：`event_0y3m_50` = 0 年 3 月第 50 条        |

好处：找得到、排序稳定、看文件名就知道该不该合并/拆分。

### 3.5 内容写法

每条只写"这一条该说的事"，并用 `[实体]` 标注专有名词，让同一实体在不同条目里能互相指认：

```text
势力：天工重工。[帝都]废墟下的重工业复合体，前身为末日前的军工集团…
早期为[龙家]生产履带式武装机器人，后协助构建[龙渊]网络…
```

反面写法是"一条写完全部背景"——那会让 RAG 的粒度失效（检索命中一条就塞进来 3000 字）。

## 四、实践

做一个小世界：1 条总述 + 4 条检索条目。

### 步骤 1：目录与元数据

```powershell
mkdir D:\demo\root\small_world\lorebooks\城市\人物
mkdir D:\demo\root\small_world\lorebooks\跨区
```

`small_world/meta.json`：

```json
{
  "id": "small_world",
  "name": "小世界",
  "requires": [{ "name": "基础设置-1.1.3", "value": "settings" }],
  "version": "1.0.0"
}
```

> 依赖 `settings` 是为了拿"世界书工具"（`get_lorebook`）和变量工具。

### 步骤 2：总述（常驻）

`lorebooks/world_00.meta.json`：

```json
{
  "code": "world_00",
  "content": "背景：新历 12 年，海面上升吞掉了旧城。幸存者住在[浮岛]上，靠[潮汐炉]供电。三座浮岛互相提防，任何跨岛交易都要经[摆渡人]。细节见各条目。",
  "disabled": false,
  "expression": { "last": false },
  "layer": 99,
  "match": "always",
  "name": "世界总述",
  "priority": 100,
  "role": "system",
  "type": "markdown"
}
```

### 步骤 3：四条检索条目

`lorebooks/城市/world_city.meta.json`：

```json
{
  "code": "world_city",
  "content": "潮汐城：最大的浮岛，靠三座[潮汐炉]维持。城区分三层，上层住商会，下层是修炉工。",
  "disabled": false,
  "expression": {},
  "layer": 100,
  "match": "vector",
  "name": "潮汐城",
  "priority": 100,
  "role": "knowledge",
  "type": "plaintext"
}
```

`lorebooks/城市/人物/role_ferry.meta.json`：

```json
{
  "code": "role_ferry",
  "content": "角色：柯。[潮汐城]与[南礁]之间唯一的[摆渡人]，五十岁，寡言。他记得每一桩跨岛交易的内容，但从不主动说。",
  "disabled": false,
  "expression": {},
  "layer": 100,
  "match": "vector",
  "name": "摆渡人·柯",
  "priority": 100,
  "role": "knowledge",
  "type": "plaintext"
}
```

`lorebooks/城市/item_furnace.meta.json`：

```json
{
  "code": "item_furnace",
  "content": "知识：[潮汐炉]把潮汐势能转成热与电。核心是一块会随潮位共振的[晶核]，一旦裂开整座浮岛会停电。修炉工能听声音判断晶核裂纹。",
  "disabled": false,
  "expression": {},
  "layer": 100,
  "match": "vector",
  "name": "潮汐炉",
  "priority": 100,
  "role": "knowledge",
  "type": "plaintext"
}
```

`lorebooks/跨区/rel_ferry_city.meta.json`：

```json
{
  "code": "rel_ferry_city",
  "content": "关系：[柯]年轻时是[潮汐城]的修炉工，因一次事故被逐出上层；他至今仍在暗中替下层居民运送晶核。",
  "disabled": false,
  "expression": {},
  "layer": 100,
  "match": "vector",
  "name": "柯与潮汐城",
  "priority": 100,
  "role": "knowledge",
  "type": "plaintext"
}
```

### 步骤 4：开 RAG、导入、验收

1. 打包导入（`tar -a -c -f demo.zip root`），确认勾选了 `基础设置`（世界书工具）；
2. 故事设置里**开启 RAG**；
3. 新建故事，问："你认识摆渡人吗？"

✅ 模型会调用 `get_lorebook`，命中"摆渡人·柯"，然后照着条目回答。
✅ 问"潮汐炉怎么工作" → 命中 `item_furnace`，回答里有晶核、裂纹这些细节。
❌ 模型完全不检索 → 没开 RAG 或没勾世界书工具。
❌ 检索到了但没用 → 检查 `role` 是否 `knowledge`、`disabled` 是否 `false`。

> 📦 **备注 · 检索参数（默认值）**
>
> 工具 `get_lorebook({ content, limit = 3, min_relevance = 0.3 })`：
> 一次最多取 `limit` 条，相似度低于 `min_relevance` 的丢弃。命中数不够就换个问法再说一次。

### 步骤 5：加一条"跨区"条目验证粒度

再加一条 `跨区/event_00.meta.json`，写"南礁与潮汐城断航"的事件。
问"最近有什么大事" → 应命中这条，而不是把四条全塞进来。

## 五、自检与下一步

| 现象                 | 原因                                                                    |
| -------------------- | ----------------------------------------------------------------------- |
| 检索永远不触发       | 故事没开 RAG；或没勾世界书工具；或 `match` 写成了 `always`              |
| 命中太多、上下文爆炸 | 条目写太长（一条塞了一个国家）；拆细，或给 `expression.keywords` 精确化 |
| 总要人说全名才能命中 | 向量检索对缩写不友好，可在条目里自然复述全称                            |
| 同一信息出现两遍     | 总述里写了细节，细节条目又写了一遍                                      |
| 世界总述被忽略       | `role` 不是 `system`，或 `layer` 排到了后面                             |
