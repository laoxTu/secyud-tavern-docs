# 08 · 疯狂水世界：工具、前端数据与关键词知识库

> **对应预设**：`docs/templates/root/疯狂水世界/`（id `fkssj`，36 个条目）｜**前置**：[02](./02-默认设置-工具与开关.md)、[07](./07-模拟经营-状态面板.md)｜**难度**：★★★
> **你将得到**：一个"抽奖/开宝箱"闭环——工具掷结果、知识库补内容、callback 兜强提示、多套开场白。

---

## 一、引言

抽奖这种玩法的数据很尴尬：

- **奖池、权重、随机** 放在提示词里 = 白烧 token，而且模型会算错；
- **什么时候抽、抽哪一类** 是"决策"，只能模型来做；
- 抽完之后要**说清楚抽到了什么**，而清单可能有几百条。

`疯狂水世界` 的解法是三条线各管一段：

```
iframe 脚本（奖池权重）──┐
                          ├─→ 工具（只掷类别）→ 关键词世界书（补该类清单）→ 模型说结果
世界书（怎么用工具）─────┘
```

---

## 二、教学目的

- [ ] 会用 `enableDoc` 让工具脚本读到 iframe 的 `window`

- [ ] 会用 `callback`（`layer: 200` + `last: true` + `role: user`）做每轮末尾强提示
- [ ] 会用"开场白宏"实现多套开场（并知道模板里那两处的一个小 bug）

## 三、理论

### 3.1 两个运行时：模型侧 vs 页面侧

| | 模型侧（工具） | 页面侧（iframe 脚本） |
| --- | --- | --- |
| 能拿到 | 参数（`input`）、`context` | `document` / `window`、变量、消息 |
| 触发时机 | 模型调用时 | 页面加载后注入、常驻 |
| 适合放 | 决策、校验 | 数据、渲染、动画 |

`config.enableDoc: true` 会给工具脚本塞 `context.document` / `context.window`——这就是"从工具里读前端数据"的桥。
`enableVariable: true` 则额外给 `context.variables`（当前变量快照）。

### 3.2 把奖池放在脚本里

`scripts/jc-0.script.js`（module）只做一件事：把权重表挂到 window 上。

```js
const jcl = {
  dj: [['基础生存资源', 1e3], ['基础食物与种子', 920], /* … */],
  zj: [/* … */],
  gj: [/* … */],
};
window._fkssj = { jc(lv) { return jcl[lv]; } };
```

工具脚本（`tools/抽奖-0.script.js`）读它 + 复用 `sUtils.weightRandom`：

```js
const jc = context.window._fkssj.jc(input.type);          // 取该类奖池
const item = context.window.sUtils.weightRandom(jc, (i) => i[1]);  // 按权重抽
return item[0];                                            // 只返回"类目名"
```

注意返回值：**不是奖品，是类目名**（如"高级船只与载具"）。原因见下一节。

> 📦 **备注 · `script` 型工具的 `config`**
>
> ```jsonc
> { "code": "lottery",              // 暴露给模型的名字（不是条目 name）
>   "description": "抽奖时调用，返回奖励",
>   "schema": "$file$抽奖-0.schema.json",   // JSON Schema，定义 input
>   "script": "$file$抽奖-0.script.js",     // 函数体，必须自己 return
>   "enableDoc": true,              // 给 context.document / window
>   "enableVariable": false }       // 给 context.variables
> ```
>
> 这个工具没写 `macro`，所以它不跟宏开关走，始终可用（由工具面板的独立开关控制）。

### 3.3 抽到类目，再由知识库补内容

30 条 `lottery_*` 条目都是这个形状：`match: "normal"`，关键词就是类目名，正文是该类目的物品清单。

```json
{
  "code": "lottery_gj_01",
  "name": "高级船只与载具",
  "match": "normal",
  "expression": { "keywords": [["高级船只与载具"]], "keywordsLength": 1, "fitCount": 1 },
  "content": "高级船只与载具：铁甲蒸汽船（载货20吨…）、潜水器…、魔法浮空艇…",
  "layer": 100, "role": "knowledge", "priority": 100
}
```

链条：工具返回"高级船只与载具" → 这段文字出现在上下文里 → `normal` 匹配器命中关键词 → 该类清单被注入
→ 模型只能从清单里挑。**用检索代替背诵**，这是这套玩法能撑起 30 个类目的关键。

> 📦 **备注 · `normal` 的表达式**
>
> `keywords` 是**二维数组**：外层是"组"，组内任一关键词命中即算这组命中；
> 命中组数 ≥ `fitCount` 才注入。`keywordsLength` 只是编辑器用的组数。
> `role: "knowledge"` 意味着它按"知识检索结果"的形式塞进上下文，不完全占系统提示。

### 3.4 别忘了提醒模型

两条常驻条目分工明确：

| 条目 | `layer` | `expression` | `role` | 作用 |
| --- | --- | --- | --- | --- |
| `tool_lottery` | `5` | `{ "last": false }` | `system` | 最前面写清"怎么用抽奖工具"（三步） |
| `callback_cj` | `200` | `{ "last": true }` | `user` | 每轮**最后**再喊一句"抽奖/开箱时记得用工具" |

`last: true` + `layer: 200` 让它排在最后注入（离"该行动"最近），而且 `role: user` 比系统提示更"顶"。

### 3.5 多套开场白

`opening.txt` 只有一行：

```text
<%~ it.opening %>
```

真正的开场白文本放在 `key: "opening"` 的**单选组**里，选哪个就显示哪个。
但模板里那两条宏**都叫 `code: "opening"`**——单选组里同 `code` 会互相覆盖，实际只剩一条，还可能取到空值。
正确写法是**同 `key`、不同 `code`**：

```json
{ "key": "opening", "code": "opening_a", "value": "开场一…", "multiple": false, "disabled": false }
```

```json
{ "key": "opening", "code": "opening_b", "value": "开场二…", "multiple": false, "disabled": true }
```

`终末` 只有一条开场白宏，所以没踩到这个坑。

## 四、实践

做一个"宝箱"玩法（简化版抽奖）。

### 步骤 1：目录与 meta

```powershell
mkdir D:\demo\root\chest\lorebooks
mkdir D:\demo\root\chest\macros
mkdir D:\demo\root\chest\scripts
mkdir D:\demo\root\chest\tools
```

`chest/meta.json`：

```json
{
  "id": "chest",
  "name": "宝箱玩法",
  "version": "1.0.0",
  "requires": [
    { "name": "默认交互-1.1.0", "value": "ui_default" },
    { "name": "基础设置-1.1.3", "value": "settings" }
  ],
  "opening": "$file$opening.txt"
}
```

### 步骤 2：奖池脚本 + 工具

`scripts/pool.meta.json`：

```json
{ "name": "奖池", "code": "chest_pool", "content": "$file$pool.js",
  "priority": 0, "type": "module", "disabled": false }
```

`scripts/pool.js`：

```js
window._chest = {
  pool: {
    common: [['干粮', 70], ['火把', 50], ['碎布', 40]],
    rare: [['附魔匕首', 20], ['药水', 15]],
  },
};
```

`tools/open_chest.meta.json`：

```json
{
  "name": "开宝箱",
  "type": "script",
  "disabled": false,
  "config": {
    "code": "open_chest",
    "description": "开启宝箱，返回抽到的类目",
    "schema": "$file$open_chest.schema.json",
    "script": "$file$open_chest.script.js",
    "enableDoc": true,
    "enableVariable": false
  }
}
```

`tools/open_chest.schema.json`：

```json
{
  "type": "object",
  "properties": { "tier": { "type": "string", "enum": ["common", "rare"] } },
  "required": ["tier"],
  "additionalProperties": false
}
```

`tools/open_chest.script.js`：

```javascript
const pool = context.window._chest.pool[input.tier];
const picked = context.window.sUtils.weightRandom(pool, (i) => i[1]);
return picked[0];
```

### 步骤 3：知识库 + 强提示

`lorebooks/loot_common.meta.json`（类目 → 清单）：

```json
{
  "name": "普通战利品",
  "code": "loot_common",
  "type": "plaintext",
  "match": "normal",
  "expression": { "keywords": [["干粮", "火把", "碎布"]], "keywordsLength": 1, "fitCount": 1 },
  "content": "普通战利品：干粮（耐放）、火把（可燃30分钟）、碎布（可包扎）。",
  "priority": 100, "layer": 100, "role": "knowledge", "disabled": false
}
```

`lorebooks/callback.meta.json`（每轮末尾的强提醒）：

```json
{
  "name": "召用提醒",
  "code": "callback_chest",
  "type": "plaintext",
  "match": "always",
  "expression": { "last": true },
  "content": "凡是开箱、拾取、奖励结算，必须调用 open_chest，不要自己编内容。",
  "priority": 100, "layer": 200, "role": "user", "disabled": false
}
```

### 步骤 4：多套开场白（正确写法）

`opening.txt`：

```text
<%~ it.opening %>
```

`macros/opening-a.meta.json` / `opening-b.meta.json`：

```json
{ "name": "开场白：荒岛", "code": "opening_a", "key": "opening",
  "value": "你在潮湿的沙滩上醒来，脚边有一只半埋的木箱。",
  "json": false, "multiple": false, "hidden": false, "disabled": false }
```

```json
{ "name": "开场白：洞窟", "code": "opening_b", "key": "opening",
  "value": "火把熄灭的一瞬，洞窟深处传来金属摩擦声。",
  "json": false, "multiple": false, "hidden": false, "disabled": true }
```

### 步骤 5：验收

```powershell
cd D:\demo

```

| 检查 | 期望 |
| --- | --- |
| 宏面板 | `opening` 组两个单选项，默认"荒岛" |

检查 `type: "module"`、`priority` 是否比别的脚本小、`code` 有没有撞车。
❌ 抽到了但内容不对 → 关键词条目没命中（`keywords` 与工具返回的字符串要一致）。

## 五、自检与下一步

| 现象 | 原因 |
| --- | --- |
| 工具读不到 `window._chest` | 脚本未注入 / 注入晚于工具调用 / `code` 撞车被去重 |
| 每次抽到的都是最后一类 | `weightRandom` 的权重取错字段（要取 `[名称, 权重]` 的 `[1]`） |
| 抽完模型开始编物品 | 没有对应的关键词条目，或 `role` 不是 `knowledge` |
| 开场白是空白 | `opening.txt` 引用的 `it.opening` 没人提供；或单选组同 `code` 互相覆盖 |
| 提示词里有两段一样的说明 | 容器世界书与工具自带 description 都在说同一件事 |
